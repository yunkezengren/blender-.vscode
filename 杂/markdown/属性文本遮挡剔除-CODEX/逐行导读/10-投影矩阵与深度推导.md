# 投影矩阵与深度推导：为什么远近变化会影响判断

> 这篇解释 `text_anchor_project_with_depth` 的数学。先读 [09 矩阵基础](./09-矩阵从零到源码.md)。
> 下面的标准透视矩阵假设相机朝观察空间 `-Z` 看、近远裁剪距离分别为正数 `n/f` 且 `0<n<f`。它是教学模型；Blender 不同视图/后端的实际投影矩阵可能有额外偏移或约定，源码最终使用的是传入的 `persmat`。

## 1. 世界点要经过哪些空间

```text
本地点 --object_to_world--> 世界点 --view--> 观察空间点
             --projection--> 裁剪空间 (x_c,y_c,z_c,w_c)
             --除以 w_c--> NDC --视口映射--> 像素坐标与窗口深度
```

`persmat` 把中间的 view 和 projection 合为一次矩阵乘法。对世界点 `p_world`，源码的 `mul_m4_v4(persmat, vec4)` 相当于执行这个组合。它随后显式用 `w` 做除法。

## 2. 一个对称透视矩阵

令 `q=1/tan(FOV_y/2)`，宽高比为 `a=width/height`。按列向量排版的经典矩阵为：

```text
| q/a   0       0              0        |
|  0    q       0              0        |
|  0    0  -(f+n)/(f-n)  -2fn/(f-n)     |
|  0    0      -1              0        |
```

观察空间点 `(X,Y,-r,1)` 的距离 `r>0`。乘矩阵得到 `w_c=r`，`x_c=(q/a)X`，`y_c=qY`，`z_c=(f+n)r/(f-n)-2fn/(f-n)`。再除以 `w_c=r` 得：

```text
ndc_x = qX/(ar)
ndc_y = qY/r
ndc_z = (f+n)/(f-n) - 2fn/((f-n)r)
```

前三行可解释三个现象：物体越远，横纵投影越靠近中心；深度包含 `1/r`；`w=0` 时无法透视除法。

## 3. 窗口深度 `d`

本项目代码按 `d=(ndc_z+1)/2` 映射。代入上式可化简为：

```text
d(r) = f/(f-n) - fn/((f-n)r)
```

令 `r=n`，得到 `d=0`；令 `r=f`，得到 `d=1`。导数为 `d'(r)=fn/((f-n)r²)`。当距离变大时，`1/r²` 变小，意味着远处单位世界距离造成的深度差变小。固定的深度容差 `2e-5` 不能简单解读为固定多少米。

例如 `n=0.1`、`f=100`、`r=1` 时，`d≈0.90090`；`r=2` 时，`d≈0.95095`。深度看起来已接近 1，但它并不是背景；背景由纹理清除值 `1.0` 表示。

## 4. 正交投影的对照

对于相同 `n/f`、观察方向距离 `r`，标准正交窗口深度是：

```text
d_ortho(r) = (r-n)/(f-n)
```

它对距离呈线性关系，导数为常数 `1/(f-n)`。这有助理解为何当前用户场景的跳动主要在透视下表现，但不能证明正交视图永远没有像素采样误差。当前代码根据 `rv3d->is_persp` 决定是否使用局部平面补偿。

## 5. `text_anchor_project_with_depth` 每一步

1. `copy_v3_v3(vec4, co); vec4[3]=1`：把三维锚点扩成可受平移影响的齐次位置。
2. `mul_m4_v4(perspmat, vec4)`：得到裁剪空间四维向量。
3. `w=abs(vec4[3])`、`scalar=1/w`：准备透视除法，避免零除。
4. 比较 `vec4[2]` 与 `±w`：排除裁剪深度范围外的点。
5. `(width/2)*(1+clip_x/w)` 与 y 对应式：映射到像素浮点位置。
6. 检查 `fx/fy`：避免在视口外采样。
7. `ndc_z=clip_z/w`，`depth=(ndc_z+1)/2`：得到与深度缓冲比较的窗口深度。

函数之前的 `ED_view3d_project_short_ex` 还执行 Blender 原有裁剪逻辑。不要只拿教学矩阵公式代替实际投影路径；调试时应记录传入的 `persmat` 和输出的 `xy/depth`。

## 6. 为什么同一个三角形仍可用平面补偿

“透视深度与距离非线性”与“屏幕上的三角形深度线性插值”同时成立。GPU 投影后，三角形三个顶点各有窗口深度，光栅化对覆盖像素的深度按屏幕三角形的重心坐标插值。因此在同一个平面三角形内部，窗口深度可以写成 `z(x,y)=A x+B y+C`。

`text_anchor_is_occluded_perspective` 用中心像素和相邻像素估计 A、B，再计算文字锚点实际浮点屏幕位置上的表面深度。它并未把透视深度当成对三维距离线性的量。平面只能用于同一局部表面，所以还要用 3×3 样本验证候选是否平面一致。

## 7. 一个子像素算例

锚点落在 `xy=(4.9,4.8)`，整数像素为 `(4,4)`，中心位置 `(4.5,4.5)`。所以 `dx=0.4`、`dy=0.3`。中心深度 `0.5000`，向右每像素增加 `0.0020`，向上每像素增加 `0.0010`，则预测锚点处表面深度 `0.5000+0.4×0.0020+0.3×0.0010=0.5011`。

锚点深度也为 `0.5011` 时，单像素比较认为它比中心深度远 `0.0011`，远大于固定容差。但若 3×3 的采样确实构成该平面，补偿判断会显示文字。若中心到相邻像素跨越物体轮廓，九样本残差会阻止错误放行。

## 8. 量化、浮点与深度格式

深度纹理的请求格式与底层后端的实际实现应分别核对。即便纹理可用浮点回读，CPU 的矩阵乘法、GPU 顶点处理和光栅插值也未必给出按位相同的值。`text_depth_bias` 是最终比较容差；`text_depth_plane_tolerance` 是局部平面拟合容差。两者单位均是窗口深度，目的不同。

若想调阈值，先记录一个闪烁锚点的 `xy`、中心深度、锚点深度、候选平面预测和九样本最大残差。没有这些数据，单纯增大阈值可能让真实遮挡漏出。
