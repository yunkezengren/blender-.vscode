# 第二站：属性值怎样找到锚点并成为文字

> 核心文件：`overlay_attribute_text.hh`。这是九个文件中改动最多的一处。
> 读法：先认清入口与数据结构，再看普通几何、点云、实例，最后看字符串和标志的传播。

## 1. 它是什么类

`AttributeTexts : Overlay` 是 Overlay 绘制流程里的一个组件。其 `begin_sync` 在本轮同步开始时决定是否启用；`object_sync` 对每个相关对象读取 Viewer 预览数据并登记文字。文字不是在这里立即画到屏幕。`DRWTextStore` 接收缓存项，真正绘制在后面的 `DRW_text_cache_draw`。

类中的 `occlusion_test_` 是当前组件的布尔状态。它由 `state.viewer_text_occlusion_culling()` 初始化。它控制传给缓存的标志，也决定点云、实例是否需要调整锚点。

`enabled_` 是另一件事：没有 Viewer 属性文字预览，或者当前是选择 pass，就不生产文字。`occlusion_test_` 为真并不强迫 `enabled_` 为真。

## 2. 新引入的头文件为什么存在

`<algorithm>` 提供 `std::max`，用于避免负点云半径产生反方向偏移。`BLI_array.hh` 提供拥有内存的 `Array<float3>`，用于临时存每个点云锚点。`BLI_math_geom_c.hh` 提供射线与 AABB 的交点测试。`BLI_math_matrix.hh`、`BLI_math_vector.hh` 提供变换、长度、逆矩阵和缩放等数学操作。`BKE_object.hh` 提供对象包围盒查询。

头文件不是“运行开关”；它们让该头文件中的内联成员函数有对应声明可用。`overlay_attribute_text.hh` 被其他 `.cc` 包含，少了直接依赖可能碰巧通过间接 include，却容易随别处调整而编译失败。

## 3. `begin_sync`：每帧起点

已有语句 `enabled_ = !res.is_selection() && state.show_attribute_viewer_text()` 把“不是选择绘制且要显示 Viewer 属性文字”组合起来。新增 `occlusion_test_ = state.viewer_text_occlusion_culling()` 只读取用户选项。即使关闭 Viewer 文字，该成员仍会更新到当前状态，避免保留上一帧的选择。

## 4. `object_sync`：先看实例预览，再看几何类型

`ob_ref.preview_base_geometry()` 非空意味着这是 Viewer 预览相关对象。`state.dt` 指向文字缓存；`object_to_world` 是本地坐标到世界坐标的矩阵。

若 `preview_instance_index() >= 0`，这是某一个实例的预览。函数从预览基础几何的 `Instances` 上找 `.viewer`。如果找到，就调用 `add_instance_attributes_to_text_cache`，传入 `state`、属性访问器、对象、矩阵与实例下标，然后 `return`。这里的 `return` 很重要：已经处理实例域值后，不再把该对象按网格或点云路径重复加入文字。

普通对象按 `object.type` 分派。网格进入 `add_mesh_attributes_to_text_cache`；点云改走新的 `add_pointcloud_attributes_to_text_cache`；旧曲线和新 Curves 仍走通用属性路径。`object_sync` 负责选路线，不负责深度比较。

## 5. 普通属性路径：值域决定位置数目

`attributes.contains(".viewer")` 先确认有 Viewer 值。`attribute = lookup(".viewer")` 得到数据和所在域。`lookup<float3>("position", attribute.domain)` 取该域对应的位置。随后把 `attribute.varray`、位置、对象矩阵与 `occlusion_test_` 交给 `add_values_to_text_cache`。

“域”决定 `values[i]` 与 `positions[i]` 的配对含义。点域是每个点；边、面和角等路径会使用各自计算过的位置。域与位置数组不对应，文字就会落错地方，即使遮挡判断完全正确。

## 6. 网格属性：为什么有特殊的角域位置

网格路径已有计算 `corner_positions` 的逻辑。它考虑面法线、视图方向和不同元素类型的偏移，减少多个域的文字堆在完全相同位置。此次改动保持这些位置逻辑，在调用 `add_values_to_text_cache` 时补上传递 `occlusion_test_`。

有角域位置数组时，使用 `corner_positions.as_span()`；其余情况使用 `positions`。`Span<float3>` 是只读视图，不拥有数据。`Array<float3>` 存储实际内存，必须在调用期间保持有效；`add_values_to_text_cache` 会立即遍历值、把结果复制/写入 `DRWTextStore`，所以临时数组在当前函数范围内就够用。

## 7. 点云：为什么中心锚点会被自己遮住

点云绘制出的可见几何有半径。原始点位置是圆盘中心。如果深度缓冲记录点的前方表面，用中心作为文字锚点，`anchor_depth` 就比圆盘表面更远。深度判断会把自己的文字剔除。

新函数先读取属性和 `pointcloud.positions()`。没有 `.viewer` 就立即返回。选项关闭时走原路径，避免准备半径与世界空间锚点。选项打开才读取逐点 `pointcloud.radius()`。

`radius_scale = length(to_scale(object_to_world)) * 0.577350269f` 是对象三个轴缩放的均方根，`0.577350269` 近似 `1/√3`。同一公式可在 `draw_pointcloud_lib.glsl` 中找到：`length(to_scale(object_to_world)) * M_SQRT1_3`。这是**匹配当前点云 shader 的半径缩放规则**，不是对任意非均匀缩放几何的精确屏幕轮廓求解。

透视视图的朝相机向量为 `camera_position - center`，各点方向不同。正交视图用相同的 `camera_forward`。`distance > 1e-20` 防止对零长度向量做除法；否则退回 `camera_forward`。

`anchors[i] = center + direction * max(radii[i], 0) * radius_scale` 为每个点独立计算锚点。`max` 把负半径夹为零。`float4x4::identity()` 传给后续函数，因为这些 `anchors` 已经是世界坐标；若再乘 `object_to_world` 就会变换两次。最后一个 `true` 令这些文字带深度测试标志。

## 8. 实例：为什么 AABB 能作为轻量近似

实例域文字原本绑定实例原点 `(0,0,0)`。实例的可见几何经常包住原点，原点相对视图位于几何内部。深度判断把它当成被实例本身遮挡。

`lookup(".viewer").varray.slice(IndexRange(instance_index, 1))` 只取当前实例的一条属性值。`GVArray` 是类型擦除的虚拟数组表示；`slice` 没有把整个实例数组都转换成文字。

`local_anchor(0)` 是实例本地原点。`BKE_object_boundbox_get(&object)` 给当前对象几何的本地轴对齐包围盒，返回 `std::optional<Bounds<float3>>`；可能没有边界，所以先检查 `bounds`。`bounds->contains(local_anchor)` 限制当前算法为“原点在盒内”的情况。`determinant(object_to_world)` 接近零时逆矩阵不可靠，故以 `1e-20` 做退化保护。

`world_to_object = invert(object_to_world)` 把朝相机方向转回本地坐标。`world_center = object_to_world.location()` 是本地原点的世界坐标。透视时 `toward_camera = camera_position - world_center`，没有归一化；正交时用 `camera_forward`。`math::transform_direction` 只变换方向，不加平移。

射线为 `P(t) = local_anchor + t * local_direction`。因为透视向量从原点指向相机，`t=1` 对应相机本身。`isect_ray_aabb_v3_simple` 在这里把相机方向的盒出口参数写入 `exit_t`。代码要求方向非零、射线命中、`exit_t>0`，透视还要求 `exit_t<1`，确保出口位于原点与相机之间。满足条件时才前移锚点。

**AABB 只是长方体包围盒**。它可能位于真实几何的前面；文字可能因此被允许显示在真实表面之外。它也不能表达凹陷和空洞。当前改法优先低成本，且只为此实例准备一个锚点。更精确的凸壳或 BVH 需要更多几何准备与射线求交。

## 9. 文字标志如何一直传到最终缓存

新增 `flag` 参数进入 `add_text_to_cache` 和 `add_lines_to_cache`。两者最终都调用 `DRW_text_cache_add`，把同一个标志写进每条文字的 `ViewCachedString::flag`。

`text_flags = DRW_TEXT_CACHE_GLOBALSPACE | (occlusion_test ? DRW_TEXT_CACHE_OCCLUSION_TEST : 0)` 是位组合。`GLOBALSPACE` 说明本函数传入世界坐标；条件表达式决定是否附加遮挡位。对多行值，例如 `float3`、颜色、四元数、矩阵，所有行共用相同锚点和标志。也就是说多行文本会逐条走后续绘制判断，但一组数值不会出现某行故意不开测试。

`add_values_to_text_cache` 中的 `to_static_type` 把运行时属性类型分派成编译期类型 `T`。`values.typed<T>()` 提供该类型的读取；`positions[i]` 取匹配位置；`math::transform_point` 将位置变到世界空间。格式化分支把布尔、整数、浮点、向量、颜色、四元数和矩阵转为一行或多行字符串。此次遍历和格式化逻辑基本沿用原代码，关键变化是每个 `add_text_to_cache` / `add_lines_to_cache` 调用都追加 `text_flags`。

## 10. 一次调试应检查哪些数值

若文字错位：查 `attribute.domain`、`positions[i]`、`object_to_world`、实例 `local_anchor`。若文字存在但被剔除：查 `text_flags` 是否带 `OCCLUSION_TEST`，然后去第四篇检查投影和深度。若点云全部不显示：查每点 `radius`、`radius_scale` 和计算出的 `anchors[i]`。若只在实例上出现：查包围盒是否存在、是否包含原点、矩阵行列式、`exit_t`。
