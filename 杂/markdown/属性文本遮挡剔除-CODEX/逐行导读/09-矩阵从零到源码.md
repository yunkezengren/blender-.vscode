# 矩阵从零到源码：把 `float4x4` 真正看懂

> 这篇从“矩阵是什么”开始，最后能解释 `object_to_world`、`world_to_object`、`persmat`、`persmatob` 和 `mul_m4_v4` 各在做什么。
> 数学公式采用**列向量记法**，即右边的向量先作用：`p_world = M_object · p_local`。Blender 源码的存储下标与数学排版方式不必一一对应；调试时以 API 的变换语义为准。

## 1. 矩阵不是神秘的四方格

三维位置 `(x,y,z)` 可以被平移、旋转、缩放。矩阵把一组变换规则包装成可以重复作用的对象。最简单的二维缩放矩阵 `[[2,0],[0,3]]` 作用于 `(4,5)`，得 `(8,15)`：第一行算新 x，第二行算新 y。

矩阵乘向量时，每个输出分量是矩阵对应行与向量的点积。若 `A` 是 `m×n`，输入有 `n` 个分量，输出有 `m` 个分量。`4×4` 矩阵接受四维齐次向量，产出四维结果。

矩阵相乘表示变换的组合。`A · B · p` 的计算顺序是先 `B · p`，再 `A`。因此 `projection · view · object · local_point` 依次完成本地到世界、世界到观察、观察到裁剪的变换。顺序反过来通常会得到不同结果。

## 2. 为什么三维位置要加第四个数

普通 `3×3` 线性矩阵能做旋转与缩放，不能单独表示“所有点统一向右 5”。用 `(x,y,z,1)` 表示**位置**，用 `(dx,dy,dz,0)` 表示**方向**，则同一个 `4×4` 仿射矩阵既能处理旋转缩放，也能在最后一列放平移。

数学排版中的仿射矩阵：

```text
| r00 r01 r02 tx |   | x |   | r00*x + r01*y + r02*z + tx |
| r10 r11 r12 ty | · | y | = | r10*x + r11*y + r12*z + ty |
| r20 r21 r22 tz |   | z |   | r20*x + r21*y + r22*z + tz |
|   0   0   0  1 |   | 1 |   |                1             |
```

若右侧最后一项是 `0`，平移项乘零，方向只受线性部分影响。这就是 `math::transform_point` 与 `math::transform_direction` 的关键区别。**射线方向不是一个世界位置**，不能把相机或对象的平移加进去。

## 3. 单位矩阵与两次变换错误

单位矩阵 `I` 的主对角线为 1，其余为 0，满足 `I·p=p`。`add_values_to_text_cache` 会计算 `transform_point(object_to_world, positions[i])`。

普通网格传本地 `positions` 和真实 `object_to_world`；点云新路径先自行算出世界 `anchors`，因此传 `float4x4::identity()`。如果点云世界锚点再乘真实对象矩阵，位置会二次平移、旋转和缩放，错误不一定立刻显眼，但深度采样像素会完全错位。

## 4. `object_to_world` 的组成

设对象局部点为 `p_local`，通常可把对象矩阵理解为平移、旋转和缩放的组合 `M = T·R·S`。在这个记法下，`S` 先缩放，`R` 再旋转，`T` 最后平移。真实对象矩阵还可能包含更复杂的仿射成分，不应盲目把每个对象都当作纯正交旋转和均匀缩放。

`object_to_world.location()` 提取本地原点的世界位置。实例路径用它得到实例中心 `world_center`。`math::to_scale(object_to_world)` 提取轴尺度，点云半径路径用三个尺度的均方根，使 CPU 的半径偏移与当前 shader 的尺度规则保持一致。

## 5. 逆矩阵：从世界回到本地

如果 `p_world = M·p_local` 且 `M` 可逆，那么 `p_local = M⁻¹·p_world`。逆矩阵不是“把所有数字取倒数”；它是满足 `M⁻¹·M=I` 的整体变换。

实例包围盒的 `Bounds<float3>` 在本地坐标里定义，所以向相机的世界方向必须用 `world_to_object = invert(object_to_world)` 转回本地。代码先检查 `abs(determinant(M)) > 1e-20`。行列式为零表示线性部分把某一维压扁，无法唯一逆变换；接近零时数值也可能不可靠。阈值是当前代码里的保护值，不是普适的“所有矩阵安全线”。

## 6. 数值例子：平移加缩放

对象把本地 x 轴放大 2 倍，再平移世界 x=3。只看 x：`world_x = 2·local_x + 3`。本地 `(1,0,0)` 到世界 `(5,0,0)`。世界相机在 `(13,0,0)`，对象原点的世界位置 `(3,0,0)`，向相机方向为 `(10,0,0)`。

逆变换的**方向部分**只除以 2，不减平移，所以本地射线方向是 `(5,0,0)`。若本地包围盒 x 覆盖 `[-1,1]`，从本地原点到朝相机盒面 x=1 的参数是 `t=1/5=0.2`。新本地锚点为 `(1,0,0)`，世界锚点是 `(5,0,0)`。相机对应 `t=1` 的本地 x=5。

如果错把方向使用 `transform_point(M⁻¹, (10,0,0))`，会把世界平移减进去，得到错误方向。这就是 API 命名里 `point` 与 `direction` 不可互换的实际后果。

## 7. 矩阵顺序在项目中怎么验证

`rv3d->persmat` 是把世界坐标送入裁剪空间的组合矩阵；`rv3d->persmatob` 用于对象本地坐标。项目中 `view3d_utils.cc` 的调用把 `rv3d->persmat` 与对象矩阵组合为 `persmatob`，验证了“本地先到世界、再做视图投影”的语义。

属性文字缓存设置 `DRW_TEXT_CACHE_GLOBALSPACE`，所以 `DRW_text_cache_draw` 选择 `rv3d->persmat`。若缓存里保存的是本地坐标且不带该位，才用 `persmatob`。两个矩阵的区别是已经包含对象变换与否。

## 8. Blender 存储方式与数学记法

源码有 `float[4][4]` 和 `float4x4`，不同 API 的索引约定、参数次序不能仅凭表面 `m[3][0]` 猜测。这里的矩阵图是数学解释，不是对每个下标的内存布局说明。可靠的核对方式是看 `math::transform_point`、`math::transform_direction`、`mul_m4_v4` 的输入输出，并用平移和单位矩阵做小数值例子。

## 9. 常见错误清单

| 误用 | 后果 | 对应源码 |
|---|---|---|
| 世界锚点再乘对象矩阵 | 投影像素错位 | 点云传 `identity()` |
| 世界方向直接与本地 AABB 求交 | 射线与盒不在同一空间 | 实例 `transform_direction(world_to_object, ...)` |
| 用点变换处理方向 | 平移混入方向 | 同上 |
| 可逆矩阵检查缺失 | 零缩放时求逆不可靠 | `determinant` 保护 |
| `persmat` 与 `persmatob` 混用 | 同一文字被投到错误位置 | 文字标志选择矩阵 |
