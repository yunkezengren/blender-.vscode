# 调试路线、性能观测和已知边界

> 本篇帮助把用户观察到的现象定位到具体层。它不会把推测当成已经测得的根因。

## 1. 先问“文字是否进入缓存”

如果任何视角都没有某条属性文字，先查 `.viewer` 是否存在、该对象是否被 `object_sync` 处理、`enabled_` 是否为真。实例路径还依赖 `preview_instance_index` 和该实例的属性值。没有缓存项时，深度比较根本不会运行。

如果关掉遮挡选项文字会显示，说明值和字符串生产基本可用，可把重点放到锚点、深度读取和比较。

## 2. 再问“锚点在什么空间”

网格和普通曲线由公共函数乘 `object_to_world`。点云已经生成世界锚点并传单位矩阵。实例先在本地盒上求交，再由公共函数乘对象矩阵。任一路径多乘或少乘一次矩阵，投影就会指向错误像素。

建议记录一个稳定 ID 的本地位置、世界位置、`xy`、`anchor_depth`。调试日志必须限定到单个 ID 或少量点，避免成千上万条文字刷满控制台。

## 3. 检查深度来自哪一帧

若移动相机后出现“远处全灭、近处全亮”，检查 `update_text_depth` 是否每帧用带目标缓冲的 `GPU_texture_read` 刷新像素。缓存指针复用和像素内容复用是两件不同的事。

若沿网格轴或地面网格闪烁，检查回读时机是否仍在 grid 绘制前。这个顺序被 `draw_v3d` 的调用位置决定，不能只看 `update_text_depth` 函数内部。

## 4. 检查单像素与透视补偿

对一条“明明在表面，却被剔除”的文字，记录：`xy` 的浮点值、`int(xy)` 结果、中心 `scene_depth`、`anchor_depth`、`rv3d->is_persp`、最终 `occluded`。如果基础比较判遮挡且透视补偿判可见，现象符合采样位置差异。若透视补偿也判遮挡，记录四象限各自失败原因：越界、预测仍在前方、背景样本或平面残差。

正交视图只走单像素判断。若未来正交也出现同类问题，需要先收集数值证据，再决定是否扩展补偿；当前限定来自实际复测范围。

## 5. 点云与实例自身遮挡

点云：检查 `radius[i]` 是否为预期、变换尺度是否与 shader 规则匹配、`anchors[i]` 是否朝相机前移。各点必须用各自半径。

实例：检查 `BKE_object_boundbox_get` 是否有值、盒是否含原点、对象矩阵是否可逆、局部射线方向是否非零、`exit_t` 是否满足条件。若 AABB 与真实表面相差很大，即使算法按代码正确运行，也可能出现视觉上不理想的锚点。

## 6. 性能应测什么

按成本来源分开量测：

| 指标 | 反映什么 | 一般执行频次 |
|---|---|---|
| 文字缓存条目数 | 后续逐条判断的规模 | 每帧 |
| `DRW_text_cache_needs_depth_test` 用时 | 是否需要回读的扫描 | 最多一次/相关帧 |
| `GPU_texture_read` 用时 | 整幅深度 GPU→CPU 回读 | 有需要时每帧一次 |
| 基础判断命中数 | 直接判可见/遮挡的比例 | 每条带标志文字 |
| 透视补偿调用数 | 进入四象限算法的真实比例 | 仅透视且基础判遮挡 |
| `draw_text` 总用时 | 文字绘制和 BLF 的总成本 | 每帧 |

复杂度是 O(文字条目数)，但一次 GPU 回读可能比多数 CPU 算术更显著。不能只根据循环层数断言“很卡”或“完全没影响”。此前 34 项数值检查验证了算法路径，没有量测真实视口帧时。

## 7. 当前实现能保证什么

它按文字**锚点**决定显示与否，不逐字形像素裁剪。它在透视视图用经 3×3 验证的局部深度平面补偿采样位置差异。点云按逐点半径移锚点，实例按本地 AABB 出口移锚点。GPU 深度每帧刷新，且在 grid 影响深度前读取。

## 8. 当前实现不能保证什么

极细面、三角形边界、曲面、高曲率、透明物体、复杂遮挡和与实际表面不一致的 AABB，可能不能由四个 3×3 候选平面表达。没有可靠局部平面时，代码保留基础遮挡判断。AABB 不是凸壳，更不是实际网格求交。各 GPU 后端和显示模式对深度内容的贡献也需现场验证。

这些限制不是对当前复测结果的否定；它们定义了后续排查应优先收集的证据。
