# 第一站：按钮怎样传到 C++ 绘制层

> 本篇逐项解释四个文件：`DNA_view3d_types.h`、`rna_space.cc`、`space_view3d.py`、`overlay_private.hh`。
> 读完会知道按钮的值为什么可以保存、为什么 Python 能访问，以及 C++ 如何取得它。

## 1. 先看 DNA：给状态分配一个位

`eView3DOverlay_Flag` 是整型位集合，每一位可以独立表达一个开关。
已有 `V3D_OVERLAY_VIEWER_ATTRIBUTE_TEXT = (1 << 18)` 控制属性文字是否显示；`V3D_OVERLAY_PERFORMANCE = (1 << 19)` 是邻近既有标志；当前新增 `V3D_OVERLAY_VIEWER_TEXT_OCCLUSION_CULLING = (1 << 20)`。

`1 << 20` 的意思是二进制的第 20 位为 1，其余位为 0。它能与已有标志通过按位或共存。若两个开关共用同一位，切一个就会影响另一个，所以新位必须唯一。`ENUM_OPERATORS(eView3DOverlay_Flag)` 允许这种枚举参与相应位运算。

新增位仅表达**用户选择**；它不会自己执行深度测试。把它理解为配电开关，电路的实际工作仍在后面的 `State`、`AttributeTexts` 与文字绘制函数里。

## 2. RNA：让位标志具有名字、提示和更新行为

`rna_def_space_view3d_overlay(BlenderRNA *brna)` 注册 `View3DOverlay` 的属性。`RNA_def_property(srna, "viewer_text_occlusion_culling", PROP_BOOLEAN, PROP_NONE)` 建立一个布尔 RNA 属性。这里的字符串是 Python 属性名，面板会用同名属性读取和修改。

`RNA_def_property_boolean_sdna(prop, nullptr, "overlay.flag", V3D_OVERLAY_VIEWER_TEXT_OCCLUSION_CULLING)` 把这个布尔属性映射到 DNA 的 `overlay.flag` 指定位。`prop` 是刚创建的 RNA 属性描述对象；`nullptr` 在这里使用默认结构来源；`"overlay.flag"` 指出底层字段；最后一个参数是位掩码。

`RNA_def_property_clear_flag(prop, PROP_ANIMATABLE)` 说明这个界面设置不按动画属性处理。`RNA_def_property_ui_text` 提供标题 `Occlusion Culling` 和悬停提示，提示明确说比较文字**锚点**与场景几何遮挡：这不意味着逐字形像素测试。

`RNA_def_property_update(prop, NC_SPACE | ND_SPACE_VIEW3D, nullptr)` 把属性改变通知给 3D 视图。用户切换开关后需要视图刷新，下一次同步才能读取新的标志。`|` 组合的是两类通知位。

这五个调用按“创建属性 → 映射底层存储 → 设置元信息 → 发出更新通知”的顺序理解即可。每一行配置的是同一个 `prop`。

## 3. Python 面板：在哪里显示，何时允许操作

`VIEW3D_PT_overlay_viewer_node.draw` 中已有属性文字总开关。新增的第一行 `row = col.row(align=True)` 建立一行；`align=True` 让这一行的控件按 Blender 面板惯例靠拢。

第二行：

```python
row.active = view.show_viewer and overlay.show_text and overlay.show_viewer_text
```

这不是改变选项的值，而是决定控件是否可以操作。只有 Viewer 预览、一般文字显示、属性文字显示三者都开启时，深度剔除控件才有实际意义。关掉上游选项以后，当前选择仍可保留，重新启用后恢复。

第三行 `row.prop(overlay, "viewer_text_occlusion_culling", text="Occlusion Culling")` 创建真正的复选框。`overlay` 是 RNA 对象，第二个参数必须与注册名一致。`text=` 决定面板上的短标签。

## 4. C++ State：把底层位包装为可读查询

`State` 中已有 `show_attribute_viewer_text()`。新函数：

```cpp
bool viewer_text_occlusion_culling() const
{
  return (this->overlay.flag & V3D_OVERLAY_VIEWER_TEXT_OCCLUSION_CULLING);
}
```

`const` 保证查询不改 `State`；`&` 只保留目标位。结果非零时隐式转成 `true`，否则为 `false`。这个函数不判断是否存在几何、深度或文字；它只读取设置。

`AttributeTexts::begin_sync` 在一帧开始时调用它，把结果存进 `occlusion_test_`。因此不必让每条文字都直接访问 RNA，也避免把 UI 概念传播到通用文字绘制层。

## 5. 两个开关要分清

`show_viewer_text` 控制属性文字是否进入文字缓存。`viewer_text_occlusion_culling` 控制这些文字是否带遮挡测试标志。第二个开关不开时，文字依然可以存在并绘制。

如果只看 `DNA` 新位，会误以为“打开选项就触发 GPU 读回”。实际触发条件还有 `state.show_text`、3D 视图、以及缓存中至少一条文字带测试标志。条件检查在 `Instance::update_text_depth`。

## 6. 为什么四个文件都要动

| 层 | 如果缺少它会怎样 |
|---|---|
| DNA | 没有稳定的状态位可存 |
| RNA | Python/UI 找不到 `viewer_text_occlusion_culling` |
| Python 面板 | 用户没有常规入口切换选项 |
| C++ State | 绘制实现必须直接理解底层位细节 |

这些文件组成一条数据路径，但不是一次函数调用链。UI 改动造成底层状态变化；下一帧 Overlay 同步时读取这个状态。
