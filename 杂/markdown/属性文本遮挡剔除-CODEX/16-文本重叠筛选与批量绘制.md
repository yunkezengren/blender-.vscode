# 文本重叠筛选与批量绘制

## 使用方法

按用户要求，本版仅保留绘制层实验，已撤回 DNA、RNA 和 Python 界面的新增设置。
`overlay_attribute_text.hh` 中的局部常量 `avoid_overlap = true` 暂时启用筛选。
需要代码级对比时可改为 `false`，重新编译后生效。
文字重叠筛选与 **Occlusion Culling（遮挡剔除）** 独立：前者处理文字之间的覆盖，后者处理几何体遮挡文字锚点。

开启后按当前元素遍历顺序保留互不重叠的标签。
标签保持原位置，多行向量、颜色、矩阵作为一个整体保留或隐藏。
本版将上一帧保留标签的缓存索引传给新一帧，优先尝试保留。
已保留标签使用 1 像素余量，新标签需要 4 像素余量，形成进入与退出的滞后。
视图移动造成真正的几何冲突时，显示集合仍会改变。
它也不保证在相同屏幕空间里保留数量最多的标签。

## 三项性能改进

1. 同一多行标签只投影和测试深度一次，后续行复用屏幕位置与可见性。
2. 使用 BLF 批处理字形，批处理结束后才恢复绘制矩阵。
3. 字号设置一次，相同颜色和描边状态复用，避免逐条重复设置。

开启避免重叠后，仅为通过筛选的标签生成绘制字形。
文字包围盒的测量结果同时用于居中和矩形筛选。
布局使用临时绘制位置，不再反复减写缓存中的 x/y 偏移。

## 标签分组

`DRW_TEXT_CACHE_CONTINUATION` 表示当前缓存行属于前一行所在的标签。
Viewer 写入多行属性时，仅后续行设置该标志。
因此相同坐标处的不同元素不会因位置相同被误认为同一标签。
该标志要求所有行共享锚点与投影/可见性选项。

`DRW_TEXT_CACHE_AVOID_OVERLAP` 只由启用该选项的 Viewer 属性文本设置。
测量文字等其他使用者不参与此筛选。
批处理仍用于通用缓存绘制。

## 屏幕网格

`TextOverlapGrid` 将视口分成 32×32 像素的单元。
每个单元保存与它相交的已接受标签矩形索引。
待选标签只检查覆盖单元中的矩形，并进行实际矩形相交测试。
两个标签处于相同网格单元不会自动互斥。
被拒绝的标签不占用单元，也不会阻止后面的标签显示。

每个多行标签先合并所有行的字形包围盒，再按 UI 缩放增加描边与间距余量。
稀疏标签通常只需访问少量单元；密集重叠标签通常很快遇到冲突并退出。
这避免了直接将所有候选标签两两比较。
极宽标签会覆盖更多单元，因此不承诺所有输入都具有严格线性耗时。

## 验证记录

从生产源码逐字提取网格类，在独立 MSVC 程序中使用标准库容器适配运行。
20,000 个随机矩形的接受结果与暴力逐矩形比较一致。
另外检查了视口边缘、单像素视口、矩形接触边界与跨单元重叠。

独立优化构建中的密集网格实验：

- 候选矩形数：1,000,000。
- 实际接受数：480。
- 单次测得网格筛选耗时：47,225 微秒。

这个数字仅描述网格算法；容器适配、优化级别均与 Blender Debug 构建不同。
它不包括格式化、深度回读、字体测量、字形生成和 GPU 绘制，不能当作 Blender 帧时。
完整构建已按用户要求停止，定时检查已暂停；本版尚未完成编译验证。

## 尚未解决的成本

文本仍在同步阶段按元素格式化和加入缓存，筛选发生在投影之后。
隐藏标签仍需投影与测量，深度模式也仍需每帧回读深度。
本次主要减少多行重复处理、状态设置、绘制调用和最终绘制的字形数量。
后续应以真实场景的阶段耗时决定是否继续优化格式化和标签生成。

## 视图移动时的闪烁修正

第一版按每帧当前矩形独立筛选，稍微移动视图就会让标签在碰撞阈值两侧反复切换。
Overlay 每帧重新创建文字缓存，因此新缓存现在接收旧缓存的已接受标签索引。
绘制分两遍：先处理上一帧显示过的 Viewer 标签，再处理新增标签和普通文字。
真实的几何遮挡仍在当前帧重算，历史只影响标签之间的优先级。

此实验使用缓存中的标签起始索引作为跨帧标识。
如果对象遍历顺序或元素数量变化，索引可能暂时代表另一条标签。
要做正式功能，需要对象与元素的稳定标识来解决这一限制。
按用户要求，本轮不运行完整 Blender 编译；修复效果仍需后续构建并在视口中验证。

## 复测建议

- 对比局部常量关闭/开启后的构建，确认密集编号不再覆盖。
- 用向量与颜色属性检查各分量一起显示或隐藏。
- 分别启用/关闭几何遮挡，确认标签筛选不让被遮挡标签占据位置。
- 检查透视、正交、视口边缘、不同 UI 缩放和多行矩阵标签。
- 在同一场景比较缩放、旋转流畅度；本版尚无真实视口前后帧时数据。
