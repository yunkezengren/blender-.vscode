一帧的真实时间顺序

设置并不直接读取 GPU。属性条目先加入文字缓存，之后 Overlay 依据其中是否有遮挡标志，才决定是否读取深度。

同步开始：`AttributeTexts::begin_sync` 读取 State 的用户选项。没有 Viewer 文字时组件不会生产条目。
按对象同步：`object_sync` 找 `.viewer` 值，准备点云/实例锚点，`DRW_text_cache_add` 缓存字符串。
深度 prepass 结束：当前场景的可遮挡表面已把深度写入视口缓冲。
grid 绘制之前：`Instance::update_text_depth` 按需回读本帧深度，避开网格线与轴线对深度的影响。
输出阶段：`draw_text` 调用通用文字绘制。每个锚点投影、比较深度，合格者交给 BLF。

三个容易混淆的边界

谁拥有深度？

Instance::text_depth_cache_ 拥有 CPU 深度副本；DRWTextStore::depths 只借用指针。每帧更新的是像素内容，尺寸不变时可复用内存。

文字锚点等于字形吗？

深度测试发生在三维锚点。BLF 之后画出二维字形；本分支不为每个字符像素做几何遮挡。

AABB 等于表面吗？

它是本地空间的包围长方体，可能比真实几何宽。实例把锚点移到盒出口，仅作为轻量近似。

四个象限每次都跑吗？

只有透视视图且单像素初判遮挡才进入。发现一个有效平面就返回；没有额外 GPU 回读。
