01 / 基础

先分清“点”和“方向”

三维数值 (x,y,z) 可以表示空间位置，也可以表示方向。第四个齐次分量决定平移是否作用到它。

位置：w = 1

p = (x, y, z, 1) M · p = 旋转缩放后的坐标 + 平移

点云的 positions[i]、实例的 local_anchor 都是位置。代码用 math::transform_point 把点变到世界空间。

方向：w = 0

d = (dx, dy, dz, 0) M · d = 旋转缩放后的方向

实例射线的 toward_camera 是方向。代码用 math::transform_direction，平移不应混进来。

手算：对象沿 x 平移 3，x 轴缩放 2。位置 x=1 变成 2×1+3=5；方向 dx=1 只变成 2×1=2。

齐次坐标还允许透视投影。仿射对象矩阵的最后一行在数学列向量排版下通常是 (0,0,0,1)；投影矩阵可以让输出的 w 依赖点与相机的距离。随后用 x/w、y/w 得到远小近大的画面。

03 / 几何

逆矩阵让射线和 AABB 处于同一空间

为什么 t=1 是相机？

C = object_to_world · (0,0,0,1) D_world = K − C D_local = inverse(object_to_world) · (D_world,0) P_local(t) = O + t · D_local

方向没有归一化。t=1 表示走完整个“原点到相机”的向量。对象在朝相机方向的盒出口若 0 < exit_t < 1，就位于相机之前。

04 / 投影

透视深度为何不是“每米增加固定值”

标准对称透视投影令观察空间距离为 r、近裁剪为 n、远裁剪为 f。窗口深度 d 的变化包含 1/r；正交深度随距离线性变化。

透视：d(r) = f/(f−n) − fn/((f−n)r) 正交：d(r) = (r−n)/(f−n) 像素：x = width/2 × (1 + clip_x/clip_w) y = height/2 × (1 + clip_y/clip_w)

05 / 遮挡

文字在像素内部，深度却取像素中心

一个像素格子的整数索引为 (4,4)，中心是 (4.5,4.5)。锚点可能落在 (4.9,4.8)。同一个斜面上，这两个位置本来就可能有不同深度。

调整锚点和局部斜率

源码的两道判断

初判：anchor_depth > center + 0.00002 补偿：surface_at_anchor = center + slope_x × dx + slope_y × dy 平面检查：九个样本都接近预测平面

只在透视、且单像素初判遮挡时尝试补偿。四个象限各最多检查 3×3 样本；背景或不平面样本会拒绝候选。此交互图假定所有邻域样本来自一个平面，实际源码还必须验证这一点。

自己预测：把 dx=0.4、slope_x=0.002、其他斜率和真实遮挡差设为 0。中心是 0.5000，锚点深度会变为 0.5008。单像素会剔除；若邻域确实是一个平面，补偿会显示。
