## 1. 放进整条调用链

```text
Instance::begin_sync()
  └─ 销毁上一轮 DRWTextStore，建立当前轮的文字清单
       └─ 属性预览等来源向清单添加文字及锚点

Instance::draw_v3d()
  ├─ 场景及 Overlay 的深度预处理
  ├─ update_text_depth()       ← 本章：把当前帧深度从 GPU 读到 CPU
  ├─ grid、axes 等继续绘制
  └─ draw_text()
       └─ DRW_text_cache_draw() ← 按文字投影、取深度、决定画或跳过
```

调用点在 `overlay_instance.cc:938–939`；文字绘制调用在 `1009`、`1055–1063`。把读取安排在 grid 和 axes 之前，是为了避免它们画出的细线写入深度并被误认为遮挡文字的实体表面。**本函数只提供深度数据，不逐条判断文字。**

这里的 `Instance` 是 Overlay 绘制引擎的 C++ 实例，不是 Geometry Nodes 的实例域。实例域文字的锚点在别处计算，最终和其他文字一起进入 `state.dt`。

## 2. 三份相关数据及所有权

| 对象 | 内容 | 谁拥有 | 何时改变 |
|---|---|---|---|
| `GPUViewport` 的 `depth_tx` | GPU 上当前视口的深度纹理 | 视口绘制系统 | 随当前帧的绘制更新 |
| `Instance::text_depth_cache_` | `ViewDepths` 与 CPU 浮点深度数组 | Overlay `Instance` | 尺寸变化时重建；需要时每帧覆写数组 |
| `state.dt` | 待绘制字符串与借用的 `const ViewDepths *` | 当前轮文字缓存 | `begin_sync()` 重建；本函数设置借用指针 |

`ViewDepths` 定义在 `source/blender/editors/include/ED_view3d.hh:91–97`：

```cpp
struct ViewDepths {
  unsigned short w, h;   // 图宽、高；每行有 w 个像素
  short x, y;            // 子矩形偏移；本函数未使用
  float *depths;         // 长度对应 w × h 的 CPU 深度数组
  double depth_range[2]; // 本函数设为 [0, 1]
};
```

取 `(x, y)` 像素时，逐行数组通常按 `depths[y * w + x]` 访问。`w` 必须对应这份数组的真实行宽，否则会读错像素。

`DRW_text_cache_depth_set()` 只执行类似 `dt->depths = depths` 的指针赋值，不复制深度数据，也不转移所有权。文字缓存借用该指针，`Instance` 负责保证它活到 `DRW_text_cache_draw()` 后。释放 `ViewDepths` 时，`ED_view3d_depths_free()` 先释放 `depths` 数组，再释放结构体。

## 3. 每一段代码在做什么

### 3.1 声明与退出条件：1017–1026

```cpp
void Instance::update_text_depth()
{
  // 这三个条件只要一个为真，本轮就无需准备 CPU 深度图。
  if (!state.show_text ||                   // 本轮根本不显示文字
      !state.is_space_v3d() ||              // 当前空间不是 3D View
      !DRW_text_cache_needs_depth_test(state.dt))  // 没有文字要求遮挡测试
  {
    // 清除 DRWTextStore 借用的指针。下一步可能释放其指向的对象。
    DRW_text_cache_depth_set(state.dt, nullptr);

    // 旧数组可能来自前一轮绘制。本轮不用，就释放。
    if (text_depth_cache_ != nullptr) {
      ED_view3d_depths_free(text_depth_cache_);
      text_depth_cache_ = nullptr; // 防止成员保留悬空指针
    }
    return; // 不访问视口，也不触发 GPU → CPU 回读
  }
```

`!` 是布尔取反，`||` 是逻辑或。C++ 对 `||` 从左到右短路求值：前面的条件为真时，后面的表达式可以不执行。比如完全不显示文字时，不必扫描文字清单。

`DRW_text_cache_needs_depth_test()` 会扫描 `state.dt->cache_strings`，找到带 `DRW_TEXT_CACHE_OCCLUSION_CULLING` 标志的文字时返回 `true`。扫描成本随文字条目数增长，但避免了无需要时的整张深度纹理回读。它判断“**是否至少有一条文字需要**”，不在这里逐条做可见性测试。

**为什么先 `depth_set(nullptr)` 再释放？** 假设 `state.dt->depths` 原来指向 `text_depth_cache_`。若先释放，`state.dt->depths` 会暂时成为悬空指针；先清空借用关系，随后释放所有者，生命周期更清楚。

### 3.2 获取当前帧的 GPU 深度纹理：1027–1032

```cpp
  /* Refresh from this frame after the depth prepass, before grid and axes can alter depth.
   * The read-back is deliberately skipped when no text requested occlusion testing. */

  // 从当前 ARegion 找到其 GPUViewport。
  GPUViewport *viewport = WM_draw_region_get_viewport(
      const_cast<ARegion *>(state.region));

  // 取该视口的深度纹理：这是 GPU 侧的数据源。
  gpu::Texture *depth_tx = GPU_viewport_depth_texture(viewport);

  // 尺寸取自纹理本身，随后据此决定 CPU 缓冲区能否复用。
  const int width = GPU_texture_width(depth_tx);
  const int height = GPU_texture_height(depth_tx);
```

`ARegion` 是 Blender 的屏幕区域对象；`state.region` 的静态类型是 `const ARegion *`。`WM_draw_region_get_viewport` 的接口接受 `ARegion *`，这里用 `const_cast` 去掉类型上的 `const`。它不会复制对象，也不意味着任意修改原对象都是安全的；是否实际修改取决于被调用函数的实现与原对象的约束。

深度纹理是当前视口的逐像素深度结果。它和 `ViewDepths` 不同：前者在 GPU 资源里；后者提供 CPU 可读取的浮点数组。`width`、`height` 单位为**像素**，不是世界空间尺寸，也不是窗口在桌面上的坐标。

### 3.3 处理视口尺寸变化：1033–1038

```cpp
  if (text_depth_cache_ != nullptr &&
      (text_depth_cache_->w != width || text_depth_cache_->h != height))
  {
    ED_view3d_depths_free(text_depth_cache_);
    text_depth_cache_ = nullptr;
  }
```

此处同时要求旧缓存存在、宽或高至少一个发生变化。举例：旧纹理为 `800 × 600`，新纹理为 `1000 × 600`，旧数组既装不下新结果，`y * w + x` 的行跨度也不对。即使像素总数碰巧一样，只要宽高组合不同，仍要重建，因为行布局已经改变。

判断的是**能否安全复用内存**，不是判断“场景是否改变”。相机转动、对象移动时，即使尺寸完全相同，下面的 `else` 仍会把数组覆写成当前帧的深度。

### 3.4 首次使用或尺寸变化后的首次回读：1039–1047

```cpp
  if (text_depth_cache_ == nullptr) {
    // 分配并清零 ViewDepths 结构体；尚未分配逐像素数组。
    text_depth_cache_ = MEM_new_zeroed<ViewDepths>("ViewDepths");
    text_depth_cache_->w = width;
    text_depth_cache_->h = height;

    // 三参数重载：读取 mip 0，并返回新分配的 CPU 缓冲区。
    text_depth_cache_->depths = static_cast<float *>(
        GPU_texture_read(depth_tx, GPU_DATA_FLOAT, 0));

    // 记录此处采用的窗口深度范围。
    text_depth_cache_->depth_range[0] = 0.0;
    text_depth_cache_->depth_range[1] = 1.0;
  }
```

`MEM_new_zeroed<ViewDepths>` 分配的是**结构体**，`GPU_texture_read()` 返回的是另一块存储所有像素的内存。`"ViewDepths"` 是分配标签，便于内存诊断。`GPU_DATA_FLOAT` 要求以浮点数据形式回读；`0` 表示 mip level 0，即基础分辨率。因为三参数版本的返回类型是 `void *`，需 `static_cast<float *>` 才能存进 `depths`。

内存量的粗略估算：若结果每像素一个 32 位 `float`，1920 × 1080 的数组约为 `1920 × 1080 × 4 = 8,294,400` 字节，约 7.91 MiB。实际总显存、驱动暂存及传输成本另计。

`depth_range = [0, 1]` 是该视口深度的数值约定；**不要把深度值误解为米数**。透视投影下，它通常也不是与相机距离成正比的线性量。

### 3.5 已有且尺寸匹配的缓存：1048–1051

```cpp
  else {
    /* Refresh the contents with this frame's depth. */
    // 四参数重载：把当前帧数据写到已经分配好的目的缓冲区。
    GPU_texture_read(depth_tx, GPU_DATA_FLOAT, 0, text_depth_cache_->depths);
  }
```

这一分支**复用地址和容量，但不复用上一帧的像素值**。四参数重载返回 `void`，最后一个参数 `dst` 是调用者已经提供的目标内存。相机移动后，新的深度会覆盖旧数组。这一点直接关系到先前出现过的“远一点全部消失、近一点又全部显示”：若只在尺寸变化时读深度，就会把新相机投影的锚点拿去比较旧相机的像素深度。

复用分配不等于回读免费。需要遮挡测试的每一轮仍会读整张深度纹理。GPU 到 CPU 的传输和潜在同步，通常比本函数的几个条件判断更值得关注。要判断具体帧时影响，应分别测量关闭/开启属性文字遮挡时的视口耗时、分辨率和 GPU 后端。

### 3.6 提供给文字缓存：1052–1053

```cpp
  // 文字缓存借用这份深度图；不取得所有权。
  DRW_text_cache_depth_set(state.dt, text_depth_cache_);
}
```

后续 `draw_text()` 调用 `DRW_text_cache_draw()`。绘制代码把每条文字的世界或对象局部锚点投影到屏幕，再比较锚点深度与相应像素的场景深度。当前分支的透视视图还有局部平面重建来缓解子像素位置与整像素采样产生的误判；正交视图走较直接的比较路径。详情见 `source/blender/draw/intern/draw_manager_text.cc:193–291`。

`DRW_text_cache_depth_set()` 所建立的借用关系要求 `text_depth_cache_` 在文字绘制期间保持有效。`Instance` 析构时也负责释放缓存；在本函数的跳过分支与尺寸变化分支中，则会提前释放旧缓存。

## 4. 三条时间线：什么刷新、什么复用

```text
帧 N：窗口 1000×800，相机 A
  begin_sync → 新建文字清单
  update_text_depth → 首次分配数组，读取相机 A 的深度
  draw_text → 文字锚点按相机 A 投影，与相机 A 深度比较

帧 N+1：窗口 1000×800，相机 B
  begin_sync → 再次建立文字清单
  update_text_depth → 复用 CPU 数组，覆写为相机 B 的深度
  draw_text → 锚点按相机 B 投影，与相机 B 深度比较

帧 N+2：窗口 1200×800，相机 B
  update_text_depth → 旧数组尺寸不符，释放并重新分配、回读
```

这里存在两个名称相近但生命周期不同的“缓存”：`state.dt` 缓存待画文字，`text_depth_cache_` 缓存 CPU 深度数组的分配。前者在 `begin_sync()` 重建；后者可跨帧留存，但内容需要按当前帧刷新。

## 5. 理解与排查时的边界

- **本函数不决定每条文字是否被遮挡。** 判断发生在 `DRW_text_cache_draw()` 的遍历中。
- **本函数不处理实例域文字的几何锚点。** 实例中心、包围盒求交等逻辑位于属性文字生成路径。
- **有一条文字需要测试，就会读整张视口深度。** 减少需要测试的条目数并不必然降低这次回读的像素量。
- **缓存复用解决分配问题，不解决传输成本。** 若评估性能，应测 GPU 回读与同步，不只看循环次数。
- **深度图代表读取时刻。** 若读取后有其他绘制写入深度，文字使用的仍是此前抓取的场景快照；这是调用时序的明确选择。
- **文档按源码快照写成。** 将来若深度来源、视口尺寸类型、文字绘制时序变化，应重新核对这里的所有权和时间线。
