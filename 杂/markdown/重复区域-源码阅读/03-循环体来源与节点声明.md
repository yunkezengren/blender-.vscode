# 03 · 循环体来源与节点声明

前两篇已经走通“调用 Repeat → 建图 → 执行”。现在补上函数从哪里来，以及界面插槽如何定义。

## build_repeat_zone_function：逐句读构建入口

源码：[geometry_nodes_lazy_function.cc](../../source/blender/nodes/intern/geometry_nodes_lazy_function.cc)，2243 行。

```cpp
void build_repeat_zone_function(const bNodeTreeZone &zone)
{
  ZoneBuildInfo &zone_info = zone_build_infos_[zone.index];
  ZoneBodyFunction &body_fn = this->build_zone_body_function(
      zone, "Repeat Body", &scope_.construct<GeometryNodesLazyFunctionSideEffectProvider>());
  auto &zone_fn = build_repeat_zone_lazy_function(scope_, btree_, zone, zone_info, body_fn);
  zone_info.lazy_function = &zone_fn;
}
```

| 语句 | 解释 |
| --- | --- |
| 参数 `const bNodeTreeZone &zone` | 已经发现的区域，提供区域索引、两端节点与区域关系；不是临时创建区域 |
| `zone_build_infos_[zone.index]` | 根据区域索引取得该区域的构建记录，引用取得后可写回 |
| `build_zone_body_function(...)` | 将区域内部节点构建成可调用的体函数，返回函数及其接口编号信息 |
| `"Repeat Body"` | 调试名称，帮助识别函数 |
| `scope_.construct<GeometryNodesLazyFunctionSideEffectProvider>()` | 在资源作用域中构造体图的副作用提供者；它与 Repeat 外层按轮次选节点的提供者职责不同 |
| `build_repeat_zone_lazy_function(...)` | 用节点树、区域、接口信息和体函数构造 Repeat 包装函数 |
| `zone_info.lazy_function = &zone_fn` | 将包装函数写回区域构建记录，供外围图使用 |

## 这里涉及的四类对象

| 类型 | 含义 |
| --- | --- |
| `bNodeTreeZone` | 节点树中的一个区域，表达编辑图里的边界和归属关系；定义见 [BKE_node_tree_zones.hh](../../source/blender/blenkernel/BKE_node_tree_zones.hh) |
| `ZoneBuildInfo` | 区域整体的 LF 包装函数指针和接口索引 |
| `ZoneBodyFunction` | 区域体的 LF 函数指针和接口索引；它表示一轮所调用的体 |
| `ResourceScope` | 集中管理所构造资源的生命周期；函数引用的对象必须在使用期间存在 |

两个 Zone 结构都用 `ZoneFunctionIndices` 描述接口，但各自的编号属于自己的函数。不能拿包装层编号直接访问体函数插槽。

## 追到 Repeat 类构造

回到 [geometry_nodes_repeat_zone.cc](../../source/blender/nodes/intern/geometry_nodes_repeat_zone.cc)，423 行的工厂函数：

```cpp
return scope.construct<LazyFunctionForRepeatZone>(btree, zone, zone_info, body_fn);
```

它在作用域中构造 Repeat 函数对象，以基类引用返回。没有在这里执行循环。

再看 122 行附近的构造函数：

| 语句 | 解释 |
| --- | --- |
| `: btree_(btree)` | 保存节点树引用 |
| `zone_(zone)` | 保存区域引用 |
| `repeat_output_bnode_(*zone.output_node())` | 保存 Output 节点引用，作为设置与区域身份的来源 |
| `zone_info_(zone_info)` | 保存包装层接口信息引用 |
| `body_fn_(body_fn)` | 保存体函数及其接口信息引用 |
| `debug_name_ = "Repeat Zone"` | 设置调试名称 |
| `initialize_zone_wrapper(...)` | 初始化区域包装层接口，填充输入输出描述和索引信息 |
| `inputs_[...main[0]].usage = lf::ValueUsage::Used` | 从接口层声明 Iterations 是必需输入，使建图前能取得次数 |

这里的引用成员不会复制整个节点树或体函数。资源的生命周期由构图系统及作用域维持。此处的接口 `Used` 声明，与 `execute_impl` 写出的 Iterations usage 输出，分别服务于函数输入需求和向外围传播需求。

## 两个 node_declare：逐句对应界面

源码：[node_geo_repeat.cc](../../source/blender/nodes/geometry/nodes/node_geo_repeat.cc)。先看 Input 的 72—111 行，再看 Output 的 176—207 行。

`NodeDeclarationBuilder` 是插槽声明构建器，`decl::Int`、`decl::Extend` 是插槽声明类型。链式调用修改声明属性；这些函数不是逐轮执行循环体的代码。

### Repeat Input

| 源码语句 / 调用 | 逐句解释 |
| --- | --- |
| `b.use_custom_socket_order()` | 使用自定义插槽排列方式 |
| `b.allow_any_socket_order()` | 允许灵活排列插槽 |
| `b.add_output<decl::Int>("Iteration"_ustr)` | 声明整数输出 Iteration；`_ustr` 构造字符串表示 |
| `.description(...)` | 说明索引从 0 开始 |
| `b.add_input<decl::Int>("Iterations"_ustr)` | 声明整数输入 Iterations |
| `.min(0).default_value(1)` | 设置最小值 0 与默认值 1；求值层仍有负数钳制逻辑 |
| `b.node_or_null()`、`b.tree_or_null()` | 取得本次声明对应的节点与树；通用声明情形可能为空 |
| `if (node && tree)` | 实际节点和树都存在时才读取动态状态项 |
| `node_storage(*node)` | 取得 Input 的 `NodeGeometryRepeatInput` 设置 |
| `tree->node_by_id(storage.output_node_id)` | 按保存的 ID 找配对 Output；找不到就不进入分支 |
| 转换 `output_node->storage` | 取得 Output 的 `NodeGeometryRepeatOutput` 设置 |
| 遍历 `output_storage.items_num` | 两端的状态插槽都依据 Output 保存的项目数组 |
| `const NodeRepeatItem &item = ...items[i]` | 取得一个状态项，保存名称、类型和稳定标识等信息 |
| `socket_type = item.socket_type` | 取得插槽数据类型 |
| `item.name ? UString(item.name) : ""_ustr` | 名称存在则转换为字符串，否则使用空字符串 |
| `socket_identifier_for_item(item)` | 为该项目生成稳定的插槽标识；显示名称与标识各有用途 |
| `b.add_input(socket_type, name, identifier)` | 声明对应状态输入，返回其声明对象引用 |
| `.socket_name_ptr(&tree->id, ... &item, "name")` | 将插槽显示名称关联到项目的 RNA 名称属性 |
| `.structure_type(StructureType::Dynamic)` | 标记动态结构类型，交由结构推导机制处理 |
| `.compositor_realization_mode(...None)` | 指定合成器输入 realization 模式；它不负责几何节点轮间传值 |
| `b.add_output(socket_type, name, identifier)` | 声明同一状态项对应的输出 |
| `.align_with_previous()` | 将输出与前一输入在布局上对齐 |
| `.propagate_all({input_decl.index()})` | 声明从对应输入传播的关系，供声明相关分析使用；不是执行时直接拷贝状态 |
| `.inferred_structure_type({input_decl.index()})` | 输出结构类型从对应输入推断 |
| `.structure_type(StructureType::Dynamic)` | 输出也使用动态结构类型 |
| `add_input<decl::Extend>(..., "__extend__"_ustr)` | 声明用于扩展状态项的特殊输入插槽 |
| `.custom_draw(...draw_extend_socket_fn<RepeatItemsAccessor>())` | 使用状态项框架提供的扩展插槽绘制函数 |
| `add_output<decl::Extend>(...)` | 声明特殊扩展输出插槽 |
| 扩展输出的 `.structure_type`、`.align_with_previous` | 设置结构类型并与扩展输入对齐 |

### Repeat Output

Output 的声明与上述动态项目循环基本一致，按源码顺序对应如下：

1. `use_custom_socket_order()`、`allow_any_socket_order()` 设置插槽排列规则。
2. `tree_or_null()`、`node_or_null()` 取得树和节点。
3. `if (node)` 进入实例声明；`node_storage(*node)` 直接取得自己的状态项目设置。
4. `IndexRange(storage.items_num)` 遍历自己的项目数组，不需要通过 `output_node_id` 查另一个节点。
5. `item`、`socket_type`、`name`、`identifier` 分别取得项目、类型、显示名、稳定标识。
6. `add_input` 及其 `socket_name_ptr`、`structure_type`、`compositor_realization_mode` 配置输入，含义与上表一致。
7. `add_output` 及其 `align_with_previous`、`propagate_all`、`inferred_structure_type`、`structure_type` 配置匹配输出，含义与上表一致。
8. 最后声明输入输出两侧的 Extend 插槽，并设置动态结构、绘制函数与对齐关系。

Output 这里没有再声明 Iterations / Iteration。次数在 Repeat Input，状态项目列表在 Repeat Output；Input 借助配对 ID 读取 Output 的项目列表，以保持两端状态项一致。
