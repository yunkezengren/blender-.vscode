# 02 · 循环展开逐行阅读

源码：[geometry_nodes_repeat_zone.cc](../../source/blender/nodes/intern/geometry_nodes_repeat_zone.cc)，`initialize_execution_graph()`，195—409 行。按同一条 C++ 语句合并换行解释，纯括号和注释不单独讲。

例子保持不变：只有一个整数状态项 `x`，初值 0，每轮加 1，迭代 3 次。

## 先认识图上的对象

| 类型 | 作用 |
| --- | --- |
| `lf::Graph` | 承载函数节点、图边界插槽与连线 |
| `lf::FunctionNode` | 图中一次函数调用的位置；三轮是三个节点，引用同一个体函数定义 |
| `lf::GraphInputSocket` | 整张图的输入边界，在图内部可作为连线的来源 |
| `lf::GraphOutputSocket` | 整张图的输出边界，在图内部作为连线的目的地 |
| `lf::Input`、`lf::Output` | 函数的接口描述，包含类型等信息；不是当前计算出的值 |
| `SocketValueVariant` | 节点插槽值的载体；这里装 Iterations 和 Iteration 的整数 |
| `IndexRange(n)` | 表示从 0 开始的 n 个索引；`IndexRange(3)` 遍历 0、1、2 |
| `Span` | 不拥有元素的连续序列视图；切片不等于复制元素 |
| `Vector` / `Array` | 动态序列 / 数组，保存指针或数值等元素 |

图类型见 [FN_lazy_function_graph.hh](../../source/blender/functions/FN_lazy_function_graph.hh)。`ZoneFunctionIndices` 定义见 [NOD_geometry_nodes_lazy_function.hh](../../source/blender/nodes/NOD_geometry_nodes_lazy_function.hh)。

`indices.inputs.main[i]` 不是状态值，而是“第 i 个主输入在完整 LF 接口中的编号”。不同函数的接口布局各自查自己的 `indices`。

## 229—253：创建接口与各轮调用节点

```cpp
const int main_inputs_offset = 1;
const int body_inputs_offset = 1;
```

两个 1 含义不同：包装层主输入的第一项是 Iterations，体函数主输入的第一项是 Iteration。状态项 `x` 在两边都要跳过第一项，但不能把 Iterations 与 Iteration 当作同一个数据。

| 源码语句 / 标识 | 逐句解释 |
| --- | --- |
| `lf::Graph &lf_graph = eval_storage.graph` | 引用存储中的图，后续直接修改它 |
| `lf_inputs` / `lf_outputs` | 临时保存图边界插槽指针，方便按接口编号查找 |
| `for (... inputs_.index_range())` | 遍历 Repeat 包装函数的所有输入，包括辅助信号 |
| `const lf::Input &input = inputs_[i]` | 取得第 i 项接口描述 |
| `lf_graph.add_input(*input.type, this->input_name(i))` | 按类型和名称创建图输入边界 |
| `lf_inputs.append(&...)` | 记录创建结果的地址；指向图持有的对象 |
| 输出侧对应的循环 | 用 `add_output` 同样创建并记录所有输出边界 |
| `VectorSet<...> &lf_body_nodes = ...` | 引用存储中的有序节点集合 |
| `for ([[maybe_unused]] const int i : IndexRange(iterations))` | 按次数建节点；i 未用于循环体，属性避免未使用变量警告 |
| `lf_graph.add_function(*body_fn_.function)` | 新增一个体函数调用节点；不是复制整份函数实现 |
| `lf_body_nodes.add_new(&lf_node)` | 按轮次顺序保存节点指针 |

此时三轮节点已经存在，但状态传递连线还没完成。

## 255—294：各轮的常量、跨界输入与引用集合

| 源码语句 / 标识 | 逐句解释 |
| --- | --- |
| `lf_border_link_usage_or_nodes(num_border_links)` | 每条跨界输入准备一个 OR 节点指针位置 |
| `or_function.emplace(iterations)` | 原地构造有 N 个输入的 OR 函数 |

| `index_values[i].emplace<int>(i)` | 第 i 项载体装整数 i，得到 0、1、2 |
| `static_unused_index{-1}` | 未使用 Iteration 时提供占位值；static 保证默认值指针长期有效 |
| 遍历 `lf_body_nodes.index_range()` | 按轮次配置每个体节点 |
| `lf_node = *lf_body_nodes[iter_i]` | 取得当前轮节点 |
| 条件表达式 `use_index_values ? ... : ...` | 选择真实索引值地址或占位值地址 |
| `input(...main[0]).set_default_value(index_value)` | 给当前轮的 Iteration 主输入设置默认值指针 |
| 跨界循环的第一个 `add_link` | 同一个外部跨界输入接到每轮体函数；它不经上一轮更新 |
| 跨界循环的第二个 `add_link` | 每轮对该跨界输入的需求信号，接到对应 OR 的第 iter_i 个输入 |
| `reference_sets.items()` | 遍历体函数需要的引用集合接口，键是引用集合标识 |
| `lookup(item.key)` | 在包装函数的引用集合接口中找到同一个标识 |
| 对引用集合的 `add_link` | 将包装层引用集合输入接到当前体节点的相应输入，支持引用依赖传播 |

跨界需求的例子：三轮需求是 `false, true, false`，OR 输出为 true，意味着外部输入需要求值。引用集合的详细语义可查 [旧文第 07 篇](../重复区域-codex/03-值寿命与观察机制/07-状态值Field引用与内存寿命.md)，无需在这里展开字段系统。

## 296—317：前一轮输出接后一轮输入

```cpp
static bool static_true = true;
for (const int iter_i : lf_body_nodes.index_range().drop_back(1)) {
  lf::FunctionNode &lf_node = *lf_body_nodes[iter_i];
  lf::FunctionNode &lf_next_node = *lf_body_nodes[iter_i + 1];
  for (const int i : IndexRange(num_repeat_items)) {
    lf_graph.add_link(
        lf_node.output(body_fn_.indices.outputs.main[i]),
        lf_next_node.input(body_fn_.indices.inputs.main[i + body_inputs_offset]));
    // 源码中间还有未启用的需求回连 TODO。
    lf_node.input(body_fn_.indices.inputs.output_usages[i]).set_default_value(&static_true);
  }
}
```

按顺序解释：`static_true` 提供稳定的 true 地址；`drop_back(1)` 排除最后一轮，避免 `iter_i + 1` 越界；两个引用分别指当前轮和下一轮；内层循环逐个处理状态项；`add_link` 将当前轮的第 i 个状态输出接到下一轮状态输入，输入需跳过 Iteration；最后将当前轮的该输出标为需要。

源码中被注释的 `add_link` 不执行。TODO 表明作者希望未来恢复更精确的反向需求传播；当前做法把非最后轮的状态输出需求设为 true。不能描述成当前已经完整实现跨轮需求裁剪。

之后的 border usage 循环：把每个 OR 的输出接到整张图对应的跨界输入需求输出。

## 319—359：接入初值、取出结果、处理零轮

| 源码语句 / 标识 | 逐句解释 |
| --- | --- |
| `if (iterations > 0)` | 有体节点时才允许取首尾节点 |
| `lf_first_body_node = *lf_body_nodes[0]` | 找第一轮 |
| 首个 `add_link` | 包装层状态输入 → 第一轮状态输入，两边分别跳过 Iterations / Iteration |
| 第二个 `add_link` | 第一轮状态输入的使用信号 → 包装层初值输入的使用信号 |
| `lf_body_nodes.as_span().last()` | 找最后一轮 |
| 最后一轮的第一个 `add_link` | 最后一轮状态输出 → 包装层最终状态输出 |
| 最后一轮的第二个 `add_link` | 外层对最终输出的需求 → 最后一轮对该输出的需求 |
| `else` | N=0，没有任何体节点 |
| 零轮第一个 `add_link` | 包装层初值直接接最终输出 |
| 零轮第二个 `add_link` | 最终输出的需求直接传给对应初值输入需求 |
| `static_false` | 稳定的 false 默认值 |
| 跨界需求输出 `set_default_value(&static_false)` | 零轮不执行体，因此体的跨界输入都不需要 |
| `input_usages[0]` 默认 true | 图中 Iterations 使用信号始终为 true；对外实际由 execute_impl 写入 |

到这里，例子中的数据主线完整：`0 → body0 → body1 → body2 → 3`。usage 连线传播“需要什么”，main 连线传递计算数据，两者方向可能相反。

## 361—389：整理索引与参数映射

| 源码语句 / 标识 | 逐句解释 |
| --- | --- |
| `lf_graph.update_node_indices()` | 更新图节点编号，供执行器使用 |
| 注释掉的 `std::cout` | 调试用 DOT 输出，当前不执行 |

## 两个辅助类为何必要

`RepeatBodyNodeExecuteWrapper::execute_node()`：先在体节点集合中查轮次；查不到时普通执行。查到时创建 `RepeatZoneComputeContext`，由父上下文、Output 节点和轮次确定调用身份；复制用户环境后替换计算上下文，重新决定详细日志开关，创建该轮局部环境，最后执行体函数。栈上的上下文覆盖这次同步调用，函数返回后销毁。

`RepeatZoneSideEffectProvider::get_nodes_with_side_effects()`：没有副作用集合就返回空；否则用父计算上下文 hash 和 Output 节点 ID 查需要执行的轮次；过滤越界轮次后返回体节点列表。即便普通最终输出不要求某轮，也可能因为 Viewer 等副作用需求需要执行它。

这两类位于同文件开头。需要逐段追观察机制时，可接着读 [旧文第 08 篇](../重复区域-codex/03-值寿命与观察机制/08-轮次上下文日志Viewer与副作用.md)。
