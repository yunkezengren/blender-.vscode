# 02 · 逐行读 `Instance::update_text_depth()`

![逐行分支](./图片/03-分支流程.svg)

对照 `source/blender/draw/engines/overlay/overlay_instance.cc:1017–1053`。本函数的输入都来自 `Instance` 的成员，返回类型 `void`，不直接返回深度图。它的副作用是管理 `text_depth_cache_`，并设置 `state.dt->depths`。

## 1017–1026：短路与清理

```cpp
void Instance::update_text_depth()
{
  if (!state.show_text || !state.is_space_v3d() ||
      !DRW_text_cache_needs_depth_test(state.dt))
  {
    DRW_text_cache_depth_set(state.dt, nullptr);
    if (text_depth_cache_ != nullptr) {
      ED_view3d_depths_free(text_depth_cache_);
      text_depth_cache_ = nullptr;
    }
    return;
  }
```

`||` 为逻辑或，并采用从左到右短路求值。`show_text` 为假，后两个检查可以不执行；如果是文字可见但非 3D 视图，则不扫描文字数组。第三个条件仅在前两个检查均未使表达式成立时扫描 `state.dt->cache_strings`。这保证不需要遮挡测试时不触发整张 GPU 深度回读。

`DRW_text_cache_depth_set()` 的实现就是 `dt->depths = depths`，位于 `draw_manager_text.cc:337–340`。传入 `nullptr` 清除的是**借用指针**。之后调用 `ED_view3d_depths_free()`；这个函数在 `view3d_draw.cc:2551–2557` 先释放 `depths->depths`，再释放 `depths`。先解除借用再释放对象，是为了不让文字系统保留指向已释放内存的地址。`text_depth_cache_ = nullptr` 则让所有者成员也不保留悬空指针。

`return` 结束函数；后续访问视口、回读、赋指针均不会执行。

## 1027–1032：找 GPU 深度纹理

```cpp
  GPUViewport *viewport = WM_draw_region_get_viewport(
      const_cast<ARegion *>(state.region));
  gpu::Texture *depth_tx = GPU_viewport_depth_texture(viewport);
  const int width = GPU_texture_width(depth_tx);
  const int height = GPU_texture_height(depth_tx);
```

`state.region` 来源于 `Instance::init()` 的 `ctx->region`。它的声明是 `const ARegion *`。`WM_draw_region_get_viewport` 接口接受 `ARegion *`，所以这里用 `const_cast` 去掉指针类型中的 `const`；它不复制区域，不产生新视口，也不能单凭这行断言被调用者会修改区域。

`WM_draw_region_get_viewport()` 查 `region->runtime->draw_buffer->viewport`，实现见 `wm_draw.cc:954–962`。`GPU_viewport_depth_texture()` 返回该视口结构体中的 `depth_tx` 成员，见 `gpu_viewport.cc:605–608`。`GPU_texture_width/height()` 分别调用纹理对象的 `width_get/height_get`，见 `gpu_texture.cc:773–780`。宽高以**像素**为单位；取得宽高本身不等于回读所有像素。

## 1033–1038：尺寸改变时丢弃旧 CPU 数组

```cpp
  if (text_depth_cache_ != nullptr &&
      (text_depth_cache_->w != width || text_depth_cache_->h != height))
  {
    ED_view3d_depths_free(text_depth_cache_);
    text_depth_cache_ = nullptr;
  }
```

`&&` 要求旧缓存存在并且尺寸不匹配。`||` 表示宽或高任何一个变化就要重建。`ViewDepths::depths` 是逐行排布的像素数组，访问一个像素的表达式是 `depths[y * w + x]`。即使像素总数恰好不变，只要 `w` 改变，每行起点就不同。旧数组不能安全地作为新纹理的目标缓冲区。

这里并未判断相机是否变化。相机变化但尺寸相同，会进入下面的 `else`，覆写数组中的全部深度值。

## 1039–1047：第一次分配并回读

```cpp
  if (text_depth_cache_ == nullptr) {
    text_depth_cache_ = MEM_new_zeroed<ViewDepths>("ViewDepths");
    text_depth_cache_->w = width;
    text_depth_cache_->h = height;
    text_depth_cache_->depths = static_cast<float *>(
        GPU_texture_read(depth_tx, GPU_DATA_FLOAT, 0));
    text_depth_cache_->depth_range[0] = 0.0;
    text_depth_cache_->depth_range[1] = 1.0;
  }
```

`MEM_new_zeroed<ViewDepths>` 在 CPU 内存里创建并清零一个结构体；字符串是内存分配标签。`w/h` 存纹理尺寸。三参数 `GPU_texture_read` 先计算读回所需字节数，再分配**另一块** CPU 内存，读取纹理并返回它的地址；`static_cast<float *>` 把 `void *` 转成与 `ViewDepths::depths` 匹配的指针。`GPU_DATA_FLOAT` 是主机结果数据格式，`0` 是基础 mip 层。

`depth_range` 设置 `[0,1]`。这里的数值是窗口深度，不是米；透视情况下不能把 `0.5` 理解为视距恰好在近远裁剪面之间的中点。

## 1048–1051：尺寸相同，复用内存但读取新数据

```cpp
  else {
    GPU_texture_read(depth_tx, GPU_DATA_FLOAT, 0, text_depth_cache_->depths);
  }
```

四参数版本接受调用者已分配的 `dst`。它不另建返回数组，而是把**本帧**深度写到原来的 CPU 缓冲区。它在 `gpu_texture.cc:554–562` 验证纹理允许 `HOST_READ`，然后调用 GPU 后端纹理对象的虚函数 `read()`。

“复用缓存”的准确含义是复用 `ViewDepths` 和像素数组的**分配**；数组**内容每个需要测试的绘制轮次都刷新**。否则相机 B 的文字锚点会与相机 A 的深度比较，产生旧帧误判。

## 1052–1053：把读回结果交给文字系统

```cpp
  DRW_text_cache_depth_set(state.dt, text_depth_cache_);
}
```

这再次是指针赋值，没有深度数组复制。`DRWTextStore` 中的字段类型是 `const ViewDepths *`：文字代码可以读深度，却不拥有或修改它。`Instance` 必须让这个对象至少活到后续 `DRW_text_cache_draw()` 完成。

这也是本函数的主要产出：不是返回值，而是 `state.dt->depths` 现在指向一张当前帧、CPU 可读的场景深度图。
