02原理、状态与设计取舍

一个函数不够表达整张计算图

表达式 (A+B)*C 包含多个计算步骤以及中间值。Procedure 提供把批量函数组合成执行过程的机制。它与后面的 LazyFunction 图有不同目标，不能因为都含有图结构，就把两套系统的调用语义混为一谈。

先从 FN_multi_function_procedure.hh 的变量与指令表示入手，再查看 executor 如何管理变量状态。历史 Field 引入提交明确说明使用 multi-function procedure 进行求值，这为理解其实际用途提供了上下文。

最后一次使用决定回收机会

中间值 T 被两个下游共享，计算第一个下游后不能立刻释放它。若已知最后一个使用完成，就可以销毁或复用相应存储。活跃区间分析把表达式依赖转成内存寿命，这与容器模块中的存活对象模型一致，只是规模变成了一组变量。

类型、元素数量、对齐和初始化状态限制哪些缓冲区可以复用。不能因为两个临时值字节数相同，就随意把一个对象数组解释成另一类型。复用存储时仍要完成必要析构和构造。

优化应保留可观察行为

常量传播、死输出省略和共享子表达式可以减少工作，但需要明确函数是否纯、是否有副作用，以及结果比较的语义。练习版本可先限定纯算术函数，避免在尚未定义效果模型时做激进优化。

把执行日志写成变量产生、使用和销毁的序列。若能从日志重建每个临时值的生命周期，你就开始具备理解复杂执行器的工具。

inline const MultiFunction &Procedure::construct_function(Args &&...args)
{
  destruct_ptr<T> fn = allocator_.construct<T>(std::forward<Args>(args)...);
  const MultiFunction &fn_ref = *fn;
  owned_functions_.append(std::move(fn));
  return fn_ref;
}

用具体输入推演状态

过程 P 构造函数 F，再让两个 CallInstruction 都引用 F；两个调用不需要复制 F，但 P 必须活到整个执行结束。若把 F 只放在构建辅助函数的局部栈上，返回后指令中保存的引用会悬空。

调用关系与设计判断

继续查看 Procedure 的成员声明顺序与执行器对 Procedure 的借用方式，再追踪 DestructInstruction 如何结束运行期变量的寿命。函数对象生命周期和每次执行的临时值生命周期是两套责任，不能合成一个模糊的“过程内存”。

Procedure 的完整验证入口：控制流与值状态分层检查

Geometry Nodes: fields and anonymous attributes

展开提交原文、变更规模与阅读命令
This implements the initial core framework for fields and anonymous
attributes (also see T91274).

The new functionality is hidden behind the "Geometry Nodes Fields"
feature flag. When enabled in the user preferences, the following
new nodes become available: `Position`, `Index`, `Normal`,
`Set Position` and `Attribute Capture`.

Socket inspection has not been updated to work with fields yet.

Besides these changes at the user level, this patch contains the
ground work for:
* building and evaluating fields at run-time (`FN_fields.hh`) and
* creating and accessing anonymous attributes on geometry
  (`BKE_anonymous_attribute.h`).

For evaluating fields we use a new so called multi-function procedure
(`FN_multi_function_procedure.hh`). It allows composing multi-functions
in arbitrary ways and supports efficient evaluation as is required by
fields. See `FN_multi_function_procedure.hh` for more details on how
this evaluation mechanism can be used.

A new `AttributeIDRef` has been added which allows handling named
and anonymous attributes in the same way in many places.

Hans and I worked on this patch together.
