02原理、状态与设计取舍

数组是可索引的语义

一个逻辑长度为 N 的常量数组，只需要保存一个值和长度。另一种数组可能借用 Span，还有一种在访问索引时计算值。它们都支持按索引取值，但其存储与计算成本不同。VArray 提供统一外观，让属性和函数系统不必为每种表示暴露完全不同的高层接口。

统一接口不应抹去所有信息。算法若能识别单值表示，可以把常量运算移出循环；识别连续 Span，则可以使用适合编译器优化的普通循环。通用性与快速路径通过有意设计的查询机制共存。

外层值对象与内部多态

d4c868da9f9 将外层 VArray 设计为更方便传递的固定大小值对象，内部再管理 VArrayImpl。它解决了过去频繁通过 unique_ptr 传递以及小对象分配的问题。当前实现已经继续演化，读历史提交是为了理解这次职责划分。

不同实现的所有权可能不同：引用 Span 的实现不自动拥有原数组，持有容器的实现可能拥有数据。复制一个 VArray 后数据是否保活，必须看具体构造途径，不能仅凭外层看起来像值类型就判断。

物化是一项显式成本

把虚拟数组变成实际连续缓冲区称为物化。它可能让多次访问变便宜，也可能对本来只读少数元素的情况产生大量不必要工作。决定是否物化时要考虑后续访问次数、选择密度和每个元素的计算成本。

在源码中追踪 materialize 或 VArraySpan 一类辅助接口，说明它是借用已有连续数组，还是为当前表示分配临时缓冲区。性能判断必须追到实际存储路径。

Geometry Nodes: refactor virtual array system

重点读外层值语义、内部实现与小对象分配之间的关系。

展开提交原文、变更规模与阅读命令
Goals of this refactor:
* Simplify creating virtual arrays.
* Simplify passing virtual arrays around.
* Simplify converting between typed and generic virtual arrays.
* Reduce memory allocations.

As a quick reminder, a virtual arrays is a data structure that behaves like an
array (i.e. it can be accessed using an index). However, it may not actually
be stored as array internally. The two most important implementations
of virtual arrays are those that correspond to an actual plain array and those
that have the same value for every index. However, many more
implementations exist for various reasons (interfacing with legacy attributes,
unified iterator over all points in multiple splines, ...).

With this refactor the core types (`VArray`, `GVArray`, `VMutableArray` and
`GVMutableArray`) can be used like "normal values". They typically live
on the stack. Before, they were usually inside a `std::unique_ptr`. This makes
passing them around much easier. Creation of new virtual arrays is also
much simpler now due to some constructors. Memory allocations are
reduced by making use of small object optimization inside the core types.

Previously, `VArray` was a class with virtual methods that had to be overridden
to change the behavior of a the virtual array. Now,`VArray` has a fixed size
and has no virtual methods. Instead it contains a `VArrayImpl` that is
similar to the old `VArray`. `VArrayImpl` should rarely ever be used directly,
unless a new virtual array implementation is added.

To support the small object optimization for many `VArrayImpl` classes,
a new `blender::Any` type is added. It is similar to `std::any` with two
additional features. It has an adjustable inline buffer size and alignment.
The inline buffer size of `std::any` can't be relied on and is usually too
small for our use case here. Furthermore, `blender::Any` can store
additional user-defined type information without increasing the
stack size.
