02原理、状态与设计取舍

只有 void 指针远远不够

节点插槽的类型可能在运行时才知道。执行器拿到地址之后，还必须知道需要多少存储、怎样对齐、如何构造、复制、移动和析构。CPPType 将这些操作及性质收集在一个描述对象中，使不依赖具体 T 的代码仍可正确管理其对象。

模板依然参与其中：编译期针对具体 T 生成正确操作，再把这些操作注册到运行时表中。类型擦除并没有让类型消失，而是把某些静态知识转换成动态数据与函数入口。

已初始化与未初始化目标不同

向已经存在的对象复制赋值，与在原始存储中复制构造，具有不同前提。一个通用函数若把二者混淆，可能对尚未构造的字符串调用赋值，或在原有对象上覆盖构造而不释放旧资源。阅读 CPPType 时，把所有操作按目标状态分组。

类似地，平凡类型可以有快捷处理，但对非平凡类型必须保留对象语义。记录哪些性质来自类型 traits，哪些来自显式注册策略，避免把当前 int 的行为推广到所有类型。

从单个值走向批量数据

节点系统常常需要处理一组同类型元素。把类型描述与连续存储结合，就得到通用数组的基础；再加上索引选择，便能只操作部分元素。0a907657d4d 同时引入运行时类型和 IndexMask，说明这些组件来自同一个批量执行需求。

你可以先写只有三种类型的描述表，再研究 Blender 如何扩展。第一目标是所有权与对象状态正确，之后才考虑注册速度、代码体积和快捷路径。

inline void *ResourceScope::allocate_owned(const CPPType &type)
{
  void *buffer = allocator_.allocate(type);
  if (!type.is_trivially_destructible) {
    this->add_destruct_call([&type, buffer]() { type.destruct(buffer); });
  }
  return buffer;
}

用具体输入推演状态

CPPType::get<int>() 与 CPPType::get<std::string>() 可以保存相同签名的回调指针，但分别调用对应模板实例。调用者用 int 的 CPPType 处理 string 存储，即使都是 void*，仍然违反契约。

调用关系与设计判断

把静态知识生成、运行期保存、运行期调用三个阶段分开。类型擦除只隐藏静态类型，不允许丢失实际类型身份。回调数量、对象大小与对齐、是否支持操作的标记必须一起保持一致。

对 int，new(ptr) int 与 new(ptr) int() 的初始化结果不同；前者不能直接当成已知零读取，后者是零。对有用户提供默认构造函数的类型，值初始化效果还要看它的实际构造器。

调用关系与设计判断

为运行期接口分别命名 default_construct 与 value_initialize 是有用的。上层究竟需要未写入标量、默认类对象还是已知零值，应由算法需求决定，不应为了统一接口把两者混成一个 init。

运行期析构：恢复实际类型后结束生命周期

完整回调仅结束对象生命周期，不释放原始存储。它与 ResourceScope、LinearAllocator 的分工正好对应。

用具体输入推演状态

线性块中的一个 string 析构以后，字符串内部资源被释放，块地址本身还可以等待整体释放或再次 placement-new。重复调用此回调会对已结束生命周期的对象重复析构，是调用协议错误。

调用关系与设计判断

在调试型练习实现里加活对象状态表，验证构造恰一次、析构恰一次。真实基础库往往因性能原因把这些状态责任交给上层；读懂这个取舍，比为每个回调增加同样的检查更重要。

Functions: Run-time type system and index mask

历史 CPPType 位于 functions；当前移到 blenlib。研究需求，不要只机械匹配旧路径。

展开提交原文、变更规模与阅读命令
This adds a new `CPPType` that encapsulates information about how to handle
instances of a specific data type. This is necessary for the function evaluation
system, which will be used to evaluate most of the particle node trees.

Furthermore, this adds an `IndexMask` class which offers a surprisingly useful
abstraction over an array containing unsigned integers. It makes two assumptions
about the underlying integer array:
* The integers are in ascending order.
* There are no duplicates.

`IndexMask` will be used to "select" certain particles that will be
processed in a data-oriented way. Sometimes, operations don't have to
be applied to all particles, but only some, those that are in the indexed by
the `IndexMask`. The two limitations imposed by an `IndexMask` allow for
better performance.

06自测：先回答，再展开

有类型描述就能随意转换类型吗？

不能。描述对象操作的是对应具体类型；类型转换需要单独定义的语义。

模板与运行时类型系统冲突吗？

不冲突，模板常用来生成运行时表中的类型专用操作。
