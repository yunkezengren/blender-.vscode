02原理、状态与设计取舍

从消费者向下追踪

Set Position 是理解 Field 的好入口：它需要在具体几何上解释位置、偏移和选择。阅读时先列出节点拿到哪些字段、在哪个域使用它们、怎样获得可写位置。随后跟进 FieldEvaluator，而不是从整个 field_evaluation.cc 第一行开始。

FieldEvaluator 保存 context 引用、mask 引用或作用域内构造的 mask、待求值 Field 和结果数组。构造函数的指针形式特别强调传入 mask 的生命周期要求；这些小接口细节连接着整个结果管理。

选择也可以需要求值

set_selection 接受布尔 Field，先求出选择，再决定其他 Field 需要处理哪些元素。它与构造时 mask 的关系是交集。未选择的元素不应被当作已经计算的有效输出随意读取。

如果同时需要多个共享子表达式的结果，把它们放入同一次合适的求值组织中，可以减少重复工作。是否真正共享以及如何调度，应沿当前实现验证，而不是仅凭两段节点图看起来相似判断。

写目标与结果寿命

add_with_destination 允许将结果写入调用者提供的目标表示。目标大小、类型和可写性需要满足契约；普通 add 则可能通过求值器管理结果表示及临时资源。调用者持有结果多久，取决于结果自身拥有关系与 evaluator 的作用域。

当前析构中的断言能捕捉忘记调用 evaluate 的使用错误。学习时把构造、登记、执行、取结果、销毁当成一个完整协议，避免只记住单个方法名称。

void FieldEvaluator::evaluate()
{
  BLI_assert_msg(!is_evaluated_, "Cannot evaluate fields twice.");

  selection_mask_ = selection_field_ ?
                        evaluate_selection(*selection_field_, context_, mask_, scope_) :
                        mask_;

  Vector<GFieldRef> fields;
  fields.reserve(fields_to_evaluate_.size());
  static constexpr bool true_value = true;
  for (const int i : fields_to_evaluate_.index_range()) {
    const GField &field = fields_to_evaluate_[i];
    if (field == selection_field_) {
      /* Avoid evaluating the selection field again. */
      fields.append(GFieldRef::from_constant(CPPType::get<bool>(), &true_value));
    }
    else {
      fields.append(field);
    }
  }
  evaluated_varrays_ = evaluate_fields(scope_, fields, selection_mask_, context_, dst_varrays_);
  BLI_assert(fields_to_evaluate_.size() == evaluated_varrays_.size());
  for (const int i : fields_to_evaluate_.index_range()) {
    OutputPointerInfo &info = output_pointer_infos_[i];
    if (info.dst != nullptr) {
      info.set(info.dst, evaluated_varrays_[i], scope_);
    }
  }
  is_evaluated_ = true;
}

Geometry Nodes: fields and anonymous attributes

观察 Set Position 作为首批 Field 消费节点如何连接用户功能与底层框架。

展开提交原文、变更规模与阅读命令
This implements the initial core framework for fields and anonymous
attributes (also see T91274).

The new functionality is hidden behind the "Geometry Nodes Fields"
feature flag. When enabled in the user preferences, the following
new nodes become available: `Position`, `Index`, `Normal`,
`Set Position` and `Attribute Capture`.

Socket inspection has not been updated to work with fields yet.

Besides these changes at the user level, this patch contains the
ground work for:
* building and evaluating fields at run-time (`FN_fields.hh`) and
* creating and accessing anonymous attributes on geometry
  (`BKE_anonymous_attribute.h`).

For evaluating fields we use a new so called multi-function procedure
(`FN_multi_function_procedure.hh`). It allows composing multi-functions
in arbitrary ways and supports efficient evaluation as is required by
fields. See `FN_multi_function_procedure.hh` for more details on how
this evaluation mechanism can be used.

A new `AttributeIDRef` has been added which allows handling named
and anonymous attributes in the same way in many places.

Hans and I worked on this patch together.
