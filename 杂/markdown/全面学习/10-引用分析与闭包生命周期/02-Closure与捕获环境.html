02原理、状态与设计取舍

函数代码与环境组合成可执行值

一个闭包可以把计算定义和捕获环境一起传递。比如创建时捕获 scale=2，执行时传入 x，得到 2*x。这里 x 是调用参数，scale 属于环境。节点系统中的闭包也需要明确哪些输入由调用者提供，哪些值由创建时捕获。

Bundle 把多个有名字的插槽值组合成一个值，并可以嵌套。它让函数和数据的传递更灵活，也让类型、生命周期和引用传播必须处理嵌套情况。

捕获不自动等于复制所有数据

实现可以捕获值、共享所有者或借用引用。不同选择决定结果是否独立于原环境，以及复制代价。教学练习先按值捕获简单数值；引入几何和 Field 时，再考虑共享、只读约束与延迟求值。

8ec9c62d3ea 的初始实现说明中明确记录了一些惰性限制：某些组合值和捕获值即使最终不需要也会先求值。把这些看成该历史版本的限制，不能未经检查推断今天所有路径仍然如此。

签名与调用边界

闭包输入输出需要有可检查的签名，调用者必须匹配类型和数量。错误可以在编辑、构建或执行阶段被发现，设计应决定哪一层掌握足够信息。动态组合并不意味着放弃接口契约。

Geometry Nodes: add Closures and Bundles behind experimental feature flag

分别阅读已实现功能、实验状态和当时明确记录的限制。

展开提交原文、变更规模与阅读命令
This implements bundles and closures which are described in more detail in this
blog post: https://code.blender.org/2024/11/geometry-nodes-workshop-october-2024/

tl;dr:
* Bundles are containers that allow storing multiple socket values in a single
  value. Each value in the bundle is identified by a name. Bundles can be
  nested.
* Closures are functions that are created with the Closure Zone and can be
  evaluated with the Evaluate Closure node.

To use the patch, the `Bundle and Closure Nodes` experimental feature has to be
enabled. This is necessary, because these features are not fully done yet and
still need iterations to improve the workflow before they can be officially
released. These iterations are easier to do in `main` than in a separate branch
though. That's because this patch is quite large and somewhat prone to merge
conflicts. Also other work we want to do, depends on this.

This adds the following new nodes:
* Combine Bundle: can pack multiple values into one.
* Separate Bundle: extracts values from a bundle.
* Closure Zone: outputs a closure zone for use in the `Evaluate Closure` node.
* Evaluate Closure: evaluates the passed in closure.

Things that will be added soon after this lands:
* Fields in bundles and closures. The way this is done changes with #134811, so
  I rather implement this once both are in `main`.
* UI features for keeping sockets in sync (right now there are warnings only).

One bigger issue is the limited support for lazyness. For example, all inputs of
a Combine Bundle node will be evaluated, even if they are not all needed. The
same is true for all captured values of a closure. This is a deeper limitation
that needs to be resolved at some point. This will likely be done after an
initial version of this patch is done.
