02原理、状态与设计取舍

哈希表首先依赖等价关系

哈希值用于缩小查找范围，相等比较用于确认是否为同一个键。因此相等的键必须得到相同哈希；不同键可以发生碰撞。若前一条件失效，表可能把逻辑上相同的键放进不同探测路径，查找和去重便失去可靠性。这个规则属于哈希与比较的联合契约，不能分别设计。

自定义键中哪些字段参与相等，就必须相应考虑哪些字段参与哈希。参与哈希的状态在键处于表中时也不能随意变化，否则其存储位置与当前哈希不再一致。

位表示和数值语义不总是一致

IEEE 浮点中的正零与负零比较相等，却有不同位表示。直接 bit_cast 后哈希会破坏契约。Jacques 的修复在核心哈希层处理这个特殊情况，并让向量、矩阵等组合类型的哈希从正确的基础实现派生。修复范围体现了基础库设计的传播效应。

NaN 又是另一类问题：它通常不等于自身。不能因为解决了正负零，就断言任意浮点值都能自然成为满足全部期望的键。应用需要说明 NaN 的允许性、归一化方式或专用相等语义。

组合类型需要组合证明

对二维向量的哈希，不妨先写出相等条件：两个分量分别相等。然后证明每个分量哈希满足契约，再分析组合函数。组合函数不需要无碰撞，却应该避免对常见输入产生严重聚集。测试需要同时检查正确性和分布，不要把二者混为一个指标。

源码阅读时从 BLI_hash.hh 的标量处理走向组合类型。记录哪些调用者自行处理位表示，哪些统一使用基础哈希；后者更容易获得集中修复带来的收益。

浮点哈希：在位表示之前处理相等关系

这是 DefaultHash<float> 的完整调用运算符。读它时先写下 +0.0f == -0.0f 为真，再问这两个数的位表示是否一致。哈希函数必须服务于键的相等语义，不能只选择一个看起来便宜的编码。

用具体输入推演状态

正零位表示通常为 0x00000000，负零为 0x80000000；直接使用表示会分到不同探测序列。当前函数先把两者归一为 0。普通数如 1.0f 进入 bit_cast 路径。NaN 的相等关系另有问题，不能把修复零推广成解决所有浮点键语义。

调用关系与设计判断

对照 79ef927ea93，测试应把 +0 作为插入键、-0 作为查询键，再交换两者；只测试两个 hash 输出相等还不能证明容器整体查找正常。继续阅读 Map 查找中的 Equality 比较，明确哈希和相等各负责什么。

HISTORY 79ef927ea93 Jacques Lucke · 2026-06-04

Fix: BLI: ensure that +0.0 and -0.0 hash to the same value

把正负零的失败例子写出来，再观察修复为什么放在核心哈希函数。

展开提交原文、变更规模与阅读命令
Floating point representation has the special case that `+0.0` and `-0.0` exist.
They compare equal but do not have the same bit representation. This implies
that a `bit_cast` does not work to get a hash from the number. It breaks the one
rule for these hashes: if two values compare equal, they have to have the same
hash.

Floating point values have other special values but they don't need the same
treatment:
* `+inf` and `-inf` have unique representations.
* `nan` has many different representation, all of which never compare equal to
  each other, even if the bit pattern is the same.

The fix is to add this special case in the core hashing functions and to make
sure that hashing functions of vectors, matrices, etc. derive from that.

Unique hashing is updated to properly handle this too.

This also fixes #158701.

06自测：先回答，再展开

两个不同值哈希相同就是错误吗？

不是，碰撞是允许的，必须通过相等比较区分；大量碰撞会影响性能。

正负零为什么不能直接按位哈希？

它们数值比较相等，按位哈希可能得到不同值，违反相等必同哈希的要求。
