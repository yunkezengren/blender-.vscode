02原理、状态与设计取舍

条件决定依赖

普通急切执行可能先把 A 与 B 都算出来，再计算 Switch(condition,A,B)。若 B 极其昂贵而条件始终选择 A，这会浪费大量工作。惰性函数先要求条件，得到条件后只要求被选择的值，最后产生输出。依赖因此不能全部在执行前静态展开为必需。

FN_lazy_function.hh 顶部把这一过程解释成状态机：一次调用推进到当前输入允许的位置，缺少输入就请求并返回。这里的暂停通过执行协议表达，不必等同于语言级协程。

区分输入值与使用信息

Params 提供取得已有输入、请求输入、设置输出等通道；ValueUsage 区分确定使用、可能使用和不使用。一个值还没到达与一个值不需要，是不同状态。执行器若混淆它们，可能永远等待或提前结束。

同一个 LazyFunction 可以被多次调用，因此实现不能假设第一次进入就拥有全部输入。还要区分函数描述对象和一次执行的 storage/context，避免把不同求值实例的进度互相污染。

把输出发布当成协议

输出应在对应对象已经正确构造、内容可读取时标记可用。重复设置或漏设输出会破坏下游状态。当前执行器提供日志接口来报告一些协议错误，这说明可观测性本身是架构组成部分。

教学实现先采用单线程事件循环：请求缺少输入，将当前节点挂起；输入就绪后再次排队。使用清楚的状态表比一开始套入多线程队列更容易验证。

用具体输入推演状态

Switch 先请求条件，条件暂未到达时返回，调度器计算条件后再次执行 Switch；随后只请求被选中的分支。不能在第一次条件缺失时把两个分支都标为最终不需要。

用具体输入推演状态

Switch 的条件作为始终需要输入先到达，但被选分支值尚未到达。入口断言成立，execute_impl 请求分支后返回。下一次调度进入同一函数，条件仍可用，分支这次也可读，才设置结果。

调用关系与设计判断

派生实现需要幂等地检查哪些输出已经设置，避免重复构造输出对象。执行入口的 profiling 是每次调用记录，不应把一次调用等同于整个节点从第一次请求到完成的总延迟。

Geometry Nodes: new evaluation system

先读新执行系统的设计目标，再进入最小 LazyFunction 接口。

展开提交原文、变更规模与阅读命令
This refactors the geometry nodes evaluation system. No changes for the
user are expected. At a high level the goals are:
* Support using geometry nodes outside of the geometry nodes modifier.
* Support using the evaluator infrastructure for other purposes like field evaluation.
* Support more nodes, especially when many of them are disabled behind switch nodes.
* Support doing preprocessing on node groups.

For more details see T98492.

There are fairly detailed comments in the code, but here is a high level overview
for how it works now:
* There is a new "lazy-function" system. It is similar in spirit to the multi-function
  system but with different goals. Instead of optimizing throughput for highly
  parallelizable work, this system is designed to compute only the data that is actually
  necessary. What data is necessary can be determined dynamically during evaluation.
  Many lazy-functions can be composed in a graph to form a new lazy-function, which can
  again be used in a graph etc.
* Each geometry node group is converted into a lazy-function graph prior to evaluation.
  To evaluate geometry nodes, one then just has to evaluate that graph. Node groups are
  no longer inlined into their parents.

Next steps for the evaluation system is to reduce the use of threads in some situations
to avoid overhead. Many small node groups don't benefit from multi-threading at all.
This is much easier to do now because not everything has to be inlined in one huge
node tree anymore.

06自测：先回答，再展开

调用多次说明函数重复算错了吗？

不一定，惰性协议允许多次推进，每次处理当前可用输入。

未到达与不使用为什么不能合并？

前者可能需要等待或调度，后者不应引发无谓计算，二者控制行为不同。
