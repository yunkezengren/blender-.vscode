02原理、状态与设计取舍

共享依赖只读约定

复制一个网格描述对象时，许多数组暂时可以继续共享。只要多个所有者都把共享数据当作只读，就能避免不必要的复制。要修改时，若只有一个强用户可原地写，否则先创建独立副本。这个规则将“拿到可写数据”变成重要的边界操作。

ImplicitSharingInfo 不仅计数，还知道最终怎样销毁数据。引用信息可以独立于数据分配，也可以通过 ImplicitSharingMixin 嵌入对象。这样调用者不需要猜测底层使用哪种分配器。

弱引用并非可升级的 shared_ptr 模型

当前实现的弱用户保活共享信息，而不保证数据仍然存在；强用户为零时数据已过期。源码明确说明弱用户不能直接升级成强用户，因为其他代码可能在唯一强用户假设下修改数据。不能把 std::weak_ptr 的全部行为套进来。

version 可以帮助检测数据是否变化，但它也需要正确的写入通知。每条可写访问路径若没有更新相应版本或分离规则，缓存键即使看起来完善，也会建立在错误信息上。

原子计数不等于对象任意线程安全

计数的原子操作负责引用信息的一部分并发行为，不代表多个线程可以同时修改同一几何数组。只有一个强用户也不能替代调用层的线程访问约束。并发写入、容器重分配和生命周期结束仍需各自的协议。

在 GeometryComponent 中观察共享基类与几何组件的关系，再寻找请求可写数据的路径。阅读顺序应从只读复制走向可写分离，而不是从计数实现猜测所有调用者。

SharedCache::tag_dirty：失效只影响自己的分支

SharedCache 的共享单位是 CacheData，它把 CacheMutex 和 T 放在一起，再由 shared_ptr 管理。此函数必须同时处理独占与共享：如果修改一个对象的失效状态导致另一个未变化对象也被迫重算，共享缓存的收益就会被破坏。

用具体输入推演状态

A 与 B 共享已缓存的 C0。A 的位置数据改变以后调用 tag_dirty：A 指向新块 C1，B 仍指向已缓存 C0。A.ensure 只填充 C1。若 A 原本独占 C0，则保留块地址，仅改变有效位。这里的共享条件来自调用者判断两个对象的数据是否等价，SharedCache 本身不会比较整份 Mesh。

调用关系与设计判断

把位置变化、拓扑变化、属性变化分别列成行，把 bounds、normals、BVH 分别列成列，逐格说明是否失效。这张依赖矩阵决定何处调用 tag_dirty；容器只能执行分离策略，无法替系统猜出遗漏的依赖。

隐式共享：最后一个强用户与弱用户分别释放什么

完整释放函数比单独读取引用计数更能说明生命周期。强用户保活数据；弱用户可以让共享信息继续存在，但不保活数据，也不允许像 std::weak_ptr 那样任意升级成强用户。

  void remove_user_and_delete_if_last() const
  {
    const int old_user_count = strong_users_.fetch_sub(1, std::memory_order_acq_rel);
    BLI_assert(old_user_count >= 1);
    const bool was_last_user = old_user_count == 1;
    if (was_last_user) {
      const int old_weak_user_count = weak_users_.load(std::memory_order_acquire);
      BLI_assert(old_weak_user_count >= 1);
      if (old_weak_user_count == 1) {
        /* If the weak user count is 1 it means that there is no actual weak user. The 1 just
         * indicates that there was still at least one strong user. */
        weak_users_ = 0;
        const_cast<ImplicitSharingInfo *>(this)->delete_self_with_data();
      }
      else {
        /* There is still at least one actual weak user, so don't free the sharing info yet. The
         * data can be freed though. */
        const_cast<ImplicitSharingInfo *>(this)->delete_data_only();
        /* Also remove the "fake" weak user that indicated that there was at least one strong
         * user. */
        this->remove_weak_user_and_delete_if_last();
      }
    }
  }

引用计数是原子的，元素就可以并行修改吗？

不可以，引用管理和数据读写同步是不同层次。

弱用户可以任意恢复强拥有权吗？

当前这套隐式共享接口明确不支持这样做，应遵守其可变性约定。
