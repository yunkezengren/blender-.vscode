02原理、状态与设计取舍

局部更新需要旧状态

通常缓存失效后可以完整重算，因此丢弃旧缓存很自然。但雕刻等工作流可能只更新受影响的局部，仍需要未变化部分的旧结果。共享状态下若 tag_dirty 直接建立空的新缓存，后续局部更新就可能缺失所需旧数据。

b339e3937d8 在引入共享法线缓存后修复这类问题。其核心是把保留旧内容、标记失效和更新放在适合的操作中。当前 SharedCache::update 与 tag_dirty/ensure 的区别，应当从这个需求理解。

用操作语义划分 API

tag_dirty 表达旧结果整体不能使用；update 表达需要在已有内容基础上维护新结果。二者可能都触发共享分离，但分离时是否复制旧数据不同。一个含糊的 invalidate 接口若承担所有情况，调用者就难以知道内容是否仍存在。

写状态转换表，横轴为唯一拥有或共享，纵轴为全量重算或局部维护。分别列出需要保留的数据、分配动作和其他对象看到的状态。四个格子能把隐含行为展开。

修复会移动责任边界

提交说明提到某些其他缓存需要手动标记失效，说明局部更新与更大系统的脏标记责任相互影响。读修复时要追踪谁拥有“知道哪些区域变化”的知识，谁只是通用缓存容器。

不要为了一个局部修复立刻搭建万能缓存框架。先明确当前责任和可验证用例，再决定抽象是否足够重复、是否值得通用化。这个克制本身也是架构能力。

SharedCache::update：为什么这里必须保留旧值

这是与 tag_dirty 最值得逐行对照的函数。两者都要分离共享状态，但 update 的回调允许在旧数据基础上做小修改，因此共享分支必须复制旧 T。理解这一个参数差异，才能真正理解共享缓存修复的动机。

  void update(FunctionRef<void(T &data)> compute_cache)
  {
    if (cache_.use_count() == 1) {
      cache_->mutex.tag_dirty();
    }
    else {
      cache_ = std::make_shared<CacheData>(cache_->data);
    }
    cache_->mutex.ensure([&]() { compute_cache(this->cache_->data); });
  }

用具体输入推演状态

假设缓存是 [1,2,3]，A 与 B 共享它，A 的更新操作仅把下标 1 改为 20。update 的共享分支先复制出 [1,2,3]，回调产生 [1,20,3]，B 仍读到 [1,2,3]。若改成 tag_dirty 后 ensure，并且回调只修改一个位置，默认构造的数据没有原来的另外两个值，结果就不符合增量更新契约。

调用关系与设计判断

复盘 b339e3937d8 时先给出上面的最小反例，再看实际 sculpt 调用者的更新依赖。一个有意义的回归测试必须让两个对象先共享已填充缓存，然后只改变其中一个对象的局部内容，最后同时检查新对象的局部更新和旧对象的完整结果。只有单对象测试看不到这一类缺陷。

缓存结果读取：存在数据不代表结果有效

完整访问器只借出结果引用。update 与 tag_dirty 改变的有效性必须在读取前通过 ensure 建立，而不是因为内存里还留着旧值就直接读取。

一个共享块仍被另一个对象保活时，旧引用的存储寿命可能尚在，但语义上它对应旧输入。区分“地址还可访问”与“结果符合当前几何状态”，这是共享缓存修复中同样重要的一层正确性。

HISTORY b339e3937d8 Hans Goudey · 2023-08-29

Fix: Crash in sculpt mode with shared normals caches

先重建崩溃前提，再解释为什么新增操作比单纯调整调用顺序更清楚。

展开提交原文、变更规模与阅读命令
Since the normals are stored in a shared cache, tagging them dirty
recreated the cache from scratch when it was shared. Instead,
add a function that updates the cache in the same call as tagging
it dirty. This keeps the old state of the cache around even if it was
shared, and reflects the way that it's really the PBVH and sculpt
mode managing the dirty status of normals while sculpt mode
is active.

One consequence is that the BVH cache and the triangulation
cache need to be tagged dirty manually. I'd like to avoid abstracting
this more than necessary, because I'm hoping in the long term
different caching abstractions like a more global cache that takes
implicit sharing versions into account will make this complexity
unnecessary.

Fixes #111628, #111563
