0一图总览

Set = Map 去掉 value_buffer_。其余全部继承：同样的探测循环、同样的负载 1/2、同样的三态语义、同样的指针键特化。源码上它连独立逻辑都没有——BLI_set_slots.hh 是 BLI_map_slots.hh 的镜像减法。

3字符串键特化（Set 独有的 DefaultSetSlot 重载）

BLI_set_slots.hh L360-374。字符串键有专属槽选择，Map 侧对应能力靠 _as 异型查找实现——两条不同路径解决同一个问题。

Key 类型DefaultSetSlot 选择原因（源码注释语义）
std::stringStringSetSlot字符串较大，槽内联会拖累整表扫描
StringRef / StringRefNull同上（视图不拥有）同上 + 视图生命周期短
K*IntrusiveSetSlot状态编进指针
其他SimpleSetSlot最小通用槽

为什么字符串特殊：槽表是连续内存，槽大小 = 最大槽的尺寸。一个 32B 的 std::string 塞进槽里，会让所有槽膨胀到 40B+——把大对象挂到槽外（指针/索引）保持槽苗条，探测扫描的缓存友好性才保得住。这与 VectorSet 存键指针、Map 大值类型放弃内联是同一条物理逻辑的三种表现。

4节点系统中的 Set

代码键类型吃到的特化为什么用 Set 不用 Map
GeometryNodesReferenceSet（匿名属性存活表，09-04 篇）std::stringStringSetSlot只问"这个属性还要不要"，无值可存
副作用节点的去重集合lf::FunctionNode*IntrusiveSetSlot同上，指针键零状态字节
VectorSet 的底座对比（06a）——需要"第 i 个"时才升级到 VectorSet

注意 GeometryNodesReferenceSet 底层实测仅 31 行头文件——它就是 ImplicitSharingPtr<Set<std::string>> 的别名包装（09-04 篇的"31 行承载大概念"即此）。
