0一图总览

VectorSet 的全部内存 = 一个对象头 + 两块缓冲。键本体只在 keys_ 一处；槽表只记"下标"，8 字节一个。

VectorSet 对象头
5 标量 + 内联缓冲，约 88B		 ─→ slots_ 槽表
n×8B，n=2 的幂，负载≤1/2		 ──记录下标──→ keys_ 键数组
size×sizeof(Key)，紧凑

读取路径：按值查 → 哈希定位槽 → 槽里取下标 → keys_[下标]；按下标查 → 直接 keys_[i]（零哈希）。

2槽表逐字节：一数三态

槽类型 SimpleVectorSetSlot<Key>（BLI_vector_set_slots.hh）只有一个成员：int64_t state_。符号即状态：

state_ 取值含义探测遇到它时由谁产生
-1空槽停止（键确定不存在 / 插入落点）默认构造 / 全清
-2墓碑跳过继续（链可能还在后面）remove_key_internal
≥0占用，值即 keys_ 下标比较键：相等→命中；不等→下一个occupy(index, hash)
槽表实例（8 槽，hash("A")→0、hash("B")→2、hash("C")→5，"X" 曾占 1 号槽后被删）：
#0#1#2#3#4#5#6#7
state_ 0
→"A"		 -2
墓碑(原"X")		 1
→"B"		 -1 -1 2
→"C"		 -1 -1

注意槽里没有哈希副本：occupy(index, /*hash*/) 第二参数被忽略——比较时现算。8B/槽是空间极简路线；BLI_map_slots.hh 的 Map 存哈希副本（stored_hash_），属"时间换空间"反向取舍。

5增 / 删 / 扩容动线

add_new("D")——五步（源码 L879-900）

① 容量检查ensure_can_add()
3+1=4 ≤ 8×½=4 ✔ 不扩
② 算哈希hash_("D")
指针键=地址；字符串=内容
③ 探测从 #6 起
遇空槽 -1 停 → 落 #6
④ keys_ 追加index=size()=3
下标此刻分配，此后不变
⑤ 占槽slot#6.state_=3
+自检断言（重哈希/比较）

remove_contained("B")——三连锁（L1006-1022）

① 末尾补位keys_[1]="C"
"C" 从下标 2 → 1
② 改它的槽沿哈希链找到 #5
state_: 2 → 1（删除主要成本）
③ 留墓碑#2.state_=-2
若写 -1 会截断探测链！

结果：keys_ 变 [A, C]，"C" 的下标从 2 变 1 ——这就是"删除打乱下标"。Repeat 只增不删，契约成立。

扩容 realloc_and_reinsert（L1004 起）

触发：真实元素数+1 将超 usable×½。公式（BLI_hash_tables.hh L54）：total = power_of_2_max(ceil(min_usable ÷ ½))。重建 = 遍历 keys_ 重新探测进新槽表，键本体不搬。

6增长时间线与内存账（Key=int）

第 n 次插入动作堆分配累计堆内存
1 - 4直接进内联00 B
5扩容：16 槽(128B) + keys 转堆(32B) + 搬 4 键1 次≈160 B
6 - 8直接进堆数组0≈160 B
9扩容：32 槽(256B) + keys 增长 + 搬 8 键1 次≈416 B

对比 Vector<int> 同数据：5 个 int 仅 20B。VectorSet 用约 8 倍内存换 O(1) 反查——这正是选型判决的量化依据（前置知识 03-01 篇结论的源码级兑现）。
