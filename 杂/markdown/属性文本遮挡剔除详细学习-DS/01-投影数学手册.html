01概念地图：五个坐标空间

投影的本质是把一个点从「世界」搬到「屏幕」，中间经过五个空间。每一步的变换都有明确的数学含义：

物体空间 Object顶点在模型自己的坐标系里
│├─ M = object_to_world（刚体 + 缩放）
▼
世界空间 WorldBlender 全局坐标系，场景里所有物体共享
│├─ V = viewmat（相机变换的逆）
▼
视图空间 View相机在原点，朝 −Z 看
│├─ P = winmat（frustum 或 ortho）
▼
裁剪空间 Clip齐次坐标 (x,y,z,w)，尚未除 w
│├─ 除以 w（透视除法）
▼
NDC[−1, 1]³ 标准化设备坐标
│├─ 视口变换（仿射映射）
▼
窗口空间 Window[0, winx] × [0, winy] 像素坐标
空间维度范围 / 特征变换矩阵
物体空间3D由建模决定，原点在物体中心—
世界空间3D场景全局，原点在世界中心M
视图空间3D相机在原点，看向 −ZV
裁剪空间4D 齐次由视锥决定，w 未除P
NDC3D[−1,1]³ 立方体透视除法
窗口空间2D[0,W] × [0,H]，y 轴朝上视口变换
★

为什么裁剪空间是 4 维

因为透视除法必须在裁剪之后才能做 —— 除法的分母 w 会改变符号，若先除再裁，相机背后的点会被错误地「翻折」到前面。所以图形管线刻意把除法推迟，用 4 维齐次坐标传递，先裁剪再除。完整理由见 §4 与 §7。

02矩阵链：P·V 的合成

2.1 四个矩阵的身份

Blender 的 RegionView3D 里存了四个关键矩阵（DNA_view3d_types.h:467-482）。DNA 注释本身就是权威定义：

字段DNA 注释数学含义
winmat GL_PROJECTION matrix. P：视图空间 → 裁剪空间。与相机位置无关，只由 FOV / 正交缩放 / 近远裁剪面决定
viewmat GL_MODELVIEW matrix. V：世界空间 → 视图空间。相机变换的逆，刚体矩阵
persmat Viewmat*winmat. P · V：世界空间 → 裁剪空间，预合成的 VP 矩阵
persmatob viewmat/persmat multiplied with object matrix P · V · M：物体空间 → 裁剪空间

合成代码（每次视口重绘执行一次）：

view3d_draw.cc : 135 · space_view3d.cc : 131 – 132
/* 世界空间用的 VP 矩阵 */
mul_m4_m4m4(rv3d->persmat, rv3d->winmat, rv3d->viewmat);

/* 物体空间用的 VP·M 矩阵 */
mul_m4_m4m4(rv3d->viewmatob, rv3d->viewmat, ob->object_to_world().ptr());
mul_m4_m4m4(rv3d->persmatob, rv3d->persmat, ob->object_to_world().ptr());
!

DNA 注释「Viewmat*winmat」的写法容易误导

它说的是「用 viewmat 和 winmat 合成的矩阵」，不是乘法顺序 V × P。实际顺序是 winmat × viewmat，即 P · V。判断依据是 mul_m4_m4m4(R, A, B) 计算 R = A · B（见 §3.2），而调用是 mul_m4_m4m4(persmat, winmat, viewmat)。

2.2 结合律与预合成

预合成之所以正确，只依赖矩阵乘法的结合律：

(P · V) · v = P · (V · v) (2.1)

式 (2.1) 说明：先把 P 和 V 乘成 PV 再作用于点，与先作用 V 再作用 P，结果完全一致（在精确算术下逐位相同，浮点下误差量级也相同）。

差别只在计算量：

方案每次重绘每次投影总代价（N 个顶点）
不预合成 0 2 次矩阵-向量乘 2N 次 4×4·4 乘法
预合成（Blender 采用） 1 次矩阵-矩阵乘 1 次矩阵-向量乘 64 + N 次

当 N 是每帧数万个顶点时，预合成几乎把投影的矩阵运算量减半。这是纯粹的性能优化，不改变任何数学语义。

2.3 物体空间变体

persmatob = persmat · M 的作用是让调用方能跳过手动变换。数学上：

persmatob · vobj = (P · V · M) · vobj = P · V · (M · vobj) = persmat · vworld

也就是说，把物体局部坐标直接喂给 persmatob，与先手动用 M 变换到世界空间再喂给 persmat，结果相同。

✓

关键推论：w 的物理含义与空间无关

因为两条路径等价，所以无论用 persmat（世界空间）还是 persmatob（物体空间），算出的 w 都是同一个值 —— 即「该点到相机平面的距离」。这意味着 is_local 参数对投影数学毫无影响，它只用于视图裁剪（BB）的坐标系选择。第 2 册 §3.3 有对应说明。

03Blender 的矩阵表示

这一章是纯工程约定，但读 Blender 矩阵代码时若不知道它，几乎必然出错。

3.1 列主序存储

float mat[4][4] 在内存里是 16 个连续 float，mat[i] 是第 i 列（不是行）。这样可以直接传给 OpenGL：

列主序的内存布局
内存:  [ m00 m10 m20 m30 | m01 m11 m21 m31 | m02 m12 m22 m32 | m03 m13 m23 m33 ]
         ↑ mat[0] (第0列)  ↑ mat[1] (第1列)  ↑ mat[2] (第2列)  ↑ mat[3] (第3列)

数学矩阵:
      ⎡ m00  m01  m02  m03 ⎤
      ⎢ m10  m11  m12  m13 ⎥
      ⎢ m20  m21  m22  m23 ⎥
      ⎣ m30  m31  m32  m33 ⎦
        ↑ 平移分量在第 3 行，存储上位于 mat[0][3], mat[1][3], mat[2][3]

所以对应关系是：

mat[c][r] = Mr,c   ,   mat[3][0..2] = 平移分量
×

第一个高频踩坑点

m[2][3] 指的是第 3 列第 2 行，也就是数学矩阵的第 3 行第 2 列。下标顺序和数学教科书是反的。透视投影矩阵里那个关键的 m[2][3] = -1.0f，写出来是数学上的第 3 行第 2 列 —— 正是产生 w = −z 的那一项。

3.2 mul_m4_m4m4 的语义

函数注释（math_matrix_c.cc:226）写的是 R[j][k] = B[j][i] . A[i][k]，用的正是 [列][行] 下标。展开第 0 项验证（math_matrix_c.cc:245）：

math_matrix_c.cc : 245
R[0][0] = B[0][0]*A[0][0] + B[0][1]*A[1][0] + B[0][2]*A[2][0] + B[0][3]*A[3][0];

换成标准数学下标（把 X[c][r] 记作 Xr,c）：

逐项替换下标
R0,0 = B0,0A0,0 + B1,0A0,1 + B2,0A0,2 + B3,0A0,3
提取公因式，写成求和
= Σk A0,kBk,0
这正是矩阵乘法的定义
= (A · B)0,0

结论：

mul_m4_m4m4(R, A, B)  ⟹  R = A · B   （语义：先作用 A，再作用 B）

这解释了为什么 mul_m4_m4m4(persmat, winmat, viewmat) 是正确的：它得到 P · V，即先做视图变换、再做投影 —— 与图形管线的顺序一致。

3.3 原地乘法的别名安全

mul_m4_v4(mat, r) 内部是 mul_v4_m4v4(r, mat, r)（math_matrix_c.cc:812），输入输出是同一块内存。看实现：

math_matrix_c.cc : 798 – 808
void mul_v4_m4v4(float r[4], const float mat[4][4], const float v[4])
{
  const float x = v[0];   /* 先读进局部变量 */
  const float y = v[1];
  const float z = v[2];

  r[0] = x * mat[0][0] + y * mat[1][0] + z * mat[2][0] + mat[3][0] * v[3];
  r[1] = x * mat[0][1] + y * mat[1][1] + z * mat[2][1] + mat[3][1] * v[3];
  r[2] = x * mat[0][2] + y * mat[1][2] + z * mat[2][2] + mat[3][2] * v[3];
  r[3] = x * mat[0][3] + y * mat[1][3] + z * mat[2][3] + mat[3][3] * v[3];
}

别名安全性证明：设 r == v（同一块内存）。

第 1–3 行：先把 v[0..2] 复制到局部变量 x, y, z
此时 v 尚未被修改，读取安全
第 5–7 行：写 r[0], r[1], r[2]
右侧只用到 x, y, z（局部副本）与 v[3]；没有用到 v[0..2]
第 8 行：写 r[3]，此时才读 v[3]
r[0..2] 已被覆盖，但公式只需 v[3]，而 v[3] 此时尚未被写（写 r[3] 的赋值发生在读取之后）
结论
r == v 安全

这个细节很重要：view3d_project.cc:122 的 mul_m4_v4(perspmat, vec4) 正是依赖它才能原地覆盖 vec4。如果实现改成「先写 r[0] 再读 v[1]」，就会静默产生错误结果。

04射影几何

这一章回答：为什么代码里要补一个 1.0，为什么最后要除以 w，为什么 w = 0 要单独拦下。

4.1 为什么必须升维：平移不是线性变换

设仿射空间中的平移 T(v) = v + t（t ≠ 0）。线性变换的定义要求两条性质：

T(αu + βv) = αT(u) + βT(v)   （可加性与齐次性）

其中「齐次性」直接给出 T(0) = 0。但

T(0) = 0 + t = t ≠ 0

所以平移在 𝔸³ 上不是线性变换 —— 它不过原点。而 3×3 矩阵只能表达线性变换（它必然把零向量映到零向量），因此无法表达平移。

解决方案是升维到 4 维。定义

T̃ =

在 4 维里 T̃ 是货真价实的线性变换：它把零向量 (0,0,0,0) 映到 (0,0,0,0)，且满足可加性与齐次性。

✓

这就是「补 1」的全部意义

代码里 vec4[3] = 1.0 不是为了「凑成 4 个分量」，而是把仿射问题提升为线性问题。补上这个 1 之后，平移、旋转、缩放、投影全部统一为 4×4 矩阵乘法，可以任意复合。

4.2 射影空间的构造

三维射影空间 ℙ³ 定义为 ℝ⁴ \ {0} 在如下等价关系下的商空间：

(x, y, z, w) ∼ (λx, λy, λz, λw)   ,   λ ≠ 0 (4.1)

每个等价类记作 [x : y : z : w]，称为一个射影点。三条关键性质：

  1. 缩放是「同一件事的不同表示」。 (1,2,3,4) 与 (2,4,6,8) 与 (−1,−2,−3,−4) 是同一个射影点。这与「向量 v 与 2v 方向相同」是同一类思想。
  2. 射影坐标没有绝对大小，只有比值有意义。 这正是「必须归一化才能得到唯一表示」的根源。
  3. 注意 λ 可以是负数。 所以 w 与 −w 代表同一点 —— 这一点在理解「为什么取绝对值会丢信息」时很关键（见 §7）。

4.3 仿射图与透视除法

把 w ≠ 0 的点归一化到 w = 1，得到仿射图（affine chart）：

[x : y : z : w]  ↦  (xw, yw, zw, 1) (4.2)

式 (4.2) 就是「透视除法」的全部来历。 它不是图形学发明的技巧，而是「从射影坐标回到仿射坐标」这个数学操作的必然步骤。

代码里的对应关系：

数学步骤代码位置

矩阵作用 (x,y,z,1) ↦ (xc,yc,zc,w)view3d_project.cc:122

4.4 无穷远超平面

考察 w = 0 的点。它们构成 ℙ³ 中的一个超平面，称为无穷远超平面：

Π∞ = { [x : y : z : 0] }  ≅  ℙ²

这些点不在任何仿射图内 —— 因为无论 λ 取何值，都无法把 w 变成 1（λ·0 = 0 恒成立）。式 (4.2) 的分母为零，除法无定义。

!

CLIP_ZERO 拦住的不是「数值太小」

它拦住的是一类数学上根本不属于仿射空间的点。这解释了为什么这个检查必须存在，而不能靠「反正很小、投影结果无所谓」来搪塞 —— 除以零会产生 inf/NaN，污染后续所有计算。

几何直觉：w → 0 意味着点「跑到无穷远」，而无穷远处没有仿射坐标可言。Π∞ 正是补上「平行线交于无穷远」这一性质的产物 —— 有了它，射影空间才是紧致的，任何两条射影直线都恰好交于一点。

4.5 点与方向

齐次坐标的第 4 分量还承担区分点与方向的职责：

齐次坐标含义平移是否影响投影后
(x, y, z, 1) 点（位置） 会被平移 w = −zview，需透视除法
(x, y, z, 0) 方向（自由向量） 不会被平移 w = 0，落在 Π∞

验证：对方向向量应用 T̃，第 4 行给出

w' = 0·x + 0·y + 0·z + 1·0 = 0

而平移项 t 乘的是 w = 0，所以被完全抵消。几何意义：方向不该随位置移动而改变。

!

这解释了 co[3] 为什么硬编码为 1.0

view3d_project.cc:121 写的是 vec4[3] = 1.0。若误写成 0.0，投影结果会退化为「无穷远处」，并被 CLIP_ZERO 拦下 —— 表现为「所有点都投影失败」。

05透视矩阵推导

前面几章默认了 frustum 矩阵的形式。这一章从「我们想要什么」出发，把矩阵的每个元素解出来。

5.1 视锥与四条约束

记近裁剪面 n、远裁剪面 f，视锥在近平面上的矩形边界为 x ∈ [l, r]、y ∈ [b, t]。

我们要构造一个映射，把视锥（一个截头锥体）映成 NDC 立方体 [−1,1]³。要求：

#约束含义
1x = l, z = −n ⟹ xndc = −1近平面左边界
2x = r, z = −n ⟹ xndc = +1近平面右边界
3z = −n ⟹ zndc = −1近平面
4z = −f ⟹ zndc = +1远平面

注意约束 1、2 只在近平面上成立（都带条件 z = −n）。这正是「透视」的含义：越远，同一个 x 对应的视野越宽，所以 xndc 必须同时依赖 x 和 z。

5.2 求解 x / y 行

透视除法意味着 xndc = xc/w。取 w = −z（第 4 行的选择，见 §5.4），并设

xc = A·x + C·z   ⟹   xndc = A·x + C·z−z = −Axz − C

代入约束 1 与 2（都在 z = −n 上）：

约束 1：x = l, z = −n, 要求 x_ndc = −1
−Al−n − C = −1   ⟹   A·ln − C = −1
约束 2：x = r, z = −n, 要求 x_ndc = +1
A·rn − C = +1
两式相减，消去 C
A(r − l)n = 2   ⟹   A = 2nr − l
回代求 C
C = A·rn − 1 = 2rr − l − 1 = 2r − (r − l)r − l = r + lr − l

于是 m00 = 2nr−l、m20 = r+lr−l，与源码 m[0][0]、m[2][0] 一致。y 行完全同理：

m11 = 2nt − b   ,   m21 = t + bt − b
★

C ≠ 0 的含义：视锥不对称补偿

C = (r+l)/(r−l) 只有在视锥左右不对称时才非零，它补偿「视锥中心不在光轴上」的偏移。当 l = −r（对称视锥，普通 3D 视口即是）时 C = 0，矩阵退化为对角形式 —— 这正是 §8 数值验算里能简化计算的原因。

5.3 求解 z 行

z 行决定了整个深度缓冲的精度特性（§6 将详细分析）。矩阵存的是 zc = m22·z + m32，而 zndc = zc/w = zc/(−z)。记 m22 = α、m32 = β：

zndc = αz + β−z = −α − βz

代入约束 3（z = −n，要求 zndc = −1）：

−α − β−n = −1   ⟹   −α + βn = −1   ⟹   β = n(α − 1) (5.1)

代入约束 4（z = −f，要求 zndc = +1）：

−α + βf = 1   ⟹   β = f(α + 1) (5.2)

联立 (5.1) 与 (5.2)：

消去 β
n(α − 1) = f(α + 1)   ⟹   nα − n = fα + f   ⟹   α(n − f) = n + f
解出 α（注意 n − f < 0，所以结果带负号）
α = n + fn − f = −f + nf − n
回代 (5.2) 求 β
β = f(α + 1) = f · −(f+n) + (f−n)f − n = f · −2nf − n = −2fnf − n

与源码逐项吻合：

为什么 z 行必须是分式线性函数

如果 zndc = zview 就简单了，但 zview ∈ [−f, −n] 与 [−1,1] 对不上；更根本的是，zc/w 的形式（分母含 z）迫使 zndc 必须是 z 的分式线性函数，即含 1/z 项。正是这个 1/z 造成了深度精度的严重非线性 —— 见 §6。

5.4 第 4 行与 w

最后一行取 (0, 0, −1, 0)，即数学上的 m2,3 = −1（存储下标 m[2][3]）、m3,3 = 0。于是

w = 0·x + 0·y + (−1)·z + 0·1 = −z (5.3)

精确成立，无需任何近似。 这一行的作用是把「深度」搬进 w，从而让后续的除法自动产生透视缩放。

完整的透视投影矩阵：

第 4 行是整个透视投影的灵魂

它是唯一让 w ≠ 1 的一行。去掉它（改成 (0,0,0,1)），透视投影立刻退化为正交投影。

5.5 正交投影对比

06深度与精度分析

这一章是整本手册最实用的部分：它解释了 z-fighting 的数学根源，并给出可操作的调参结论。

6.1 解析式与反解

令 d = −zview > 0 表示到相机的距离。把 z = −d 代入 zndc = −α − β/z：

代入 α、β 的值
zndc(d) = f + nf − n − 2fn(f − n)·d
通分合并
zndc(d) = (f+n)d − 2fn(f−n)d
zndc(d) = (f+n)d − 2fn(f−n)d (6.1)

这是一个分式线性函数（Möbius 变换），图像是双曲线的一支。反解出 d：

由 (6.1) 两边乘分母
zndc(f−n)d = (f+n)d − 2fn
把含 d 的项移到一侧
d[zndc(f−n) − (f+n)] = −2fn
两边取负，解出 d
d(zndc) = 2fn(f+n) − zndc(f−n)
d(zndc) = 2fn(f+n) − zndc(f−n) (6.2)

式 (6.2) 在从深度缓冲反推世界坐标时非常有用，例如 ED_view3d_win_to_3d 系列的深度重建、以及第 2 册里「用深度缓冲做遮挡测试」的场景。

6.2 导数与分辨率

对 (6.1) 求导。把 (6.1) 改写成便于求导的形式：

zndc(d) = f+nf−n − 2fnf−n · 1d

前项是常数，后项用到 d/dd[1/d] = −1/d²：

对 d 求导
dzndcdd = −2fnf−n · (−1d²) = 2fn(f−n)d²
dzndcdd = 2fn(f−n)d² (6.3)

反过来，给定深度缓冲的最小可分辨步长 Δzndc，能分辨的世界空间距离是：

Δd = dzdzndc · Δzndc = (f − n) · d² · Δzndc2fn (6.4)
★

(6.4) 是本章最重要的结论

深度分辨率与距离的平方成正比（Δd ∝ d²）。距离翻倍，可分辨的最小间距变成 4 倍；距离变成 10 倍，精度损失 100 倍。这就是透视深度缓冲的根本缺陷，也是所有 z-fighting 问题的数学根源。

代入典型值 n = 0.1、f = 1000，24 位深度缓冲（Δzndc = 2·2−24 = 2−23 ≈ 1.192×10−7）：

Δd = 999.9 · d² · 1.192×10−72 · 1000 · 0.1 ≈ 5.959 × 10−7 · d²
距离 dΔd（可分辨间距）直观感受
0.16.0 × 10−9亚纳米级，远超需求
16.0 × 10−7微米级
106.0 × 10−50.06 毫米
1006.0 × 10−36 毫米
10000.596约 0.6 个世界单位！

最后一行非常震撼：在远裁剪面处，深度缓冲能分辨的最小间距是 0.6 个世界单位。若场景尺度是米，那就是 60 厘米 —— 任何小于这个距离的两层表面都无法正确排序。

6.3 精度由近平面决定

把 (6.4) 的系数单独拿出来分析：

f − nfn = 1n − 1f = 1n(1 − nf)

当 f ≫ n（绝大多数实际场景）时，n/f → 0，于是

Δd ≈ d² · Δzndc2n   ⟹   Δd ∝ 1n (6.5)

精度只由近平面决定，与远平面几乎无关。 数值验证：

1010000.0990100× 更好
✓

实践结论（可操作）

遇到 z-fighting 时，把近裁剪面调大是最有效的办法，而调整远裁剪面基本没用。Blender 相机的 clip_start 默认 0.1 —— 这个值越小，远处精度越差。把 clip_start 从 0.1 改成 1，远处精度立刻提升 10 倍；而把 clip_end 从 1000 拉到 10000，几乎毫无改善。

6.4 z-fighting 临界距离

给定一个需要区分的几何间距 ε，由 (6.4) 解出「超过此距离就无法区分」的临界值：

令 Δd = ε，解出 d
ε = (f−n)·d²·Δzndc2fn
整理
d² = 2fn·ε(f−n)·Δzndc
开方
dcrit = √2fn·ε(f−n)·Δzndc
dcrit = √2fn·ε(f−n)·Δzndc (6.6)

取 n = 0.1, f = 1000, Δzndc = 2−23，要求区分 ε = 0.01：

dcrit = √0.015.959 × 10−7 = √16781 ≈ 129.5

即：超过约 130 个世界单位后，间距 0.01 的两层表面开始 z-fighting。

6.5 缓冲位深的影响

由 (6.4)，Δd ∝ Δzndc，而 Δzndc = 21−b（b 为位深）。所以位深每增加 1 位，精度翻倍：

如果用 float32 而非 32 位定点，浮点本身的尾数只有 24 位有效精度，且分布方式不同（在 0 附近更密）。实际效果介于 24 位与 32 位定点之间。更彻底的解法是 reversed-Z：把深度映射反转（近平面为 1、远平面为 0），使浮点精度集中到远处 —— 这是现代引擎的常见做法，但 Blender 的这条管线用的是标准映射。

07数值理由：交叉相乘

代码里深度裁剪写的是 zc ≤ −w 而不是 zc/w ≤ −1。这一章解释为什么这个改写不只是优化，而是必要的。

7.1 两种写法的差异

数学上，当 w > 0 时两式完全等价：

zcw ≤ −1   ⟺   zc ≤ −w (7.1)

但在浮点算术里它们不等价。差异来自三处：

方面除法写法 zc/w乘法写法 zc ≤ −w
运算成本 一次除法（延迟约 4–20 倍乘法） 一次比较
w → 0 时 商 → ±∞，可能溢出为 inf 两侧都有界，比较始终有效
相对误差 商继承两个操作数的误差（≈ 2ε） 比较不引入额外舍入
编译器假设 依赖 IEEE 754 溢出语义 仅需普通有限算术

7.2 w → 0 的具体行为

设 w 极小。注意代码里 w 已经取过绝对值，所以 w ≥ 0。

除法写法

若 zc = 1、w = 10−40（次正规数），则

zcw = 1040 > FLT_MAX ≈ 3.4 × 1038   ⟹   溢出为 +inf

而 inf ≤ −1 为假，恰好「碰巧」得到正确结论（近平面内？不，是远平面内）。如果 zc 为负，则得到 −inf，−inf ≤ −1 为真，同样「碰巧」正确。

×

它看起来能用，但完全依赖未定义行为的边界

正确性建立在 IEEE 754 的溢出语义之上，而一旦编译器开启 -ffast-math（或 -ffinite-math-only），溢出行为就不再受保证 —— 编译器可以假设不存在 inf，从而优化掉整个判断。Blender 的部分构建配置使用激进浮点选项，这类代码是隐患。

乘法写法

zc ≤ −w 即 1 ≤ −10−40，为假。结果正确，且不依赖任何特殊值语义 —— 两侧都是普通有限浮点数。

✓

这就是「先判后除」的完整理由

把除法推迟到 ZERO / NEAR / FAR 三道检查之后，确保所有可能让除法失效的点都已被过滤。此时 w 已保证大于 0.001（若开了 ZERO）或至少非零（有三元兜底），除法才是安全的。第 2 册 §3.7 讲解那个兜底的具体写法。

7.3 为什么默认不检查 ZERO

第 2 册会讲到，默认掩码 V3D_PROJ_TEST_CLIP_DEFAULT 只含 BB | WIN | NEAR，不含 ZERO。这意味着使用默认掩码时，w 可能仍然很小（比如 10−5），除法会得到一个巨大但有限的值。

后果分析：fx 会是一个天文数字（比如 107），然后被 CLIP_WIN 拦下 —— 功能上正确，因为这样一个点确实在窗口外。

所以默认掩码的取舍是：

决策理由
不检查 ZERO 省一次比较；极近点通常会被 CLIP_WIN 兜住
但除法必须有三元兜底 以防 w 精确为 0 时产生 NaN 污染后续计算
需要精确性的调用方显式传入 ZERO 例如 transform_draw_cursors.cc:103 的变换辅助线

08数值验算实例

把前面所有公式代入一个具体点，走完整条链路。

场景设定：n = 0.1、f = 1000，视锥对称（l = −r、b = −t），所以 C = 0、(t+b)/(t−b) = 0，矩阵退化为对角形式。取相机正前方 10 单位、且 xview = yview = 0 的点，即 zview = −10。

手算推演 · n = 0.1, f = 1000
第 1 步  齐次嵌入
         (x, y, z) = (0, 0, -10)  →  vec4 = [0, 0, -10, 1]

         x_c = m00 · x                                = 0
         y_c = m11 · y                                = 0
         z_c = m22 · z + m32 · 1
             = -(f+n)/(f-n) · (-10) + (-2fn/(f-n))

         z_ndc = z_c / w = 9.800980 / 10              = 0.980098

         z_ndc = (1000.1 · 10 − 200) / (999.9 · 10)

第 5 步  深度缓冲值
         b = (z_ndc + 1) / 2                          = 0.990049
