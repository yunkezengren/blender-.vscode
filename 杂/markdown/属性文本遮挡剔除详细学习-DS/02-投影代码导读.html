参数类型含义与约束
region const ARegion * 必须是 RGN_TYPE_WINDOW 区域。函数只读取 winx / winy（两个 short，见 DNA_screen_types.h:819）。注意参数是 const，但内部第 112 行要取 regiondata 拿 rv3d，所以做了 const_cast 风格的类型转换
perspmat const float[4][4] 已合成的 VP 矩阵。世界空间传 rv3d->persmat（= P·V），物体空间传 rv3d->persmatob（= P·V·M）。不要传裸的 winmat —— 那样会缺少视图变换
is_local const bool 注释写着 /* normally hidden */，因为它是内部参数。只影响 BB 裁剪：决定用 rv3d->clip（世界空间平面）还是 rv3d->clip_local（物体空间平面）。对投影数学无影响
co const float[3] 输入 3D 点。空间必须与 perspmat / is_local 匹配：persmat 配世界坐标，persmatob 配物体局部坐标。传错空间不会报错，只会得到错误结果
r_co float[2] 输出：float 像素坐标（未取整）。失败时完全不写入 —— 调用方必须先检查返回值，否则可能读到未初始化值
flag const eV3DProjTest 位掩码，逐项开启裁剪检查。位定义见 §2
数学依据 persmat 为什么是 P·V、persmatob 为什么能直接吃物体坐标 → 第 1 册 §2 矩阵链

1.3 三种输出类型的包装层

_ex 层是薄包装：调用核心函数拿到 float 结果，再做类型转换与溢出检查。三者的差异只在最后几步：

包装函数行号转换方式溢出判据
ED_view3d_project_short_ex 153-173 short(floorf(tvec[i])) |tvec| < 32700，否则返回 V3D_PROJ_RET_OVERFLOW
ED_view3d_project_int_ex 175-196 int(floorf(tvec[i])) |tvec| < 2.14×109，否则 OVERFLOW
ED_view3d_project_float_ex 198-216 直接拷贝 isfinite() 检查，非有限则 OVERFLOW
view3d_project.cc : 153 – 173 · short 版包装
eV3DProjStatus ED_view3d_project_short_ex(const ARegion *region,
                                          float perspmat[4][4],
                                          const bool is_local,
                                          const float co[3],
                                          short r_co[2],
                                          const eV3DProjTest flag)
{
  float tvec[2];
  eV3DProjStatus ret = ed_view3d_project__internal(region, perspmat, is_local, co, tvec, flag);
  if (ret == V3D_PROJ_RET_OK) {
    if ((tvec[0] > -32700.0f && tvec[0] < 32700.0f) &&
        (tvec[1] > -32700.0f && tvec[1] < 32700.0f))
    {
      r_co[0] = short(floorf(tvec[0]));
      r_co[1] = short(floorf(tvec[1]));
    }
    else {
      ret = V3D_PROJ_RET_OVERFLOW;   /* 注意：此时 r_co 未被写入 */
    }
  }
  return ret;
}
!

为什么是 floorf 而不是截断

floorf 对负数向下取整（−1.5 → −2），而 C 的强制转换是向零截断（−1.5 → −1）。用 floorf 保证「落在同一个像素格内的点映射到同一整数」，这对拾取和栅格化的一致性很重要。

2.2 短路求值与性能

每个检查都写成 (flag & BIT) && (条件) 的形式。C 的 && 短路求值意味着：当该位未设置时，右侧的比较根本不执行。

短路求值的实际效果
/* 写法：位未设置 → 右侧被跳过 */
if ((flag & V3D_PROJ_TEST_CLIP_ZERO) && (w <= float(BL_ZERO_CLIP))) { ... }

/* flag 不含 ZERO 位时，等价于： */
if (false) { ... }        /* 整个分支被优化掉 */

/* flag 含 ZERO 位时，才真正做比较 */
if (w <= 0.001f) { ... }

所以关闭某项检查是真的省下运算，不是「算了但不用」。这在每帧数万次的顶点循环里很有意义。

✓

编译器视角

因为 flag 是编译期不可知的运行期值，编译器无法完全消除分支，但能保证位测试失败时不执行浮点比较 —— 这避免了潜在的浮点异常与不必要的依赖链。

2.3 断言与非法位

view3d_project.cc : 106 – 109
float vec4[4];

/* check for bad flags */
BLI_assert((flag & V3D_PROJ_TEST_ALL) == flag);

这个断言检查「flag 中是否含 V3D_PROJ_TEST_ALL 之外的位」。若调用方传了未定义的位，断言在 Debug 构建下触发；Release 构建下 BLI_assert 被编译掉，非法位被静默忽略。

i

为什么需要这个断言

因为 flag 是位掩码，传错一个常量不会导致编译错误 —— 比如把 1 << 6 误写成 1 << 7，只会让某项检查静默失效。断言把这类错误提前到开发阶段暴露。

03逐行拆解

下面按行号顺序讲解 120–151 行。数学推导只给结论，完整证明在第 1 册对应章节。

3.1 齐次嵌入 120 – 121

view3d_project.cc : 120 – 121
copy_v3_v3(vec4, co);
vec4[3] = 1.0;

把 3D 点 co 复制到 4 分量缓冲 vec4，并把第 4 分量置为 1.0。

  • 代码意图：把点升维成齐次坐标，使 4×4 矩阵能同时表达旋转与平移。
  • 为什么是 1.0 而不是 0.0：1.0 表示「点」，0.0 表示「方向」。投影的对象是点，写错会导致所有点被判为无穷远。
  • 缓冲区安全：vec4 是未初始化栈数组，但 copy_v3_v3 填 [0..2]、本行填 [3]，四个分量全部被覆盖，不存在未初始化读取。
数学依据 为什么必须补 1（平移不是线性变换）、点与方向的区别 → 第 1 册 §4.1 与 §4.5

3.2 VP 乘法 122

view3d_project.cc : 122
mul_m4_v4(perspmat, vec4);

用预合成的 VP 矩阵一次性把点从世界空间（或物体空间）变换到裁剪空间。

  • 原地运算：mul_m4_v4(mat, r) 内部是 mul_v4_m4v4(r, mat, r)，输入输出是同一块内存。这个别名是安全的 —— 实现先把 v[0..2] 读进局部变量，最后才读 v[3]。
  • 执行后的状态：vec4 = (xc, yc, zc, w)，其中 w = −zview（透视）或 w = 1（正交）。
数学依据 别名安全性的逐步证明 → 第 1 册 §3.3；w = −zview 的来历 → §5.4

3.3 fabsf 123

view3d_project.cc : 123
const float w = fabsf(vec4[3]);

取 vec4[3] 的绝对值，赋给局部变量 w。注意 vec4[3] 本身没有被修改 —— 后续第 138–139 行用的是 vec4[0]、vec4[1]，而 w 只在第 137 行用作除数。

这行的三个后果：

#后果影响
1 scalar = 1/w 恒为正 相机背后的点被投影到镜像位置，而不是被拒绝
2 CLIP_ZERO 语义变为「距离 ≤ 0.001」 否则所有背后点都会被误报成 CLIP_ZERO
3 拦截背后点的责任转移给 CLIP_NEAR 这是理解本段代码的关键（见 §3.5）

对比同文件开头的「不裁剪版」（view3d_project.cc:43-49），它用的是原始 vec4[3]（保留符号）：

  co_region[1] = region->winy / 2.0f + (region->winy / 2.0f) * vec4[1] / vec4[3];

两套 API 的阈值相差四个数量级

FLT_EPSILON ≈ 1.19e-7 是「浮点精度极限」，而 0.001 是「投影结果不可信的整个区间」。裁剪版用后者，因为它要拦住的不是数值噪声，而是几何上已经退化的点。

数学依据 取绝对值为什么丢失信息（λ 可为负）→ 第 1 册 §4.2

3.4 CLIP_ZERO 125 – 127

view3d_project.cc : 125 – 127
if ((flag & V3D_PROJ_TEST_CLIP_ZERO) && (w <= float(BL_ZERO_CLIP))) {
  return V3D_PROJ_RET_CLIP_ZERO;
}

检查点是否落在射影奇点上（w ≈ 0）。

  • BL_ZERO_CLIP 定义在 view3d_project.cc:27，值为 0.001。
  • float(BL_ZERO_CLIP) 把 double 字面量转成 float，避免隐式转换警告。
  • 判据用 <=：w 恰好等于 0.001 也触发。
  • 注意默认掩码不含这一位，所以默认路径下这个分支被跳过 —— 这正是第 137 行需要三元兜底的原因。
数学依据 w = 0 是无穷远超平面 Π∞ 上的点，不属于任何仿射图 → 第 1 册 §4.4

3.5 CLIP_NEAR 129 – 131

view3d_project.cc : 129 – 131
if ((flag & V3D_PROJ_TEST_CLIP_NEAR) && (vec4[2] <= -w)) {
  return V3D_PROJ_RET_CLIP_NEAR;
}

用交叉相乘代替除法判断「比近平面更近」。

  • vec4[2] 是 zc，-w 是 −w。判据 zc ≤ −w 等价于 zc/w ≤ −1。
  • 这里不做除法：省一次浮点除法，且避免 w → 0 时溢出。除法被推迟到第 137 行。
  • 相机背后的点也在这里被拦下：因为取过绝对值后 w > 0，而背后点的 zc 会急剧变负，必然跌破 −w。
★

为什么 NEAR 必须与 WIN 一起使用

ED_view3d.hh:313-316 的注释明确指出：透视视图应同时启用 CLIP_WIN 和 CLIP_NEAR。原因是近平面附近被裁的点投影后会得到极大甚至无穷的屏幕坐标 —— 只有 CLIP_WIN 能兜住这些数值，而只有 CLIP_NEAR 能阻止它们产生。

数学依据 近平面为什么映射到 −1、交叉相乘的浮点理由 → 第 1 册 §7.1 与 §7.2

3.6 CLIP_FAR 133 – 135

view3d_project.cc : 133 – 135
if ((flag & V3D_PROJ_TEST_CLIP_FAR) && (vec4[2] >= w)) {
  return V3D_PROJ_RET_CLIP_FAR;
}

同一套推导的另一半：zc ≥ w 等价于 zc/w ≥ +1。

与 NEAR 合起来，两个不等式恰好是 |zc| > w 的两个半边，等价于 |zc/w| > 1。

!

FAR 不在默认掩码里

V3D_PROJ_TEST_CLIP_DEFAULT 只有 BB | WIN | NEAR。原因：远处物体投影后落在窗口外，CLIP_WIN 已经能挡住，单独判远平面多数场景没必要。需要精确剔除远平面时才显式加上。

3.7 scalar 兜底 137

view3d_project.cc : 137
const float scalar = (w != 0.0f) ? (1.0f / w) : 0.0f;

计算透视除法系数 1/w，并处理 w = 0 的边界情况。

  • 为什么需要兜底：默认掩码不含 CLIP_ZERO，所以 w 可能精确为 0。此时 1.0f/0.0f 产生 +inf，接着 vec4[0] * inf 变成 inf 或 NaN，污染后续计算。
  • 为什么取 0.0f 而非 1.0f：取 0 时 fx = winx/2、fy = winy/2，点被温和地落到窗口正中心，而不是产生 inf/NaN。这是防污染设计，代价是结果无意义。
  • != 0.0f 与 > 0.0f 等价：因为第 123 行取了绝对值，w ≥ 0 恒成立。写成 != 更直白地表达「非零」意图。
i

这是整个函数唯一的除零保护

若调用方开启了 CLIP_ZERO，第 125 行已经拦截了 w ≤ 0.001，这个三元判断就永远不会走 else 分支。它的存在纯粹是为了默认掩码路径的安全。

这里不取整 取整交给外层包装（§1.3）。核心函数保持 float 精度，供需要亚像素精度的调用方使用
不写 r_co 结果先存局部变量 fx、fy，等窗口裁剪通过后才写（§3.10）
数学依据 NDC 与像素的映射关系、两种等价写法 → 第 1 册 §9 公式速查表

3.9 CLIP_WIN 141 – 145

view3d_project.cc : 141 – 145
if ((flag & V3D_PROJ_TEST_CLIP_WIN) &&
    (fx <= 0.0f || fy <= 0.0f || fx >= float(region->winx) || fy >= float(region->winy)))
{
  return V3D_PROJ_RET_CLIP_WIN;
}

检查投影结果是否落在窗口内。

  • 接受区间是开区间 (0, W) × (0, H)：判据用 <= 和 >=，所以恰好落在边界上的点也算被裁掉。这对「点在窗口内」是保守语义，能避免后续绘制/拾取在边界上产生歧义。
  • 这是唯一必须在除法之后做的检查，因为它需要 fx、fy 本身。
  • 注意 region->winx 在此处再次做了 float() 转换。
检查依赖的数据能否提前到除法之前
BB / ZERO / NEAR / FAR只需 zc、w、原始 co能
WIN需要 fx、fy不能

3.10 写出结果 147 – 150

view3d_project.cc : 147 – 150
r_co[0] = fx;
r_co[1] = fy;

return V3D_PROJ_RET_OK;

只有走到这里才写 r_co。所有失败分支都是裸 return，r_co 保持调用方传入时的原值（可能是未初始化栈内存）。

同文件的 ED_view3d_project_base（79-92）演示了正确的防呆写法：

view3d_project.cc : 79 – 92 · 调用方防呆示范
eV3DProjStatus ED_view3d_project_base(const ARegion *region, Base *base, float r_co[2])
{
  eV3DProjStatus ret = ED_view3d_project_float_global(
      region, base->object->object_to_world().location(), r_co, V3D_PROJ_TEST_CLIP_DEFAULT);

  /* Prevent uninitialized values when projection fails,
   * although the callers should check the return value. */
  if (ret != V3D_PROJ_RET_OK) {
    r_co[0] = -1.0;
    r_co[1] = -1.0;
  }

  return ret;
}

04状态码参考

4.1 六种返回值的含义

ED_view3d.hh : 271 – 291
/* return values for ED_view3d_project_...() */
enum eV3DProjStatus {
  V3D_PROJ_RET_OK = 0,
  /** Can't avoid this when in perspective mode, (can't avoid) */
  V3D_PROJ_RET_CLIP_NEAR = 1,
  /** After clip_end. */
  V3D_PROJ_RET_CLIP_FAR = 2,
  /** 坐标太靠近视点，投影结果不可用（可能有数值误差） */
  V3D_PROJ_RET_CLIP_ZERO = 3,
  /** Bounding box clip - RV3D_CLIPPING */
  V3D_PROJ_RET_CLIP_BB = 4,
  /** Outside window bounds. */
  V3D_PROJ_RET_CLIP_WIN = 5,
  /** Outside range (mainly for short), (can't avoid) */
  V3D_PROJ_RET_OVERFLOW = 6,
};
状态值产生位置含义与建议处理
V3D_PROJ_RET_OK 0 150 成功，r_co 已写入有效像素坐标
V3D_PROJ_RET_CLIP_NEAR 1 130 点在近平面之内或相机背后。透视模式下无法避免。处理：跳过该点，或做边裁剪
V3D_PROJ_RET_CLIP_FAR 2 134 点在远裁剪面之外。处理：通常可直接跳过
V3D_PROJ_RET_CLIP_ZERO 3 126 射影奇点，坐标不可信。处理：跳过；若需要「即使很近也要投影」，则不要传这一位
V3D_PROJ_RET_CLIP_BB 4 115 被用户自定义视图裁剪面裁掉（Alt+B）。处理：跳过
V3D_PROJ_RET_CLIP_WIN 5 144 投影结果落在窗口外。处理：跳过；注意这是最常见的结果
V3D_PROJ_RET_OVERFLOW 6 169 / 192 / 212 只在包装层产生，核心函数从不返回它。表示结果超出输出类型范围

4.2 优先级与判定顺序

状态码不是互斥的 —— 一个点可能同时满足多个条件，返回的是第一个命中的。 判定顺序即代码顺序：

1. BB111-118 · 用户裁剪面（在矩阵变换之前）
▼ 未命中
2. ZERO125-127 · 射影奇点
▼ 未命中
3. NEAR129-131 · 近平面 / 相机背后
▼ 未命中
4. FAR133-135 · 远平面
▼ 未命中
5. WIN141-145 · 窗口边界
▼ 未命中
OK147-150 · 写出结果
!

实例：既在相机背后又在窗口外的点

它返回 CLIP_NEAR 而非 CLIP_WIN —— 因为 NEAR 检查在前。如果调用方按状态码分类处理（比如只对 CLIP_WIN 做特殊逻辑），必须知道这个优先级顺序，否则会漏掉情况。

4.3 调用方契约

契约说明违反后果
必须先检查返回值 失败时 r_co 不被写入 读取未初始化内存，可能得到任意值
坐标空间必须与 API 匹配 _global 配世界坐标，_object 配物体局部坐标 结果错误，但不报错
region 必须是 window 区域 函数读取 regiondata 作为 rv3d 类型混淆，未定义行为
输出坐标是左下原点 y 轴朝上，与 area/GPU 坐标相反 图形上下颠倒
_object 版要求矩阵已初始化 ED_view3d_check_mats_rv3d 会断言 Debug 下断言失败；Release 下结果错误

05使用指南

5.1 该选哪个 API

场景推荐 API理由
绘制、gizmo、拾取（需要整数像素） ED_view3d_project_int_global int 范围足够，避免 short 的 ±32700 溢出
传给需要 short 的旧 API ED_view3d_project_short_global 仅当接口强制要求 short 时使用
需要亚像素精度（文字、细线） ED_view3d_project_float_global 不损失精度
点在物体局部坐标系里 ..._object 版 省一次手动 M 变换
只想拿屏幕坐标，不做裁剪 ED_view3d_project_float_v2_m4 不裁剪版，无状态码，w ≈ 0 时返回 (0,0)

5.2 该传哪个掩码

掩码值适用场景
V3D_PROJ_TEST_CLIP_DEFAULT 7 绝大多数场景。BB + WIN + NEAR，覆盖了「看不见的点」的全部常见情况
V3D_PROJ_TEST_CLIP_DEFAULT | V3D_PROJ_TEST_CLIP_CONTENT_DEFAULT 7 | 46 = 47 边迭代器（view3d_iterators.cc），需要把边裁到视口边界
V3D_PROJ_TEST_CLIP_ZERO 16 对 w → 0 敏感的场景，如 transform_draw_cursors.cc:103 的变换辅助线
V3D_PROJ_TEST_NOP 0 不做任何检查，只要投影结果。慎用 —— 可能得到 inf/NaN

06修改指南

6.1 本函数的职责边界

修改前必须清楚它该做什么、不该做什么：

职责说明
应该做：单点 3D → 2D 投影输入一个点，输出像素坐标或失败原因
应该做：可选的裁剪检查由 flag 控制，未启用时不做任何额外运算
应该做：状态码返回让调用方能区分失败原因
不应该做：边/线段裁剪那是 view3d_iterators.cc 的职责（CLIP_CONTENT）
不应该做：输出深度本函数丢弃 zc。需要深度用 ED_view3d_calc_zfac 或 mul_project_m4_v3_zfac
不应该做：矩阵计算矩阵在 view3d_draw.cc 里合成好，本函数只使用
不应该做：分配内存或抛异常纯计算函数，无副作用（除写 r_co）

6.2 改动风险点

1

不要「修正」第 123 行的 fabsf

去掉 fabsf 会让所有相机背后的点变成 CLIP_ZERO，而它们本应由 CLIP_NEAR 处理。这看起来像 bug，实际是刻意设计（§3.3）。

2

不要给 NEAR/FAR 加除法

改成 vec4[2]/w <= -1.0f 会引入两个问题：① 每次投影多一次除法（性能）；② w → 0 时产生 inf，使判断依赖 IEEE 溢出语义，在 -ffast-math 下失效（§3.5）。

3

不要在失败分支写 r_co

有些调用方依赖「失败时 r_co 不变」这一契约。若统一填 0，可能破坏现有逻辑（虽然填 0 更安全，但那应该由各调用方自己决定，如 ED_view3d_project_base 填 −1）。

4

不要动检查顺序

状态码优先级由顺序决定（§4.2）。把 WIN 移到 NEAR 之前会改变「背后且在窗口外」的点返回的状态码，可能影响依赖特定状态码的调用方。

5

若要新增检查位

必须同步更新 V3D_PROJ_TEST_ALL（ED_view3d.hh:327-329），否则第 109 行断言会在 Debug 下失败。位只能往后加（当前用到 1 << 5）。

6.3 不该做的事

诱惑为什么不该做
把 is_local 去掉，改用 clip 判断 会失去物体空间裁剪的性能优势 —— clip_local 让 BB 测试在物体空间直接做，省一次矩阵变换
把 region 换成显式传 winx/winy 会让所有调用点都要改动，且失去「从 region 取 rv3d」的便利
在此处实现 CLIP_CONTENT 它是边的概念，单点投影无法表达。见 view3d_iterators.cc
缓存投影结果 函数无状态，缓存需要 key（矩阵 + 坐标），开销大于收益
改成返回 bool 会丢失失败原因，破坏所有现有调用方
