# 04 · DNA_DEFINE_CXX_METHODS 与浅拷贝

[前置知识总入口](../README.md) · [本章导航](README.md) · [上一篇](03-DNA结构体编写规则.md) · [下一篇](05-blend读写与指针重定位.md)

> 基准：Blender `5.4.0-alpha`，本地工作树。本篇讲 DNA 结构体上的一组 C++ 魔法：`DNA_DEFINE_CXX_METHODS` 宏与 `dna::shallow_copy`。它解决了"DNA 结构体不能有构造函数，但又需要安全拷贝"的矛盾。主要源码：[`DNA_defs.h`](../../../source/blender/makesdna/DNA_defs.h)（146 行）、[`DNA_node_types.h`](../../../source/blender/makesdna/DNA_node_types.h)（4047 行，实例）。

## 先回答一个具体问题

DNA 结构体不能有构造函数（makesdna 不认），但它可能含有堆指针。那么"复制一个节点"时该怎么写？

直觉答案：`dst = src;` —— 但这是**编译错误**。

`[讲解]` 为什么禁掉普通拷贝？因为 DNA 结构体常含堆指针：

```c
struct NodeGeometryRepeatOutput {
  NodeRepeatItem *items = nullptr;   // 堆数组
  int items_num = 0;
  ...
};
```

如果允许 `dst = src`，两个结构体的 `items` 指向**同一块内存**。删掉一个，另一个就悬空；析构一次，再析构一次就是 double free。

所以 Blender 的答案是：**默认拷贝全部删除，只保留"显式的浅拷贝"这条唯一通道**。

## 宏的完整展开

`[讲解]` 看 `DNA_defs.h` 的实际定义（L108-L137）：

```cpp
#define DNA_DEFINE_CXX_METHODS(class_name) \
  DNA_DEPRECATED_IGNORE(class_name() = default;) \
  ~class_name() = default; \
  /* Delete copy and assignment, which are not safe for resource ownership. */ \
  class_name(const class_name &other) = delete; \
  class_name(class_name &&other) noexcept = delete; \
  class_name &operator=(const class_name &other) = delete; \
  class_name &operator=(class_name &&other) = delete; \
  /* Support for shallow copy. */ \
  class_name(const dna::internal::ShallowDataConstRef<class_name> ref) : class_name() \
  { \
    _DNA_internal_memcpy(this, ref.get_pointer(), sizeof(class_name)); \
  } \
  class_name &operator=(const dna::internal::ShallowDataConstRef<class_name> ref) \
  { \
    if (this != ref.get_pointer()) { \
      _DNA_internal_memcpy(this, ref.get_pointer(), sizeof(class_name)); \
    } \
    return *this; \
  } \
  /* Create object which memory is filled with zeros. */ \
  class_name(const dna::internal::ShallowZeroInitializeTag /*tag*/) : class_name() \
  { \
    _DNA_internal_memzero(this, sizeof(class_name)); \
  } \
  class_name &operator=(const dna::internal::ShallowZeroInitializeTag /*tag*/) \
  { \
    _DNA_internal_memzero(this, sizeof(class_name)); \
    return *this; \
  }
```

`[讲解]` 拆成四组：

### 第一组：默认构造与析构

```cpp
DNA_DEPRECATED_IGNORE(class_name() = default;)
~class_name() = default;
```

`[讲解]` 注意 `DNA_DEPRECATED_IGNORE(...)` —— 这是个包装宏，作用是"抑制默认构造产生的 deprecated 警告"。

**为什么会有警告？** 因为 DNA 结构体在 C++ 侧被视为"不该手动构造的类型"（它的正常生命周期由 DNA 系统管理）。但 `MEM_new<T>` 需要默认构造，所以必须存在。

注释里还有一句（L125 附近）："Calling the default constructor works-around deprecated warning generated by GCC." —— GCC 对某些默认构造会报 deprecated，显式调用可以绕过。

### 第二组：删除所有拷贝与移动

```cpp
class_name(const class_name &other) = delete;
class_name(class_name &&other) noexcept = delete;
class_name &operator=(const class_name &other) = delete;
class_name &operator=(class_name &&other) = delete;
```

`[讲解]` 四个 `= delete`，注释说得很直白：

> "Delete copy and assignment, which are not safe for resource ownership."

**关键理解**：这不是"不让你复制"，而是"**逼你表达意图**"。你必须在代码里显式写 `dna::shallow_copy(src)`，读代码的人一眼就知道"这是浅拷贝，指针会共享"。

`[讲解]` 对比 C++ 的常规做法：通常用"自定义拷贝构造函数 + 深拷贝"处理含指针的类型。但 DNA 结构体**不能**有自定义拷贝构造（makesdna 不认）。所以只能：

1. 删掉默认拷贝；
2. 用一个**语义明确的不同类型**（`ShallowDataConstRef`）作为"拷贝源"。

### 第三组：浅拷贝

```cpp
class_name(const dna::internal::ShallowDataConstRef<class_name> ref) : class_name()
{
  _DNA_internal_memcpy(this, ref.get_pointer(), sizeof(class_name));
}

class_name &operator=(const dna::internal::ShallowDataConstRef<class_name> ref)
{
  if (this != ref.get_pointer()) {
    _DNA_internal_memcpy(this, ref.get_pointer(), sizeof(class_name));
  }
  return *this;
}
```

`[讲解]` 三个要点：

1. **参数类型是 `ShallowDataConstRef` 而不是 `const T&`** —— 这是关键设计。因为 `const T&` 会和"被删除的普通拷贝构造"重载冲突。
2. **先 `: class_name()`** —— 调用默认构造，保证成员有默认值（然后再被 memcpy 覆盖）。
3. **赋值版本有自检** `if (this != ref.get_pointer())` —— 防止自我赋值时 `memcpy(this, this, n)` 的未定义行为。

`[讲解]` `_DNA_internal_memcpy` 而不是直接 `memcpy`：

```cpp
void _DNA_internal_memcpy(void *dst, const void *src, size_t size);
```

为什么要包一层？因为 Blender 有 sanitizer/调试模式，可能要跟踪内存操作。这个包装函数给了插入检查的机会。

### 第四组：零初始化

```cpp
class_name(const dna::internal::ShallowZeroInitializeTag /*tag*/) : class_name()
{
  _DNA_internal_memzero(this, sizeof(class_name));
}
```

`[讲解]` 用途：需要一块"全 0 的内存"时。

**为什么不直接用 `memset`？** 因为这时对象还没构造完。用带标签的构造可以在构造期间就清零，语义更清晰。

**实际场景**：新建节点时（`MEM_new<T>` 之后想清空所有字段）。

## ShallowDataConstRef：一个只借不还的包装

```cpp
namespace dna::internal {

template<class T> class ShallowDataConstRef {
 public:
  constexpr explicit ShallowDataConstRef(const T &ref) : ref_(ref) {}

  const T *get_pointer() const
  {
    return &ref_;
  }

 private:
  const T &ref_;
};

class ShallowZeroInitializeTag {};

}
```

`[讲解]` 解析：

| 特征 | 说明 |
| --- | --- |
| `explicit` | 必须显式构造，不能隐式转换（防止误用） |
| 只持有 `const T&` | 不拥有、不复制，只是"引用" |
| `get_pointer()` | 提供取地址的接口 |
| `ShallowZeroInitializeTag` 是空类 | 纯粹的"类型标签"，零开销 |

`[讲解]` 为什么这里用 `const T&` 而 DNA 结构体又删了拷贝？因为**引用不是拷贝**——它不触发任何拷贝构造函数，只是绑定了地址。

这个技巧叫"**标签分派**"（tag dispatch）：用一个独特类型让编译器选择正确的重载。

## dna::shallow_copy

```cpp
namespace dna {

/* Creates shallow copy of the given object.
 * The entire object is copied as-is using memory copy.
 *
 * Typical usage:
 *   Object temp_object = dna::shallow_copy(*input_object);
 *
 * From the implementation detail go via copy constructor/assign operator defined in the structure.
 */
template<typename T>
[[nodiscard]] inline internal::ShallowDataConstRef<T> shallow_copy(const T &other)
{
  return internal::ShallowDataConstRef(other);
}

}
```

`[讲解]` 就一行：把引用包进 `ShallowDataConstRef`。

**关键理解**：`dna::shallow_copy` 本身**什么都不复制**。它只是构造一个"拷贝源标记"。真正的 `memcpy` 发生在目标对象的构造/赋值时。

`[讲解]` 所以这行：

```cpp
NodeGeometryRepeatOutput temp = dna::shallow_copy(*input);
```

等价于：

```cpp
NodeGeometryRepeatOutput temp(dna::internal::ShallowDataConstRef<NodeGeometryRepeatOutput>(*input));
// → 触发宏里的浅拷贝构造函数
// → 内部 memcpy
```

`[讲解]` `[[nodiscard]]` 很重要：`dna::shallow_copy(x);` 单独一行什么都不做（因为真正的拷贝在赋值时）。加上 `[[nodiscard]]` 让编译器警告这种浪费。

## 语义：浅拷贝到底复制了什么

`[讲解]` 这是最容易误解的地方。`memcpy(sizeof(T))` 复制的是**结构体的字节**，包括：

| 复制 | 不复制 |
| --- | --- |
| 所有 POD 字段（int、float、enum） | 指针**指向的内容** |
| 指针的**值**（地址） | 堆上的数组/字符串 |

`[讲解]` 所以浅拷贝之后：

```text
src:
  items       ──→ [Item0, Item1]   （堆上）
  items_num   = 2

dst（浅拷贝后）:
  items       ──→ 同一个 [Item0, Item1]   ← 共享！
  items_num   = 2
```

`[讲解]` 两个结构体共享同一块堆内存。这正是"不安全"的来源——所以宏才删除普通拷贝。

## Repeat 的 node_copy_storage：先浅后深

`[讲解]` 现在看实际用法。正篇 02-01 的代码：

```cpp
static void node_copy_storage(bNodeTree &dst_tree, bNode *dst_node, const bNode *src_node)
{
  const NodeGeometryRepeatOutput &src_storage = node_storage(*src_node);
  auto *dst_storage = MEM_new<NodeGeometryRepeatOutput>(__func__, dna::shallow_copy(src_storage));
  dst_node->storage = dst_storage;

  socket_items::copy_array<RepeatItemsAccessor>(*src_node, *dst_node);
}
```

`[讲解]` 逐行：

**第 1 行**：拿源 storage 的引用。

**第 2 行**：`MEM_new` 分配 + 构造，参数是 `dna::shallow_copy(src_storage)`。这触发浅拷贝构造：
- 分配 `sizeof(NodeGeometryRepeatOutput)` 字节；
- 调默认构造；
- 触发浅拷贝构造 → memcpy。

**第 3 行**：挂到目标节点上。

**第 4 行**：`copy_array` 做**深拷贝**。

`[讲解]` 第四行是关键。看它的内部（正篇 02-03 讲过）：

```cpp
template<typename Accessor> inline void copy_array(const bNode &src_node, bNode &dst_node)
{
  using ItemT = typename Accessor::ItemT;
  SocketItemsRef src_ref = Accessor::get_items_from_node(const_cast<bNode &>(src_node));
  SocketItemsRef dst_ref = Accessor::get_items_from_node(dst_node);
  const int items_num = *src_ref.items_num;
  *dst_ref.items = MEM_new_array<ItemT>(items_num, __func__);   // 新分配数组
  for (const int i : IndexRange(items_num)) {
    Accessor::copy_item((*src_ref.items)[i], (*dst_ref.items)[i]);  // 逐项深拷贝
  }
}
```

`[讲解]` `copy_array` 做两件事：

1. **重新分配数组**（`MEM_new_array`）—— 覆盖掉浅拷贝带来的共享指针；
2. **逐项 `copy_item`** —— 对 `char *name` 做 `BLI_strdup_null`。

`[讲解]` `BLI_strdup_null` 是深拷贝字符串的关键：它分配新内存、拷贝内容，所以两个 item 的 `name` 指向不同内存。

**两步合起来才是完整拷贝**：

```text
第 1 步（shallow_copy）：结构体字节复制 → items 指针共享
第 2 步（copy_array）：重新分配数组 + 深拷贝每项 → 指针分离
```

`[讲解]` 如果漏掉第 2 步：两个节点共享 items 数组。编辑其中一个的 item 会影响另一个——这就是"复制节点"功能的经典 bug。

## 为什么 NodeRepeatItem 没有这个宏

`[讲解]` 看三个 Repeat 结构的差异：

| 结构 | 有 `DNA_DEFINE_CXX_METHODS`？ | 原因 |
| --- | --- | --- |
| `NodeRepeatItem` | ❌ | 是**数组元素**，由 `copy_item` 逐项深拷贝 |
| `NodeGeometryRepeatInput` | ✅ | 是**节点存储**，会被 `shallow_copy` 复制 |
| `NodeGeometryRepeatOutput` | ✅ | 同上 |

`[讲解]` 判据很清楚：**看到这个宏，就说明该结构体会被整块浅拷贝**。

`NodeRepeatItem` 作为数组元素，用的是另一套路径：

```cpp
static void copy_item(const NodeRepeatItem &src, NodeRepeatItem &dst)
{
  dst = src;                          // 结构体赋值（POD 部分）
  dst.name = BLI_strdup_null(dst.name);  // 深拷名字
}
```

`[讲解]` 这里有 `dst = src` —— 为什么合法？因为 `NodeRepeatItem` 没有删除拷贝。它就是纯 POD（`char*` + enum + int），普通赋值语义清晰。深拷贝由 `copy_item` 手动补上。

## 用小数据走一遍

`[讲解]` 源节点有 2 个 item，`items = 0xA000`：

**第 0 步：初始状态**

```text
src_node.storage:
  items      = 0xA000
  items_num  = 2
  inspection_index = 0

堆: 0xA000 → [ {name:"Geometry", type:SOCK_GEOMETRY, id:0},
               {name:"Radius",   type:SOCK_FLOAT,    id:1} ]
```

**第 1 步：`dna::shallow_copy(src_storage)`**

```text
返回 ShallowDataConstRef{ref_ = src_storage}
（此时什么都没复制）
```

**第 2 步：`MEM_new<...>(..., dna::shallow_copy(...))`**

```text
分配 sizeof(NodeGeometryRepeatOutput) 字节 → 假设地址 0xB000
调默认构造 → 所有字段 = 默认值
调浅拷贝构造 → memcpy(0xB000, &src_storage, sizeof)

dst_node.storage（0xB000）:
  items      = 0xA000    ← 共享！
  items_num  = 2
  inspection_index = 0
```

**第 3 步：`socket_items::copy_array<...>(src, dst)`**

```text
MEM_new_array<NodeRepeatItem>(2) → 假设地址 0xC000
copy_item(items[0]) → dst.name = strdup("Geometry") → 0xD000
copy_item(items[1]) → dst.name = strdup("Radius")   → 0xD100

dst_node.storage:
  items      = 0xC000    ← 已分离
  items_num  = 2

堆:
  0xA000 → [{"Geometry"@0xE000, ..., 0}, {"Radius"@0xE100, ..., 1}]   （源）
  0xC000 → [{"Geometry"@0xD000, ..., 0}, {"Radius"@0xD100, ..., 1}]   （目标）
```

`[讲解]` 最终：两个节点各有独立的 items 数组与独立的 name 字符串。**这才是正确的复制**。

## 反例与边界

### 反例 1：直接 `dst = src`

```cpp
NodeGeometryRepeatOutput dst;
dst = src;   // 编译错误：拷贝赋值被 delete
```

这是一个**好**错误——编译期就挡住了。

### 反例 2：浅拷贝后忘了深拷贝

```cpp
auto *dst = MEM_new<NodeGeometryRepeatOutput>(__func__, dna::shallow_copy(src));
/* 忘了 copy_array */
```

两个节点共享 items 数组。编辑一个影响另一个；析构时 double free。

### 反例 3：以为 `shallow_copy` 会复制字符串

它什么都不复制。字符串共享，直到你手动 strdup。

### 反例 4：在栈上临时对象上用

```cpp
NodeGeometryRepeatOutput temp = dna::shallow_copy(src);
/* temp 离开作用域 → 析构 → 但 items 是共享的，不该被释放 */
```

`[讲解]` 默认析构是 `= default`，所以它**不会**释放 `items`（因为 DNA 结构体的析构不管理堆内存）。这反而安全——但如果你在别处 `MEM_delete(temp.items)` 就错了。

### 反例 5：浅拷贝后修改源

```cpp
auto *dst = MEM_new<...>(..., dna::shallow_copy(src));
src.items[0].identifier = 999;   // 改源
/* 此时 dst.items[0].identifier 也是 999（共享） */
```

在 `copy_array` 之前，两个视图是同一块内存。

### 反例 6：以为零初始化标签能替代默认构造

`ShallowZeroInitializeTag` 清的是**字节**，不调构造函数。对含非 POD 成员的结构体不适用（但 DNA 结构体本来就该是 POD）。

## 对理解 Repeat 的帮助

`[讲解]` 三处直接相关：

| 概念 | Repeat 中的落点 | 正篇位置 |
| --- | --- | --- |
| `DNA_DEFINE_CXX_METHODS` | Input/Output 的声明 | 02-02 |
| `dna::shallow_copy` | `node_copy_storage` 的第一步 | 02-01 L232-L239 |
| `copy_array` 深拷贝 | 第二步（分离指针） | 02-03 |

`[讲解]` 正篇 02-02 有一句准确的总结：

> "浅拷贝 + 修复指针，是 Blender 里处理'DNA 结构含堆指针'的标准两段式。"

本篇就是这句话的完整论证。理解了它，你就明白为什么"复制节点"这个看似简单的操作需要两段——**因为 DNA 层只给浅拷贝这一个原语，深拷贝必须由业务代码补上**。
