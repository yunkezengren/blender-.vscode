# 06 · 操作符与 UI 绘制

[前置知识总入口](../README.md) · [本章导航](README.md) · [上一篇](05-拓扑缓存与更新传播.md) · [下一章](../11-观察与调度/README.md)

> 基准：Blender `5.4.0-alpha`，本地工作树。本篇讲节点系统与 UI 的两条交互通道：**绘制**（怎么画）与**操作符**（点了之后干什么）。Repeat 的 item 列表、加号按钮、inspection_index 输入框都靠它们。主要源码：[`node_geo_repeat.cc`](../../../source/blender/nodes/geometry/nodes/node_geo_repeat.cc)（`node_layout_ex` 在 L34-L66）、[`NOD_socket_items_ui.hh`](../../../source/blender/nodes/NOD_socket_items_ui.hh)（`draw_items_list_with_operators` L58、`draw_active_item_props` L107、`draw_extend_socket_fn` L128）。

## 先回答一个具体问题

Repeat 节点面板上那个 "Repeat Items" 列表和加号按钮，是哪段代码画的？点了加号之后发生什么？

`[讲解]` 两个答案：

- **画**：`node_layout_ex`（L34-L66）
- **点击后**：一个操作符（`NODE_OT_repeat_zone_item_add`）

本篇把两条线都走一遍。

## 两条通道的分工

`[讲解]` UI 与数据的两类交互：

| 通道 | 方向 | 能改数据吗 | 典型入口 |
| --- | --- | --- | --- |
| 绘制 | 数据 → 屏幕 | ❌ 只读 | `draw_buttons_ex` |
| 操作符 | 用户 → 数据 | ✅ 改 | `NODE_OT_*` |

`[讲解]` **绘制回调不允许改数据**——这是硬约束。如果它改了，后果是：

- 每次重绘都改一次（可能无限循环）；
- 撤销系统无法追踪。

所以绘制里的所有"看起来像编辑"的操作，实际都是**触发操作符**。

## node_layout_ex 逐段读

`[讲解]` 完整源码（L34-L66）：

```cpp
static void node_layout_ex(ui::Layout &layout, bContext *C, PointerRNA *current_node_ptr)
{
  bNodeTree &ntree = *reinterpret_cast<bNodeTree *>(current_node_ptr->owner_id);
  bNode *current_node = static_cast<bNode *>(current_node_ptr->data);

  const bke::bNodeTreeZones *zones = ntree.zones();
  if (!zones) { return; }

  const bke::bNodeTreeZone *zone = zones->get_zone_by_node(current_node->identifier);
  if (!zone) { return; }

  if (!zone->output_node_id) { return; }

  bNode &output_node = const_cast<bNode &>(*zone->output_node());
  PointerRNA output_node_ptr = RNA_pointer_create_discrete(
      current_node_ptr->owner_id, RNA_Node, &output_node);

  if (ui::Layout *panel = layout.panel(C, "repeat_items", false, IFACE_("Repeat Items"))) {
    socket_items::ui::draw_items_list_with_operators<RepeatItemsAccessor>(
        C, panel, ntree, output_node);
    socket_items::ui::draw_active_item_props<RepeatItemsAccessor>(
        ntree, output_node, [&](PointerRNA *item_ptr) {
          panel->use_property_split_set(true);
          panel->use_property_decorate_set(false);
          panel->prop(item_ptr, "socket_type", UI_ITEM_NONE, std::nullopt, ICON_NONE);
        });
  }

  layout.prop(&output_node_ptr, "inspection_index", UI_ITEM_NONE, std::nullopt, ICON_NONE);
}
```

`[讲解]` 分五段：

### 第 1 段：取上下文

```cpp
bNodeTree &ntree = *reinterpret_cast<bNodeTree *>(current_node_ptr->owner_id);
bNode *current_node = static_cast<bNode *>(current_node_ptr->data);
```

`[讲解]` 从 `PointerRNA` 里拆出两样东西：

- `owner_id` → 节点树（RNA 的 owner 是 ID）；
- `data` → 当前节点。

**这是 RNA 的典型用法**：`PointerRNA` 携带 owner + data，回调里再拆。

### 第 2 段：三层防御查找

```cpp
const bke::bNodeTreeZones *zones = ntree.zones();
if (!zones) { return; }

const bke::bNodeTreeZone *zone = zones->get_zone_by_node(current_node->identifier);
if (!zone) { return; }

if (!zone->output_node_id) { return; }
```

`[讲解]` **三层 if 是防御式设计的典范**：

| 检查 | 失败意味着 |
| --- | --- |
| `zones` 为空 | 树还没分析过 zone（未更新） |
| `zone` 为空 | 这个节点不在任何 zone 里 |
| `output_node_id` 为 0 | zone 残缺（配对失败，见 01-01） |

`[讲解]` 每个失败都**静默返回**（不画任何东西）。这是 UI 代码的常见做法：宁可少画，不要崩。

### 第 3 段：跨节点取 output

```cpp
bNode &output_node = const_cast<bNode &>(*zone->output_node());
PointerRNA output_node_ptr = RNA_pointer_create_discrete(
    current_node_ptr->owner_id, RNA_Node, &output_node);
```

`[讲解]` 三个要点：

1. **`const_cast`** —— `zone->output_node()` 返回 const，但 RNA 构造需要非 const；
2. **`RNA_pointer_create_discrete`** —— 创建一个指向 output 的 RNA 指针（见 07-01）；
3. **owner 仍是同一棵树** —— 因为 output 也在同一棵树里。

`[讲解]` **这就是"在 Input 上改 Output 数据"的实现**：`node_layout_ex` 被两个节点共用，但所有数据操作都落到 `output_node`。

### 第 4 段：面板内的两个绘制

```cpp
if (ui::Layout *panel = layout.panel(C, "repeat_items", false, IFACE_("Repeat Items"))) {
  socket_items::ui::draw_items_list_with_operators<RepeatItemsAccessor>(
      C, panel, ntree, output_node);
  socket_items::ui::draw_active_item_props<RepeatItemsAccessor>(
      ntree, output_node, [&](PointerRNA *item_ptr) {
        panel->use_property_split_set(true);
        panel->use_property_decorate_set(false);
        panel->prop(item_ptr, "socket_type", UI_ITEM_NONE, std::nullopt, ICON_NONE);
      });
}
```

`[讲解]` `layout.panel(...)` 的语义：

- 返回一个 `Layout*`，**只有面板展开时才非空**；
- 所以面板收起时两个 draw 都不执行（性能优化）。

`[讲解]` 两个 draw 的分工：

| 函数 | 画什么 |
| --- | --- |
| `draw_items_list_with_operators` | 列表 + 加/删/移动按钮 |
| `draw_active_item_props` | 当前活动项的属性（这里只画 `socket_type`） |

`[讲解]` 第二个的回调参数 `item_ptr` 是"活动项的 PointerRNA"——因为 item 是数组元素，需要 RNA 包装才能画属性。

### 第 5 段：面板外的 inspection_index

```cpp
layout.prop(&output_node_ptr, "inspection_index", UI_ITEM_NONE, std::nullopt, ICON_NONE);
```

`[讲解]` 注意它在 `if` **外面**——面板收起也显示。

`[讲解]` **为什么 inspection_index 单独画？** 因为它不是 item 属性，是 Output 节点自身的字段。而且它需要一直可见（用户随时可能切换轮次）。

## 三个 socket_items::ui 函数

`[讲解]` 从源码（`NOD_socket_items_ui.hh`）：

### draw_items_list_with_operators（L58）

```cpp
template<typename Accessor>
static void draw_items_list_with_operators(const bContext *C,
                                          blender::ui::Layout *layout,
                                          const bNodeTree &tree,
                                          const bNode &node)
```

`[讲解]` 做三件事（推测 + 源码印证）：

1. 画 `uiList`（用 `Accessor::ui_idnames::list`）；
2. 画下面的按钮行（加/删/上移/下移）；
3. 按钮绑到 `Accessor::operator_idnames` 里的三个操作符。

### draw_active_item_props（L107）

```cpp
template<typename Accessor>
static void draw_active_item_props(const bNodeTree &tree,
                                   const bNode &node,
                                   const FunctionRef<void(PointerRNA *item_ptr)> draw_item)
```

`[讲解]` 逻辑：

```text
1. 取 active_index
2. 越界或 -1 → 什么都不画
3. 否则：用 Accessor::item_srna 把 item 包成 PointerRNA
4. 回调 draw_item(item_ptr)
```

`[讲解]` **`item_srna` 的作用就在这里**（07-02 讲过）：把 C 结构体包装成 RNA 类型，才能画属性。

### draw_extend_socket_fn（L128）


`[讲解]` 这是 `__extend__` socket 的自定义绘制——画成一个**加号按钮**，点击触发 "add item"。

## 操作符的四个动作

`[讲解]` `NOD_socket_items_ops.hh` 里 `make_common_operators` 生成四个操作符：

| 操作符 | 作用 |
| --- | --- |
| `NODE_OT_repeat_zone_item_add` | 加一个 item |
| `NODE_OT_repeat_zone_item_remove` | 删当前 item |
| `NODE_OT_repeat_zone_item_move` | 上移/下移 |

`[讲解]` 每个 exec 大致做：

```text
1. 从 context 找到目标节点（Output）
2. 用 Accessor 操作 items 数组（add/remove/move）
3. 调 update_node_declaration_and_sockets
4. 打 BKE_ntree_update_tag_node_property
5. 通知 UI 重绘
```

`[讲解]` **第 3、4 步是关键**：改数组不会自动让 socket 变化，必须显式触发声明重建。

## 为什么操作符不直接改 DNA

`[讲解]` 操作符通过 **RNA** 访问数据，不是直接操作 DNA 数组。

原因：

1. **撤销系统**依赖 RNA 的变更追踪；
2. **Python 脚本**用同样的 RNA 接口；
3. **类型安全**（RNA 会检查范围）。

`[讲解]` 所以 `NODE_OT_repeat_zone_item_add` 的 exec 里会调类似：

```cpp
socket_items::add_item<RepeatItemsAccessor>(*node, socket_type, name);
```

这个 `add_item` 内部操作 DNA 数组，但它封装在 `socket_items` 框架里（见 02-03）。

## 用小数据走一遍

`[讲解]` 用户点 "+" 按钮的完整链路：

| 步 | 发生什么 |
| --- | --- |
| 1 | 用户点击（button 由 `draw_extend_socket_fn` 画） |
| 2 | Blender 派发 `NODE_OT_repeat_zone_item_add` |
| 3 | 操作符 exec：找到 Output 节点 |
| 4 | 调 `socket_items::add_item<...>` → 数组追加一项 |
| 5 | 分配新 identifier（`next_identifier++`） |
| 6 | `update_node_declaration_and_sockets` |
| 7 | `BKE_ntree_update_tag_node_property` |
| 8 | 树更新 → `node_declare` 重跑 → 新 socket 出现 |
| 9 | `refresh_node_socket` 按 identifier 复用旧 socket |
| 10 | UI 重绘 → 列表多一行、面板多一对 socket |

`[讲解]` 第 6、7 步是**最容易漏的**。如果只改数组不打标，socket 不会出现。

## 反例与边界

### 反例 1：在 Input 上直接读自己的 storage

```cpp
/* 错误 */
const NodeGeometryRepeatInput &s = node_storage(*node);
const NodeGeometryRepeatOutput &os = ... /* 这里 Input 没有 items */
```

Input 的 storage 只有 `output_node_id`。items 在 Output 上。

### 反例 2：操作符里改数组但不更新树

新 item 有了但 socket 没变——用户看不到。

### 反例 3：在 draw 回调里改数据

违反只读约束，会导致重绘风暴或撤销混乱。

### 反例 4：忘了 `layout.panel` 的展开检查

```cpp
/* 错误：面板收起时也画 */
socket_items::ui::draw_items_list_with_operators<...>(...);
```

`layout.panel()` 返回 nullptr 时要跳过。

### 反例 5：以为 `node_layout_ex` 只给 Output 用

它被两个节点共用，所以内部必须能处理"当前是 Input"的情况（靠 zone 反查 Output）。

### 反例 6：忘记 `const_cast`

`zone->output_node()` 返回 const，RNA 需要非 const。

## 对理解 Repeat 的帮助

`[讲解]` 本篇把正篇 02-01 的 `node_layout_ex` 与 02-03 的 `draw_*` 系列讲透：

| 正篇代码 | 本篇概念 |
| --- | --- |
| `ntree.zones()` | zone 分析结果（01-01） |
| `zone->output_node_id` | 配对 id（01-01） |
| `RNA_pointer_create_discrete` | 跨节点 RNA 指针（07-01） |
| `draw_items_list_with_operators` | 列表 + 按钮 |
| `draw_extend_socket_fn` | "+" 按钮 |
| `inspection_index` 的单独绘制 | 面板外属性 |

`[讲解]` **最关键的一条**：Repeat 的 UI 之所以能在 **Input 节点上编辑 Output 节点的数据**，是因为 `node_layout_ex` 先通过 zone 反查 Output，然后把所有操作都指向它。

这个设计的代价是：UI 代码必须处理"当前节点不是 Output"的情况（三层防御查找）。
