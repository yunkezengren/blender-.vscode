# 04 · 移动语义与内存布局

[前置知识总入口](../README.md) · [本章导航](README.md) · [上一篇](03-类型转换与访问接口.md) · [下一章](../09-几何数据与引用/README.md)

> 基准：Blender `5.4.0-alpha`，本地工作树。本篇讲 `SocketValueVariant` 的内存布局与移动/拷贝语义——为什么 `Array<SocketValueVariant>` 能预分配复用、为什么移动比拷贝便宜一个量级。主要源码：[`BLI_any.hh`](../../../source/blender/blenlib/BLI_any.hh)（总行数 408）、[`BKE_node_socket_value.hh`](../../../source/blender/blenkernel/BKE_node_socket_value.hh)（总行数 434）。

## 先回答一个具体问题

正篇 03-03 的这段代码：

```cpp
eval_storage.index_values.reinitialize(iterations);
threading::parallel_for(IndexRange(iterations), 1024, [&](const IndexRange range) {
  for (const int i : range) {
    eval_storage.index_values[i].emplace<int>(i);
  }
});
```

`reinitialize` 先造出 N 个**空 variant**，再对每个**就地 emplace**。问：

1. 空 variant 占多少堆内存？
2. `emplace<int>` 时要不要先析构旧值？
3. 这一整段会发生几次堆分配？

直觉答案"每次装值都要分配一次"是错的。答案藏在 `Any` 的存储布局里。

## Any 的对象布局

`[讲解]` `SocketValueVariant` 的唯一成员（02 篇）：

```cpp
using SocketValueVariantAny = Any<SocketValueVariantTypeInfo, 32, 16>;
```

`[讲解]` `Any` 模板的参数定义（`BLI_any.hh` L100-L107 附近）：

```cpp
template<typename ExtraInfo = void,
         size_t InlineBufferCapacity = 8,
         size_t Alignment = 8,
         typename ExtraData = blenlib_detail::EmptyType>
class Any {
```

| 实参 | 值 | 含义 |
| --- | --- | --- |
| `ExtraInfo` | `SocketValueVariantTypeInfo` | 随值存放的额外类型信息（CPPType 引用、convert_to/is_interpretable_as 函数指针、storage_kind） |
| `InlineBufferCapacity` | 32 | 内联缓冲区容量 |
| `Alignment` | 16 | 缓冲区对齐要求 |

`[讲解]` 内部字段（实测 L107-L135）：

```cpp
  static constexpr size_t RealInlineBufferCapacity = std::max(InlineBufferCapacity,
                                                              sizeof(std::unique_ptr<int>));

  /**
   * Inline buffer that either contains nothing, the stored value directly, or a #std::unique_ptr
   * to the value.
   */
  AlignedBuffer<RealInlineBufferCapacity, Alignment> buffer_;

  /** Information about the type that is currently stored.
   * This is null when the #Any does not contain a value. */
  const Info *info_ = nullptr;
```

`[讲解]` 三个要点：

1. **布局 = `buffer_`（32 字节）+ `info_`（8 字节指针）**，对象本体约 40-48 字节（`extra` 字段可能借对齐 padding 存放，`BLI_NO_UNIQUE_ADDRESS`）；
2. **`buffer_` 三态**（注释原话）：空 / 直接存值 / 存 `unique_ptr`——**第三种情况里，智能指针本身就在内联缓冲里**，堆上只有值；
3. **`RealInlineBufferCapacity = max(请求值, sizeof(unique_ptr))`**——缓冲至少装得下一个指针，这是"间接存储"的下限保证。
4. **空态判据是 `info_ == nullptr`**——"空 variant"不需要任何特殊字节，就是 `info_` 为 null。

## 内联还是堆：编译期二选一

`[讲解]` `BLI_any.hh` L38-L70 有两张类型信息模板，注册时按类型选一张：

```cpp
/** Used when #T is stored directly in the inline buffer of the #Any. */
template<typename ExtraInfo, typename T>
inline AnyTypeInfo<ExtraInfo> info_for_inline = {
    is_trivially_copy_constructible_extended_v<T> ?
        nullptr :
        +[](void *dst, const void *src) { new (dst) T(*static_cast<const T *>(src)); },
    is_trivially_move_constructible_extended_v<T> ?
        nullptr :
        +[](void *dst, void *src) { new (dst) T(std::move(*static_cast<T *>(src))); },
    is_trivially_destructible_extended_v<T> ?
        nullptr :
        +[](void *src) { std::destroy_at((static_cast<T *>(src))); },
    nullptr,
    ExtraInfo::template get<T>()};

/** Used when #T can't be stored directly in the inline buffer and is stored in a #std::unique_ptr
 * instead. In this scenario, the #std::unique_ptr is stored in the inline buffer. */
template<typename T> using Ptr = std::unique_ptr<T>;
template<typename ExtraInfo, typename T>
inline AnyTypeInfo<ExtraInfo> info_for_unique_ptr = {
    [](void *dst, const void *src) { new (dst) Ptr<T>(new T(**static_cast<const Ptr<T> *>(src))); },
    [](void *dst, void *src) { new (dst) Ptr<T>(new T(std::move(**static_cast<Ptr<T> *>(src)))); },
    [](void *src) { std::destroy_at(static_cast<Ptr<T> *>(src)); },
    [](const void *src) -> const void * { return &**static_cast<const Ptr<T> *>(src); },
    ExtraInfo::template get<T>()};
```

`[讲解]` 对照读，这是全篇最密的两段：

| 函数指针 | 内联 + trivial | 内联 + 非 trivial | 堆（unique_ptr） |
| --- | --- | --- | --- |
| `copy_construct` | **nullptr** | 调 T 拷贝构造 | **永远非空**：`new T(**src)` —— 堆上再复制一份 |
| `move_construct` | **nullptr** | 调 T 移动构造 | `new T(std::move(**src))` —— 转移内容但**仍分配** |
| `destruct` | **nullptr** | 调 `destroy_at` | 销毁智能指针（连带 free） |
| `get` | nullptr（直接 reinterpret） | nullptr | **解引用一次**：`&**ptr` |

`[讲解]` 两个必须纠正的直觉：

**第一，`nullptr` 不是"没实现"，是"走 memcpy"。** 看拷贝构造（L166-L177）：

```cpp
Any(const Any &other) : extra(other.extra), info_(other.info_)
{
  if (info_ != nullptr) {
    if (info_->copy_construct != nullptr) {
      info_->copy_construct(&buffer_, &other.buffer_);
    }
    else {
      std::copy_n(static_cast<const std::byte *>(other.buffer_.ptr()),
                  RealInlineBufferCapacity,
                  static_cast<std::byte *>(buffer_.ptr()));
    }
  }
}
```

`copy_construct == nullptr` 意味着"这个类型平凡可拷贝"，直接 `copy_n` 拷整块缓冲——**trivial 类型的拷贝比调函数还快**（这就是 01 篇 CPPType"函数指针复用同一地址"优化在 Any 层的回声）。

**第二，堆存类型的 move 也是分配。** `info_for_unique_ptr` 的移动构造是 `new T(std::move(**src))`——**新建一块堆内存再做移动构造**，不是偷指针！因为多个 `Any` 的缓冲里各有一个 `unique_ptr`，直接偷会把同一 `unique_ptr` 复制两份造成双删。这是 `Any` 语义的诚实代价：移动只省掉"值的拷贝"，省不掉"指针的分配"。

## 移动后源对象是什么状态

`[讲解]` 移动构造的注释（L180-L181）：

> "\note The #other #Any will not be empty afterwards if it was not before. Just its value is in a moved-from state."

`[讲解]` 精确解读：移动之后，源 `Any` 的 `info_` **保留**（还是那个类型），但缓冲里的值进入 moved-from 态（对 trivial 类型就是字节被原样复制过去了，源字节还在；对 `std::string` 是空串；对 `unique_ptr` 包装是"指针还指向一个 moved-from 的 T"）。

`[讲解]` 推论——回答标题里的问题：源对象**不是空 variant**，它还能被析构（info_ 在，destruct 会正常调用），只是**值不可信**。"移动后只能重新赋值或销毁，不能读"在 `Any` 上是同一条纪律，但机制不同：不是"未定义"，是"合法但无意义"。

## 析构与赋值分派

`[讲解]` 析构路径（与拷贝对称）：`info_->destruct != nullptr` 才调；trivial 直接什么都不做——**空 variant 和 int variant 的析构成本都是零**。

`[讲解]` 赋值（`emplace`/`operator=`）的内部次序：先对旧值调 `destruct`，再构造新值，必要时换 `info_`。`SocketValueVariant::emplace<T>`（02 篇 L255-L260）经 `Any::emplace` 转成 `Any(std::in_place_type<T>, ...)` 的替换。

`[讲解]` 于是开头三问有了答案：

| 问题 | 答案 | 依据 |
| --- | --- | --- |
| 空 variant 占多少堆 | **0 字节**（就是个 40 来字节的栈/数组槽位，`info_=null`） | 布局三态 |
| emplace 要不要析构旧值 | 要"调析构"，但旧值是空的 → `destruct==nullptr` 跳过；即便有值，int 的析构也是 nullptr | info_for_inline 的三目 |
| N 次 emplace<int> 几次堆分配 | **0 次**。int trivially copyable 且 ≤32 字节 → 内联，写 4 字节 + 记 info_ 指针 | 同上 |

`reinitialize(N)` 本身倒是可能分配——`Array<SocketValueVariant>` 要为 N×40 字节找一块缓冲。但那是**一次**分配，与 iterations 无关的细节：variant 数组本身是连续内存，这正是预分配复用的全部秘密。

## 32 与 16 这两个数字

`[讲解]` `Any<SocketValueVariantTypeInfo, 32, 16>` 的选择依据（推断 + 佐证，标注确定性）：

**32 = 内联容量**：

- `float3`=12、`float4`=16、`int`=4、`bool`=1、`GField`=（指针级，约 8-16）都放得下；
- `std::string`（MSVC）= 32 ——**恰好压线内联**（libstdc++ 的 32 也恰好）；
- `GeometrySet` 组件向量远超 32 → 走 `unique_ptr` 间接。

**16 = 对齐**：`float4`/`Alignment`≥16 的 SIMD 载荷能内联存放，`AlignedBuffer<32,16>` 直接满足对齐要求，不会触发"对齐不足转堆"。

`[讲解]` 注意 `RealInlineBufferCapacity = max(32, sizeof(unique_ptr))` = max(32, 8) = **32**——指针下限条款在此不生效，但设计者留着它是为了让容量小于 8 的 `Any` 也能间接存储。

## 与 GeometrySet 通道的关系

`[讲解]` 两层语义叠加，这是本章与 09 章的接缝：

```text
第一层（Any）：GeometrySet 太大放不下内联 → buffer_ 里存 unique_ptr<GeometrySet> → 堆上真身
第二层（ImplicitSharingPtr）：GeometrySet 内部只存组件的共享指针 → "复制"只加引用计数
```

`[讲解]` 所以"每轮传几何很便宜"的完整成本是：

| 动作 | 成本 |
| --- | --- |
| 拷贝 `SocketValueVariant(GeometrySet)` | 一次 `new GeometrySet`（堆分配）+ 拷贝构造：复制组件指针数组 + 每个组件引用计数 +1 |
| 之后组件数据本身 | **0**（这正是 09 章 02 篇的结论） |

即：**Any 层收一次"壳"的分配费，数据层的共享红利归 09 章解释**。两层都在，缺一不可。

## 用小数据走一遍

`[讲解]` `Array<SocketValueVariant>` 预分配 3 个槽，依次装 `int 42`、`float3 {1,2,3}`、`GeometrySet`。

**初始（reinitialize(3) 之后）**：

```text
槽0: [32 字节垃圾或零][info_=null]
槽1: [32 字节垃圾或零][info_=null]
槽2: [32 字节垃圾或零][info_=null]
堆分配：0（数组连续缓冲 1 次，Array 的活儿）
```

**emplace<int>(42)**：

```text
槽0 缓冲字节 0..3 ← 42
     info_ = &info_for_inline<Int>  （全局静态地址）
堆分配：0
```

**emplace<float3>**：

```text
槽1 缓冲字节 0..11 ← {1,2,3}
     info_ = &info_for_inline<float3>
堆分配：0
```

**emplace<GeometrySet>**：

```text
堆: p = new GeometrySet(...)
槽2 缓冲字节 0..7 ← p（unique_ptr 值）
     info_ = &info_for_unique_ptr<GeometrySet>
堆分配：1
```

**整个数组销毁**：

```text
槽0: destruct==nullptr → 跳过
槽1: 同上
槽2: unique_ptr 析构 → delete p
堆分配：净 0
```

`[讲解]` 三轮循环如果每轮都 emplace int，**零分配**贯穿到底——这就是正篇说"预分配 + 就地构造省掉 N 次分配"的字节级含义。

## 反例与边界

**1. 以为 `sizeof(SocketValueVariant)` 随装的类型变。** 恒定 = 缓冲 + 指针 + 类型信息 + 对齐 padding（约 48-64 字节）。`Array<variant>` 装 int 和装 GeometrySet 占的槽宽一样——这是"空间换零分配与地址稳定"的明示交易。

**2. 以为移动后源对象变空。** 注释原话否定：源仍是同类型、值在 moved-from 态、析构照常发生。想清空要显式 `clear()` 或赋空 variant。

**3. 以为堆存类型的移动不分配。** `info_for_unique_ptr` 的移动**必分配**（见上文加粗条款）。真正免分配的移动只存在于内联 + trivial 组合。

**4. 在 32 字节边界上赌 `std::string`。** MSVC/libstdc++ 恰好 32 内联；libc++ 是 24 也内联；但若换 `std::pmr::string`（40 字节）立刻转堆。**容量假设随实现漂移，别在热路径依赖"string 零分配"**。

**5. 给 variant 装不可拷贝的类型。** `is_allowed_v` 明写 `std::is_copy_constructible_v<T>`——不可拷贝 = 编译失败。variant 的全部语义建立在"拷贝构造存在"上。

**6. 存了超过 `InlineBufferCapacity` 又小于 `unique_ptr` 下限的值？** 不存在这种情况——`max(..., sizeof(unique_ptr))` 保证间接指针永远放得下。

**7. 以为 `extra`（SocketValueVariantTypeInfo）在堆上。** 它是 `Any` 的公开成员 `extra`，与缓冲同体；`info_` 指向的是**全局静态**的 `AnyTypeInfo`。空 variant 的 `extra` 未定义——读 `storage_kind()` 前先判类型存在。

## 对理解 Repeat 的帮助

| 正篇位置 | 本篇机制 |
| --- | --- |
| 03-03 `index_values.reinitialize + emplace` | 空槽零分配；int 全程内联，N 轮零堆分配 |
| 03-03 `static_unused_index` 静态哨兵 | 一次 emplace 的字节账（4 字节 + 静态 info_） |
| 06-02 "传几何便宜" | Any 收一次壳分配，09 章解释数据共享；两级合看才是完整成本 |
| 06-02 移动开销对比 | 内联 trivial 移动 = 32 字节 copy_n；堆存移动仍分配 |

`[讲解]` **一句话收束**：`SocketValueVariant` 的性能承诺不是"快"，而是**成本可预算**——每个槽固定宽、空槽零堆、int 级数据零分配、大对象恰好一次间接。`Array<SocketValueVariant>` 预分配复用之所以成立，是因为这些预算在编译期就写死在 `Any<…, 32, 16>` 的类型参数里。
