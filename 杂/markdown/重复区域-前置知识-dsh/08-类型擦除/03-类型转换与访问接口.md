# 03 · 类型转换与访问接口

[前置知识总入口](../README.md) · [本章导航](README.md) · [上一篇](02-SocketValueVariant.md) · [下一篇](04-移动语义与内存布局.md)

> 基准：Blender `5.4.0-alpha`，本地工作树。本篇讲 `SocketValueVariant` 的访问接口——`emplace` / `ensure_type` / `extract` / `is_*` 系列。这些是正篇里出现频率最高的调用。主要源码：[`BKE_node_socket_value.hh`](../../../source/blender/blenkernel/BKE_node_socket_value.hh)（实测 434 行）L140-L410。

## 先回答一个具体问题

正篇 03-03 这行代码到底做了什么？

```cpp
params.get_input<SocketValueVariant>(zone_info_.indices.inputs.main[0])
    .ensure_type<int>()
```

`[讲解]` 分三步：

1. `get_input<SocketValueVariant>(...)` —— 从 `Params` 拿到 variant 的**引用**；
2. `.ensure_type<int>()` —— 把 variant **转换**成 int，返回 `int&`；
3. 外面套 `std::max<int>(0, ...)` —— 钳位。

本篇聚焦第 2 步。

## 接口全表

`[讲解]` 从源码（L140-L410）提炼出的九个接口：

| 接口 | 返回 | 语义 | 失败会怎样 |
| --- | --- | --- | --- |
| `emplace<T>(args)` | `T&` | 就地构造 | — |
| `ensure_type<T>()` | `T&` | 转换并返回引用 | 断言 |
| `ensure_type(const CPPType&)` | `void*` | 运行时类型版 | 断言 |
| `extract<T>()` | `T` | 取出并 move | 断言 |
| `is_field()` | `bool` | 是否 Field 形态 | — |
| `is_single()` | `bool` | 是否 Single 形态 | — |
| `is_type<T>()` | `bool` | 是否某类型 | — |
| `get<T>()` | `const T*` | 尝试取指针 | 返回 nullptr |
| `try_get<T>()` | `const T*` | 同上（可能重载不同名） | 返回 nullptr |

`[讲解]` 三个关键区分：

1. **`ensure_*` 会转换**（可能失败断言）；
2. **`get`/`try_get` 不转换**（类型不符返回 nullptr）；
3. **`extract` 会 move**（取出后 variant 变空）。

## emplace：就地构造

`[讲解]` 源码（L255-L260）：

```cpp
template<typename T, typename... Args> inline T &SocketValueVariant::emplace(Args &&...args)
{
  using StorageT = to_storage_type<T>;
  StorageT &value = value_.emplace<StorageT>(T(std::forward<Args>(args)...));
  ...
}
```

`[讲解]` 三步：

1. `to_storage_type<T>` 把 typed 类型映射成 generic（比如 `Field<int>` → `GField`）；
2. `value_.emplace<StorageT>(...)` 在 `Any` 里就地构造；
3. 返回引用。

`[讲解]` **正篇的用法**：

```cpp
eval_storage.index_values[i].emplace<int>(i);
```

这行在**已经构造过**的 variant 上就地赋值（`Array::reinitialize` 已默认构造每个元素）。因为 int 内联（4 字节 < 32），**零堆分配**。

## ensure_type：转换并返回引用

`[讲解]` 源码（L304-L310）：

```cpp
template<typename T> inline T &SocketValueVariant::ensure_type()
{
  T *value = this->try_get_type<T>();
  BLI_assert(value != nullptr);
  return *value;
}
```

`[讲解]` 核心是 `try_get_type<T>()`（L272-L290），它的逻辑是全篇最值得读的部分：

```cpp
template<typename T> T *try_get_type()
{
  using StorageT = to_storage_type<T>;

  /* 快路径 1：存储类型相同，零转换 */
  if (value_.type() == CPPType::get<StorageT>()) {
    return &reinterpret_cast<T &>(value_.get<StorageT>());
  }

  /* 快路径 2：可解释为（布局相同） */
  if (value_.extra_info().is_interpretable_as(CPPType::get<T>(), value_)) {
    return &reinterpret_cast<T &>(value_.get<StorageT>());
  }

  /* 慢路径：真转换 */
  const CPPType &requested_type = CPPType::get<T>();
  if (value_.extra_info().convert_to(requested_type, value_)) {
    return &reinterpret_cast<T &>(value_.get<StorageT>());
  }
  return nullptr;
}
```

`[讲解]` 三级查找，这是性能设计的核心：

### 第 1 级：完全相同

```cpp
if (value_.type() == CPPType::get<StorageT>())
```

`[讲解]` 只是**一次指针比较**。如果 `SocketValueVariant` 里装的就是 int，取 int 就走这条——**零成本**。

### 第 2 级：可解释

```cpp
if (value_.extra_info().is_interpretable_as(...))
```

`[讲解]` 用于泛型投影：`GField` ↔ `Field<int>`。布局相同，`reinterpret_cast` 即可。

**为什么这需要单独一级？** 因为 `value_.type()` 是 `GField`，而请求 `Field<int>`——第 1 级不匹配。但它们布局相同，可以直接当另一种看。

### 第 3 级：真转换

```cpp
if (value_.extra_info().convert_to(requested_type, value_))
```

`[讲解]` 会**改数据**。比如 variant 里是 float 1.5，请求 int——转换成 1。

**注意**：`convert_to` 会**就地修改** `value_`。所以这次转换是**破坏性**的：之后 variant 里就是 int 了，不再是 float。

`[讲解]` 这是个重要细节：`ensure_type` 不是"只读查询"，它可能改变 variant 的内容。如果之后还要按 float 用，就丢了精度。

### 三级失败的处理

`[讲解]` 三级都失败返回 nullptr。`ensure_type` 断言 `!= nullptr`。

所以：

```cpp
.ensure_type<int>()   // 类型不兼容 → 断言崩溃（Debug）/ 未定义（Release）
```

**这就是为什么正篇说"上游构建器保证这个 socket 一定是 int"**——它是内部一致性检查，不是用户输入校验。

## ensure_type 的运行时版

`[讲解]` L312 附近还有：

```cpp
void *ensure_type(const CPPType &type);
```

`[讲解]` 当类型是运行时值（`CPPType`）而不是模板参数时用。

**场景**：通用的节点执行代码，不知道具体类型，只知道 `CPPType`（比如从 socket 声明里读出来的）。

## extract：取出并 move

`[讲解]` 源码（L172）：

```cpp
template<typename T> T extract();
```

注释（L162）说："Equivalent to calling #extract<T>() on a copy of this value."

`[讲解]` 实际实现（L326 附近）：

```cpp
T copy = this->ensure_type<T>();   /* 或类似 */
return copy.extract<T>();
```

`[讲解]` 语义：

| 接口 | variant 之后的状态 |
| --- | --- |
| `ensure_type<T>()` | 不变（可能被转换） |
| `extract<T>()` | **变空**（值被移走） |

**用途**：当你确定这个 variant 用完就不需要了，`extract` 避免一次拷贝。

## is_field / is_single：形态查询

`[讲解]` 源码（L394-L405）：

```cpp
inline bool SocketValueVariant::is_single() const
{
  return value_.extra_info().storage_kind == SocketValueStorageKind::Single;
}

inline bool SocketValueVariant::is_field() const
{
  return value_.extra_info().storage_kind == SocketValueStorageKind::Field;
}
```

`[讲解]` 只是查 `storage_kind` 字段。O(1)。

**正篇/节点代码里的用途**：区分"常量输入"与"field 输入"，决定执行策略。

比如 Set Position 节点：
- 如果偏移是 Single → 所有点加同一个值；
- 如果偏移是 Field → 逐点求值。

`[讲解]` 这个分支是几何节点性能的关键——**能用 Single 就不用 Field**。

## get / try_get：不转换的查询

`[讲解]` 源码（L341-L350）：

```cpp
template<typename T> const T *try_get() const
{
  using StorageT = to_storage_type<T>;
  const Info &info = value_.extra_info();
  if (!info.is_interpretable_as(CPPType::get<T>(), value_)) {
    return nullptr;
  }
  if (value_.type() == CPPType::get<StorageT>()) {
    return reinterpret_cast<const T *>(&value_.get<StorageT>());
  }
  return &value_.get<StorageT>();
}
```

`[讲解]` 与 `ensure_type` 的关键差异：**不调 `convert_to`**。

所以：

- 类型相同 → 返回指针；
- 可解释 → 返回指针；
- 需要转换 → **返回 nullptr**（不像 ensure_type 那样转换）。

**用途**：想检查"有没有可能是这个类型"而不想改变 variant 时。

## 三个典型使用模式

`[讲解]` 从正篇提炼。

### 模式 1：已知类型，直接取

```cpp
const int iterations = params.get_input<SocketValueVariant>(idx).ensure_type<int>();
```

`[讲解]` 最常见。前提：接口约定明确。

**风险**：类型不兼容会断言。但因为是内部约定，可以接受。

### 模式 2：查询形态，分支处理

```cpp
if (value.is_single()) {
  /* 常量快速路径 */
  const float f = value.ensure_type<float>();
  /* ... */
}
else if (value.is_field()) {
  /* field 求值路径 */
  const GField &field = value.ensure_type<GField>();
  /* ... */
}
```

`[讲解]` 这是节点实现的标准骨架。**先查形态，再按形态取类型**。

### 模式 3：构造常量并复用

```cpp
static const SocketValueVariant static_unused_index{-1};
```

`[讲解]` 静态常量 variant。构造一次，之后只读。

**注意**：`static` 的初始化线程安全由 C++11 magic statics 保证。但 variant 本身**不是**线程安全的——只读可以，写不行。

## 用小数据走一遍

`[讲解]` 四个场景，看走了哪一级：

### 场景 A：装 int，取 int

```text
variant = { type: int, value: 42 }
ensure_type<int>()
  → 第 1 级：value_.type() == CPPType::get<int>()  ✅
  → 返回 &42
成本：1 次指针比较
```

### 场景 B：装 GField，取 Field<int>

```text
variant = { type: GField, value: <field> }
ensure_type<Field<int>>()
  → 第 1 级：GField != Field<int>  ❌
  → 第 2 级：is_interpretable_as(Field<int>)  ✅
  → 返回 reinterpret_cast<Field<int>&>
成本：1 次函数指针调用
```

### 场景 C：装 float 1.5，取 int

```text
variant = { type: float, value: 1.5 }
ensure_type<int>()
  → 第 1 级：float != int  ❌
  → 第 2 级：is_interpretable_as(int)  ❌（布局不同）
  → 第 3 级：convert_to(int)  ✅ → value_ 变成 1
  → 返回 &1
成本：1 次转换 + 就地替换

注意：此时 variant 里已经是 int 1，不再是 float 1.5
```

### 场景 D：装 GeometrySet，取 int

```text
variant = { type: GeometrySet, value: <geometry> }
ensure_type<int>()
  → 第 1 级 ❌
  → 第 2 级 ❌
  → 第 3 级 ❌（无法转换）
  → 返回 nullptr → BLI_assert 崩溃
```

`[讲解]` 第四个场景说明：**`ensure_type` 不是万能的**。它在无法转换时断言，这是设计选择（内部错误应该尽早暴露）。

## 反例与边界

### 反例 1：以为 `ensure_type` 是只读的

它会改数据（第 3 级转换是破坏性的）。之后不能按原类型用。

### 反例 2：以为 `ensure_type` 一定成功

类型不兼容时断言崩溃。要用 `try_get` 先检查。

### 反例 3：在 const 上下文用 `ensure_type`

`ensure_type` 需要非 const（可能改数据）。const variant 只能 `try_get`。

### 反例 4：`extract` 之后继续用 variant

值被移走了，之后是空 variant。

### 反例 5：以为 `is_field` 等价于"类型是 Field"

它查的是 `storage_kind == Field`。一个 `GField` 的 variant `is_field()` 返回 true，一个 `Field<int>` 也是（因为存储映射成 `GField`）。

### 反例 6：在 `emplace` 之后假设原类型

`emplace<T>` 会**替换**原值。之前存的东西被析构。

## 对理解 Repeat 的帮助

`[讲解]` 正篇的三处调用，现在能逐字解释：

### 调用 1：读迭代数

```cpp
params.get_input<SocketValueVariant>(zone_info_.indices.inputs.main[0])
    .ensure_type<int>()
```

`[讲解]` 走第 1 级（variant 里就是 int）。成本：一次指针比较。**这是为什么它写在 `initialize_execution_graph` 开头而不担心性能**。

### 调用 2：预填充轮次值

```cpp
eval_storage.index_values[i].emplace<int>(i);
```

`[讲解]` 就地构造，因 int 内联，零堆分配。N 次循环 = N 次 4 字节写。

### 调用 3：静态哨兵

```cpp
static const SocketValueVariant static_unused_index{-1};
```

`[讲解]` 一次构造，N 轮复用同一对象（`set_default_value(&static_unused_index)` 传指针）。

## 接口选择决策表

`[讲解]` 一张表收尾：

| 我想… | 用 |
| --- | --- |
| 构造一个新值进 variant | `emplace<T>` |
| 我知道是 T，取引用 | `ensure_type<T>()` |
| 我不确定，想先探一下 | `try_get<T>()` |
| 我要用完就扔，避免拷贝 | `extract<T>()` |
| 我想知道是常量还是 field | `is_single()` / `is_field()` |
| 类型是运行时才知道的 | `ensure_type(const CPPType&)` |
