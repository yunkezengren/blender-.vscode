## 1. 节点概述

**Sort List** 节点根据权重值对列表中的元素重新排序。它支持三种控制输入：

| 输入 | 类型 | 说明 |
|------|------|------|
| **List** | 动态类型（List） | 待排序的列表 |
| **Selection** | Bool（Dynamic） | 哪些元素参与排序 |
| **Group ID** | Int（Dynamic） | 相同 Group ID 的元素在同一组内排序 |
| **Sort Weight** | Float（Dynamic） | 决定排序顺序的权重值 |

**输出**：排序后的列表（与输入类型相同）

```mermaid
flowchart LR
    subgraph "Sort List 节点"
        direction TB
        IN["List 输入"]
        SEL["Selection<br/>是否参与排序"]
        GID["Group ID<br/>分组排序"]
        WT["Sort Weight<br/>排序权重"]
        OUT["List 输出<br/>（排序后）"]
    end

    IN --> OUT
    SEL -.->|"控制哪些元素排序"| OUT
    GID -.->|"组内排序"| OUT
    WT -.->|"决定顺序"| OUT

    style IN fill:#3498db,color:#fff
    style OUT fill:#2ecc71,color:#fff
    style SEL fill:#f39c12,color:#fff
    style GID fill:#9b59b6,color:#fff
    style WT fill:#e74c3c,color:#fff
```

**核心特性**：
- Selection、Group ID、Sort Weight 都可以是**单值、字段或列表**
- 与 Sort Elements 节点共享排序算法（`sort_indices_by_weights`）
- SingleData 列表直接返回（所有元素相同，排序无意义）
- 使用 `to_static_type` 处理所有支持的元素类型

## 3. 节点声明与 UI

### 3.1 node_declare — Socket 声明

```cpp
static void node_declare(NodeDeclarationBuilder &b)
{
  const bNode *node = b.node_or_null();
  if (!node) {
    return;  // 首次声明时节点还不存在
  }

  b.use_custom_socket_order();    // 使用自定义 Socket 顺序
  b.allow_any_socket_order();     // 允许任意顺序排列
  b.add_default_layout();         // 添加默认布局

  const auto type = eNodeSocketDatatype(node->custom1);  // 从 DNA 读取数据类型

  // 列表输入/输出——类型由 custom1 决定
  b.add_input(type, "List"_ustr).structure_type(StructureType::List).hide_value();
  b.add_output(type, "List"_ustr)
      .propagate_all({0})                          // 传播匿名属性
      .structure_type(StructureType::List)
      .align_with_previous();                      // 与上一个 Socket 对齐

  // 三个控制输入——都是 Dynamic 结构类型（可以是 Single/Field/List）
  b.add_input<decl::Bool>("Selection"_ustr)
      .default_value(true)
      .hide_value()
      .structure_type(StructureType::Dynamic)      // ← 关键：Dynamic
      .description("Whether each element should participate in sorting");
  b.add_input<decl::Int>("Group ID"_ustr)
      .default_value(0)
      .hide_value()
      .structure_type(StructureType::Dynamic)
      .description("Elements with the same Group ID are sorted together");
  b.add_input<decl::Float>("Sort Weight"_ustr)
      .default_value(0.0f)
      .hide_value()
      .structure_type(StructureType::Dynamic)
      .description("A field or list of values that will determine the sorted order");
}
```

> **注释翻译**：
> - `"Whether each element should participate in sorting"` — 每个元素是否参与排序
> - `"Elements with the same Group ID are sorted together"` — 相同 Group ID 的元素在同一组内排序
> - `"A field or list of values that will determine the sorted order"` — 决定排序顺序的字段或值列表

```cpp
  const eNodeSocketDatatype socket_type = eNodeSocketDatatype(params.other_socket().type);
  if (params.in_out() == SOCK_IN) {

  }
}
```

### 4.2 早期退出条件

```cpp
static void node_geo_exec(GeoNodeExecParams params)
{
  GListPtr list = params.extract_input<GListPtr>("List"_ustr);
  if (!list) {
    params.set_default_remaining_outputs();  // 空列表 → 默认输出
    return;
  }

  const int list_size = list->size();
  if (list_size <= 1) {
    params.set_output("List"_ustr, std::move(list));  // 0 或 1 个元素 → 无需排序
    return;
  }
  // ...
}
```

| 条件 | 处理 | 原因 |
|------|------|------|
| `list == null` | 默认输出 | 没有输入列表 |
| `list_size <= 1` | 直接返回原列表 | 0 或 1 个元素无需排序 |
| `sort_indices_by_weights` 返回 `nullopt` | 直接返回原列表 | 排序结果与原序相同 |
| `SingleData` | 直接返回原列表 | 所有元素相同，排序无意义 |

## 5. get_varray_or_evaluate 模板函数详解

### 5.1 函数签名

```cpp
template<typename T>
static void get_varray_or_evaluate(const int list_size,
                                   bke::SocketValueVariant &value,
                                   ResourceScope &scope,
                                   fn::FieldEvaluator &field_evaluator,
                                   const T &default_value,
                                   VArray<T> &r_varray)
```

> **功能**：将 `SocketValueVariant` 转换为 `VArray<T>`，统一处理三种输入模式（字段/列表/单值）。

### 5.2 三种模式详解

```cpp
if (value.is_context_dependent_field()) {
  // 模式1：上下文依赖字段 → 加入 FieldEvaluator 延迟求值
  field_evaluator.add(value.extract<fn::Field<T>>(), &r_varray);
}
else if (value.is_list()) {
  // 模式2：列表 → 转为 VArray
  auto list = value.extract<GListPtr>();
  if (list && list->size() == list_size) {
    // 列表大小匹配 → 转为 VArray
    r_varray = scope.add_value(std::move(list))->varray().typed<T>();
  }
  else {
    // 列表大小不匹配 → 用默认值填充
    r_varray = VArray<T>::from_single(default_value, list_size);
  }
}
else {
  // 模式3：单值 → 广播为 VArray
  r_varray = VArray<T>::from_single(value.extract<T>(), list_size);
}
```


### 5.3 关键语法解释

**`r_varray = scope.add_value(std::move(list))->varray().typed<T>();`**

这一行链式调用，逐步拆解：

```cpp
// 第1步：scope.add_value(std::move(list)) 把 list 存入 scope，返回引用
// add_value 返回 T&（引用，不是指针！），指向 scope 内部存储的 GListPtr
GListPtr& list_ref = scope.add_value(std::move(list));

// 第2步：list_ref->varray()
// list_ref 是 GListPtr（shared_ptr<GList>），-> 调用 GListPtr::operator->()
// GListPtr::operator->() 返回 const GList*，然后 ->varray() 调用 GList::varray()
// GList::varray() 返回 GVArray（泛型虚拟数组）
GVArray gvarray = list_ref->varray();

// 第3步：gvarray.typed<T>() 把 GVArray 转为 VArray<T>
// 零开销 static_cast，不拷贝数据
VArray<T> varray = gvarray.typed<T>();

// 第4步：赋值给 r_varray（输出参数）
r_varray = varray;
```

**`->` 的解析**：`list_ref->varray()` 只有一个 `->`，不是两个。C++ 解析过程：
1. `list_ref` 是 `GListPtr`，有 `operator->()` 重载 → 调用它
2. `GListPtr::operator->()` 返回 `const GList*`（原始指针）
3. 用这个指针访问 `varray` 成员 → 结束

**C++ `->` 链式规则**：`a->b` 的解析——如果 `a` 有 `operator->()`，调用它得到返回值 `r`；如果 `r` 是原始指针，用 `r->b`；如果 `r` 不是指针但 `r` 的类型也有 `operator->()`，继续链式调用；如果 `r` 既不是指针也没有 `operator->()` → **编译错误**。

```cpp
// GListPtr::operator->() 的实现：
inline const GList *GListPtr::operator->() const
{
    return data_.get();  // shared_ptr::get()，返回 GList*
}
```

如果 `operator->()` 返回的不是指针且没有 `operator->()` 重载：
```cpp
struct Bad { int operator->() { return 42; } };  // 返回 int
Bad b;
b->foo();  // ❌ 编译错误！int 不是指针，也没有 operator->()
```

**`->` `.typed<T>()`** 三个操作连在一起——每一步都返回值类型，可以直接继续调用。

**为什么需要 scope？** `VArray<T>` 可能引用 `GList` 内部的数据。如果 `list` 是局部变量，函数返回后 `GVArray` 就悬空了。`scope` 延长了 `list` 的生命周期到整个求值过程结束。

```cpp
// ❌ 不存入 scope（悬空引用！）
auto list = value.extract<GListPtr>();        // list 是局部变量
r_varray = list->varray().typed<T>();         // VArray 引用 list 的数据
// list 离开作用域 → 析构 → VArray 悬空！
// 后续 field_evaluator.evaluate() 访问 VArray → UB！

// ✅ 存入 scope
r_varray = scope.add_value(std::move(list))->varray().typed<T>();
// list 存入 scope，VArray 引用 scope 中的 list → 求值时仍有效 ✅
```

**为什么其他列表节点没用这个？** 因为它们不需要保留 VArray 引用到后续求值：

| 节点        | Selection 处理                                        | 需要 scope？ | 原因                   |
| ----------- | ----------------------------------------------------- | ------------ | ---------------------- |
| FilterList  | `IndexMask::from_bools` → 生成 mask 后不再引用 VArray | ❌            | IndexMask 自己管理内存 |
| GetListItem | 直接从 GList 取数据                                   | ❌            | 不保留引用             |
| SortList    | VArray 传给 `field_evaluator`，求值时必须仍有效       | ✅            | VArray 引用 list 数据  |

FilterList 的列表模式：
```cpp
// 生成 IndexMask 后，VArray 就不需要了
IndexMask::from_bools(IndexRange(list->size()), values, memory);
// IndexMask 自己管理内存（通过 IndexMaskMemory），不引用 VArray
```

SortList 的 `get_varray_or_evaluate`：
```cpp
// VArray 要存起来，后续 field_evaluator.evaluate() 时还要用
r_varray = scope.add_value(std::move(list))->varray().typed<T>();
// r_varray 引用 list 数据 → list 必须存活 → 存入 scope
```

**`->varray().typed<T>()`**：

1. `list->varray()` — `GList` 的 `varray()` 方法返回 `GVArray`（泛型虚拟数组）
2. `.typed<T>()` — 将 `GVArray` 转为 `VArray<T>`（类型化虚拟数组），零开销 `static_cast`

## 7. SampleIndexFunction 详解

### 7.1 类定义

```cpp
// list_function_eval.hh
class SampleIndexFunction : public mf::MultiFunction {
  GListPtr list_;           // 持有列表的共享指针
  mf::Signature signature_; // 多函数签名

 public:
  SampleIndexFunction(GListPtr list);

  void call(const IndexMask &mask, mf::Params params, mf::Context /*context*/) const override;
  void hash_unique(UniqueHashBytes &hash) const override;
};
```

> **功能**：将列表包装为多函数——输入索引，输出列表中对应位置的值。这是把"列表"适配为"字段"的桥梁。

### 7.2 构造函数

```cpp
SampleIndexFunction::SampleIndexFunction(GListPtr list) : list_(std::move(list))
{
  mf::SignatureBuilder builder{"Sample Index", signature_};
  builder.single_input<int>("Index");                    // 输入：索引
  builder.single_output("Value", list_->cpp_type());     // 输出：列表元素类型
  this->set_signature(&signature_);
}
```

> **`builder.single_input<int>("Index")`** — 声明一个 `int` 类型的单值输入参数，名为 "Index"。
>
> **`builder.single_output("Value", list_->cpp_type())`** — 声明一个输出参数，类型由列表的元素类型决定。注意输出参数没有模板参数——类型通过 `CPPType` 在运行时指定。

### 7.3 call 方法详解

```cpp
void SampleIndexFunction::call(const IndexMask &mask,
                               mf::Params params,
                               mf::Context /*context*/) const
{
  const VArraySpan<int> indices = params.readonly_single_input<int>(0, "Index");
  GMutableSpan dst = params.uninitialized_single_output(1, "Value");

  // 步骤1：过滤有效索引（在列表范围内的）
  IndexMaskMemory memory;
  const IndexMask valid_indices = array_utils::indices_in_range(
      mask, indices, IndexRange(list_->size()), memory);

  // 步骤2：对无效索引填充默认值
  if (valid_indices.size() != mask.size()) {
    const IndexMask invalid_indices = valid_indices.complement(mask, memory);
    list_->cpp_type().fill_construct_indices(
        list_->cpp_type().default_value(), dst.data(), invalid_indices);
  }

  // 步骤3：根据列表数据类型读取值
  const GList::DataVariant &data = list_->data();
  if (const auto *array_data = std::get_if<nodes::GList::ArrayData>(&data)) {
    // ArrayData：从连续数组中按索引取值
    const GSpan src(list_->cpp_type(), array_data->data, list_->size());
    valid_indices.foreach_index(
        [&](const int i) { list_->cpp_type().copy_construct(src[indices[i]], dst[i]); });
  }
  else if (const auto *single_data = std::get_if<nodes::GList::SingleData>(&data)) {
    // SingleData：所有位置都是同一个值
    list_->cpp_type().fill_construct_indices(single_data->value, dst.data(), valid_indices);
  }
}
```

### 7.4 关键语法解释

**`VArraySpan<int> indices`**：`VArraySpan` 是 `VArray` 的视图——如果底层是 Span，直接引用；否则物化为临时数组。这里索引输入可能来自字段求值结果，`VArraySpan` 自动处理两种情况。

**`array_utils::indices_in_range`**：检查 `indices` 中哪些值在 `[0, list_size)` 范围内，返回有效的 `IndexMask`。例如 `indices = [0, 2, 5, 10]`，`list_size = 8`，则 `valid = [0, 2, 5]`，`invalid = [10]`。

**`fill_construct_indices(default_value, dst, invalid_indices)`**：在 `dst` 的 `invalid_indices` 位置用默认值构造对象。越界索引返回类型默认值（如 `float` 返回 `0.0f`）。

**`hash_unique`**：

```cpp
void SampleIndexFunction::hash_unique(UniqueHashBytes &hash) const
{
  static constexpr int8_t id = 0;
  hash.add(&id);
  hash.add(list_.get());  // 用列表指针作为哈希的一部分
}
```

> **`hash_unique`** 用于字段去重——如果两个 `SampleIndexFunction` 持有相同的列表指针，它们的哈希相同，可以合并。`list_.get()` 返回底层 `GList*` 指针。

```
③ grouped_sort(Span({0, 5}), weight_values, gathered_indices)
   → 按 weight 升序排 gathered_indices:
     weight[1]=1.0 < weight[3]=1.5 < weight[4]=2.0 < weight[0]=3.0 < weight[2]=4.0
   → gathered_indices = [1, 3, 4, 0, 2]

结果: 位置0放原1号(权重1.0), 位置1放原3号(权重1.5), ...
```

### 8.5 路径B：有分组

```cpp
else {
  // ① 收集选中元素的 group_id
  Array<int> gathered_group_id(mask.size());
  array_utils::gather(group_id, mask, gathered_group_id.as_mutable_span());

  // ② 将 group_id 转为连续索引 [0, total_groups)
  const int total_groups = identifiers_to_indices(gathered_group_id);

  // ③ 按组分配索引，计算每组的偏移量
  Array<int> offsets_to_sort(total_groups + 1, 0);
  find_points_by_group_index(gathered_group_id, offsets_to_sort, gathered_indices);

  // ④ 在每组内按权重排序（如果权重不全相同）
  if (!weight.is_single()) {
    Array<float> weight_values(mask.size());
    array_utils::gather(weight, mask, weight_values.as_mutable_span());
    grouped_sort(offsets_to_sort.as_span(), weight_values, gathered_indices);
  }

  // ⑤ 将局部索引转回全局索引
  parallel_transform<int>(gathered_indices, 2048, [&](const int pos) { return mask[pos]; });
}
```

> **① `array_utils::gather(group_id, mask, ...)`**：从 VArray 中按 mask 索引收集 group_id 值。`gather` 是"按索引收集"——`dst[i] = src[mask[i]]`。
>
> **② `identifiers_to_indices`**：将任意 group_id（如 100, 50, 200）映射为连续索引（0, 1, 2），同时保持值的大小顺序。详见第 10 章。
>
> **③ `find_points_by_group_index`**：根据连续索引构建分组偏移表和组内元素索引。详见第 11 章。
>
> **④ `grouped_sort`**：在每组内按权重排序。详见第 9 章。
>
> **⑤ 将局部索引转回全局索引**：`gathered_indices` 中存的是在 mask 范围内的局部位置（0, 1, 2, ...），需要转回全局索引。例如 `mask = [2, 5, 7]`，`gathered_indices = [1, 0, 2]`，则 `mask[1]=5, mask[0]=2, mask[2]=7`，最终排序结果为 `[5, 2, 7]`。

### 8.6 处理未选中元素

```cpp
// 检查排序结果是否与原序相同
if (array_utils::indices_are_range(gathered_indices, IndexRange(domain_size))) {
  return std::nullopt;
}

// 全选 → 直接返回
if (mask.size() == domain_size) {
  return gathered_indices;
}

// 部分选中 → 未选中元素保持原位
IndexMaskMemory memory;
const IndexMask unselected = mask.complement(IndexRange(domain_size), memory);
Array<int> indices(domain_size);
array_utils::scatter<int>(gathered_indices, mask, indices);       // 排序结果放到选中位置
array_utils::fill_index_range<int>(unselected, indices);           // 未选中位置保持原索引

// 再次检查最终结果
if (array_utils::indices_are_range(indices, indices.index_range())) {
  return std::nullopt;
}

return indices;
```

> **`scatter`**：`gather` 的逆操作。`gather` 是"从源中按索引收集"（`dst[i] = src[indices[i]]`），`scatter` 是"按索引散布到目标"（`dst[indices[i]] = src[i]`）。
>
> **`fill_index_range`**：在 `unselected` 位置填入与索引相同的值（即 `indices[i] = i`），表示"未选中元素保持原位不动"。
>
> **两次 `indices_are_range` 检查**：第一次检查排序后的 gathered_indices 是否就是 `[0, 1, 2, ...]`（原序）；第二次检查合并未选中元素后的最终结果是否也是原序。如果都是原序就返回 `nullopt`，避免不必要的重排。

## 9. grouped_sort 分组排序

### 9.1 完整实现

```cpp
// source/blender/geometry/intern/reorder.cc:443~462
static void grouped_sort(const OffsetIndices<int> offsets,
                         const Span<float> weights,
                         MutableSpan<int> indices)
{
  const auto comparator = [&](const int index_a, const int index_b) {
    const float weight_a = weights[index_a];
    const float weight_b = weights[index_b];
    if (weight_a == weight_b) [[unlikely]] {
      return index_a < index_b;  // 权重相同 → 保持原序（稳定排序）
    }
    return weight_a < weight_b;  // 按权重升序
  };

  threading::parallel_for(offsets.index_range(), 250, [&](const IndexRange range) {
    for (const int group_index : range) {
      MutableSpan<int> group = indices.slice(offsets[group_index]);
      parallel_sort(group.begin(), group.end(), comparator);
    }
  });
}
```

### 9.2 逐行解析

> **`comparator`**：排序比较器。比较两个索引 `index_a` 和 `index_b` 对应的权重。注意比较的是 `weights[index_a]` 和 `weights[index_b]`，不是直接比较索引本身。
>
> **`[[unlikely]]`**：C++20 属性，告诉编译器"权重相等"这个分支很少执行，帮助 CPU 分支预测器优化。等价于旧版 `UNLIKELY()` 宏。
>
> **`return index_a < index_b`**：权重相同时，按原始索引排序，保证**稳定排序**——相同权重的元素保持输入时的相对顺序。
>
> **`threading::parallel_for(offsets.index_range(), 250, ...)`**：并行处理多个组。`250` 是 grain_size——每组至少 250 个组才值得开新线程。因为组内排序本身就是 O(n log n)，如果组很少就单线程处理。
>
> **`indices.slice(offsets[group_index])`**：从 `indices` 中切出当前组对应的切片。`offsets[group_index]` 返回一个 `IndexRange`，表示该组在 `indices` 中的范围。
>
> **`parallel_sort`**：Blender 的并行排序封装。如果编译时启用了 TBB，使用 `tbb::parallel_sort`；否则退化为 `std::sort`。

### 9.3 OffsetIndices 详解

`OffsetIndices<int>` 是 Blender 的偏移索引结构——用一组偏移量表示多个区间：

```
offsets = [0, 3, 5, 8]
         → 组0: [0, 3)  → indices[0], indices[1], indices[2]
         → 组1: [3, 5)  → indices[3], indices[4]
         → 组2: [5, 8)  → indices[5], indices[6], indices[7]
```

## 10. identifiers_to_indices 标识符转索引

### 10.1 完整实现

```cpp
// source/blender/geometry/intern/reorder.cc:472~488
static int identifiers_to_indices(MutableSpan<int> r_identifiers_to_indices)
{
  // 步骤1：去重，建立标识符→索引的映射
  const VectorSet<int> deduplicated_identifiers(r_identifiers_to_indices);

  // 步骤2：将每个标识符替换为其在 VectorSet 中的索引
  parallel_transform(r_identifiers_to_indices, 2048, [&](const int identifier) {
    return deduplicated_identifiers.index_of(identifier);
  });

  // 步骤3：按标识符值排序，确保索引顺序与标识符值顺序一致
  Array<int> indices(deduplicated_identifiers.size());
  array_utils::fill_index_range<int>(indices);
  parallel_sort(indices.begin(), indices.end(), [&](const int index_a, const int index_b) {
    return deduplicated_identifiers[index_a] < deduplicated_identifiers[index_b];
  });

  // 步骤4：构建排列映射，将"VectorSet 顺序"转为"标识符值顺序"
  Array<int> permutation = invert_permutation(indices);
  parallel_transform(
      r_identifiers_to_indices, 4096, [&](const int index) { return permutation[index]; });

  return deduplicated_identifiers.size();
}
```

### 10.2 为什么需要这个函数？

`group_id` 可能是任意整数（如 `100, 200, 50`），但 `find_points_by_group_index` 需要连续的索引（`0, 1, 2`）。`identifiers_to_indices` 将任意标识符映射为连续索引，同时**保持标识符值的大小顺序**——值小的组排在前面。

### 10.3 四步详解

#### 步骤1：VectorSet 去重

```cpp
const VectorSet<int> deduplicated_identifiers(r_identifiers_to_indices);
```

> **`VectorSet<int>`**：Blender 的有序集合——同时提供哈希集合的 O(1) 查找和数组的顺序遍历。用输入范围初始化后，`deduplicated_identifiers` 包含所有不重复的标识符，按**首次出现的顺序**排列。
>
> 例如输入 `[100, 50, 200, 50, 100]` → `deduplicated_identifiers = [100, 50, 200]`（100 先出现，50 第二次出现，200 第三次出现）。

#### 步骤2：替换为 VectorSet 索引

```cpp
parallel_transform(r_identifiers_to_indices, 2048, [&](const int identifier) {
  return deduplicated_identifiers.index_of(identifier);
});
```

> **`index_of(identifier)`**：返回标识符在 VectorSet 中的位置索引。O(1) 哈希查找。
>
> 例如 `100 → 0`（VectorSet 第0个），`50 → 1`（第1个），`200 → 2`（第2个）。
> 输入 `[100, 50, 200, 50, 100]` → 输出 `[0, 1, 2, 1, 0]`。
>
> **问题**：此时索引顺序是"首次出现顺序"，不是"值大小顺序"。50 应该是组0（最小），100 应该是组1，200 应该是组2。

#### 步骤3：按标识符值排序

```cpp
Array<int> indices(deduplicated_identifiers.size());
array_utils::fill_index_range<int>(indices);  // indices = [0, 1, 2, ...]
parallel_sort(indices.begin(), indices.end(), [&](const int index_a, const int index_b) {
  return deduplicated_identifiers[index_a] < deduplicated_identifiers[index_b];
});
```

> **`fill_index_range`**：用 `std::iota` 填充 `[0, 1, 2, ...]`。
>
> **排序逻辑**：比较的不是 `index_a` 和 `index_b` 本身，而是 `deduplicated_identifiers[index_a]` 和 `deduplicated_identifiers[index_b]`——即比较标识符的**值**。
>
> 例如 `deduplicated_identifiers = [100, 50, 200]`：
> - `indices` 初始 = `[0, 1, 2]`
> - 比较 `deduplicated_identifiers[0]=100` vs `deduplicated_identifiers[1]=50` → 50 更小 → 1 排前面
> - 排序后 `indices = [1, 0, 2]`（表示"值从小到大：第1个值50, 第0个值100, 第2个值200"）

#### 步骤4：构建排列映射

```cpp
Array<int> permutation = invert_permutation(indices);
parallel_transform(r_identifiers_to_indices, 4096, [&](const int index) { return permutation[index]; });
```

> **`invert_permutation(indices)`**：求排列的逆。`indices = [1, 0, 2]` 表示"位置0放元素1, 位置1放元素0, 位置2放元素2"，逆排列 `permutation = [1, 0, 2]` 表示"元素0去位置1, 元素1去位置0, 元素2去位置2"。
>
> **注意**：这个例子中 `permutation == indices`，纯属巧合——`[1, 0, 2]` 恰好是对合（involution），自己就是自己的逆。更典型的例子（来自实际代码中 `{3, 5, 8}` 的场景）：
>
> ```
> indices    = [2, 0, 1]       ← 位置0放元素2, 位置1放元素0, 位置2放元素1
> permutation = [1, 2, 0]       ← 元素0→位置1, 元素1→位置2, 元素2→位置0
> ```
>
> 验证：`permutation[indices[0]] = permutation[2] = 0`，`permutation[indices[1]] = permutation[0] = 1`，`permutation[indices[2]] = permutation[1] = 2`。由此可见排列和逆排列完全不同。
>
> **为什么需要逆排列？** 步骤2 中每个元素已经有一个 VectorSet 索引（如 100→0, 50→1, 200→2），但我们需要的是"按值排序后的索引"（50→0, 100→1, 200→2）。`permutation[旧索引] = 新索引` 正好完成这个映射。
>
> 例如 `permutation = [1, 0, 2]`：
> - 旧索引0（值100）→ 新索引1
> - 旧索引1（值50）→ 新索引0
> - 旧索引2（值200）→ 新索引2
>
> 输入 `[0, 1, 2, 1, 0]` → 输出 `[1, 0, 2, 0, 1]`（50→0, 100→1, 200→2）。

#### 10.3.5 整体思路：为什么这么绕？

概念上这个函数只做了一件简单的事，用伪代码表达只需三行：

```python
unique = sorted(set(ids))                    # 去重 + 按值排序
rank   = {v: i for i, v in enumerate(unique)} # 值 → 排序序号
result = [rank[x] for x in ids]              # 替换
```

但 C++ 中 `rank` 是一个 `Map<int, int>`，对百万级数据构建哈希表有开销。所以代码用**排序下标 + 求逆排列**替代了哈希表，两次都是 O(1) 的数组查表。

**一张图总结**（以 `{5, 8, 3}` 为例）：

```
deduplicated = [ 5,  8,  3 ]    ← 位置→值（VectorSet 插入顺序）
                  ↓   ↓   ↓
临时索引:        0   1   2      ← 值→位置（index_of 查询）

排序下标:     [2, 0, 1]          ← 按值排序后的位置序列
                                   （dedup[2]=3 < dedup[0]=5 < dedup[1]=8）
求逆:         [1, 2, 0]          ← 每个位置在排序后的序号
                 ↓   ↓   ↓
最终映射:    5→1, 8→2, 3→0     ← 值→排序序号（按 group ID 数值升序）
```

核心技巧：**不排序值本身，而是排序"值的下标"，然后求逆得到"每个位置排第几"。**

### 10.4 完整数值例子

```mermaid
flowchart TD
    INPUT["输入: group_id = [100, 50, 200, 50, 100]"]

    STEP1["步骤1: VectorSet 去重<br/>deduplicated = [100, 50, 200]<br/>（插入顺序：100先出现, 50第二, 200第三）"]

    STEP2["步骤2: 替换为 VectorSet 索引<br/>[0, 1, 2, 1, 0]<br/>（100→0, 50→1, 200→2）<br/>⚠️ 索引顺序是插入顺序，不是值顺序"]
```

### 10.6 invert_permutation 实现

```cpp
// source/blender/geometry/intern/reorder.cc:97~106
static Array<int> invert_permutation(const Span<int> permutation)
{
  Array<int> data(permutation.size());
  threading::parallel_for(permutation.index_range(), 2048, [&](const IndexRange range) {
    for (const int64_t i : range) {
      data[permutation[i]] = i;
    }
  });
  return data;
}
```

> **核心逻辑**：如果 `permutation[i] = j`，则 `data[j] = i`。即把"位置→元素"的映射反转为"元素→位置"的映射。
>
> **类比**：
> - `permutation` = 座位表："座位 i 坐的是几号人" → `permutation[i] = j` 表示座位 i 坐 j 号
> - `data` = 查找表："j 号人坐在哪个座位" → `data[j] = i` 表示 j 号坐在座位 i
>
> **数值例子**：
> - `permutation = [2, 0, 1]`（座位0坐2号, 座位1坐0号, 座位2坐1号）
> - `data[2] = 0, data[0] = 1, data[1] = 2` → `data = [1, 2, 0]`（0号坐座位1, 1号坐座位2, 2号坐座位0）

#### count_indices 实现

```cpp
// source/blender/blenlib/intern/array_utils.cc:95~110
void count_indices(const Span<int> indices, MutableSpan<int> counts)
{
  if (indices.size() < 8192 || BLI_system_thread_count() < 4) {
    // 数据量小或线程少 → 串行计数
    for (const int i : indices) {
      counts[i]++;
    }
  }
  else {
    // 数据量大 → 并行计数（用原子操作保证线程安全）
    threading::parallel_for(indices.index_range(), 4096, [&](const IndexRange range) {
      for (const int i : indices.slice(range)) {
        atomic_add_and_fetch_int32(&counts[i], 1);  // 原子 +1
      }
    });
  }
}
```

> **`atomic_add_and_fetch_int32`**：原子操作——先加1再返回新值。多线程同时写 `counts[i]` 不会产生数据竞争。

#### accumulate_counts_to_offsets 实现

```cpp
// source/blender/blenlib/intern/offset_indices.cc:19~35
OffsetIndices<int> accumulate_counts_to_offsets(MutableSpan<int> counts_to_offsets,
                                                const int start_offset = 0)
{
  int offset = start_offset;
  for (const int i : counts_to_offsets.index_range().drop_back(1)) {
    const int count = counts_to_offsets[i];
    BLI_assert(count >= 0);
    counts_to_offsets[i] = offset;   // 用偏移量替换计数
    offset += count;                  // 累加
  }
  counts_to_offsets.last() = offset;  // 最后一个元素是总大小
  return OffsetIndices<int>(counts_to_offsets);
}
```

> **核心**：将"每组有多少元素"转为"每组的起始偏移量"。这就是**前缀和**（prefix sum / exclusive scan）。
>
> 例如 `counts = [3, 2, 4]`（组0有3个, 组1有2个, 组2有4个）→ `offsets = [0, 3, 5, 9]`

### 11.3 reverse_indices_in_groups 实现

```cpp
// source/blender/blenlib/intern/offset_indices.cc:178~206
void reverse_indices_in_groups(const Span<int> group_indices,
                               const OffsetIndices<int> offsets,
                               MutableSpan<int> results,
                               const bool sort)
{
  if (group_indices.is_empty()) {
    return;
  }
  BLI_assert(results.size() == group_indices.size());
  BLI_assert(results.size() == offsets.total_size());
  BLI_assert(*std::max_element(group_indices.begin(), group_indices.end()) < offsets.size());
  BLI_assert(*std::min_element(group_indices.begin(), group_indices.end()) >= 0);

  Array<int> counts(offsets.size(), 0);  // 每组已放入多少个元素
  threading::parallel_for(group_indices.index_range(), 1024, [&](const IndexRange range) {
    for (const int64_t i : range) {
      const int group_index = group_indices[i];       // 元素 i 属于哪一组
      const int index_in_group = atomic_fetch_and_add_int32(&counts[group_index], 1);  // 原子递增，获取组内位置
      results[offsets[group_index][index_in_group]] = int(i);  // 写入结果
    }
  });
  if (sort) {
    sort_groups(offsets, results);  // 可选：对每组内结果排序
  }
}
```

> **核心逻辑**：遍历每个元素，根据其 `group_index` 找到它属于哪一组，然后在 `results` 中该组对应的区间内找一个位置放入。
>
> **`offsets[group_index][index_in_group]`**：`offsets[group_index]` 返回一个 `IndexRange`（如 `[3, 7)`），`[index_in_group]` 取其中的第 `index_in_group` 个位置（如 `3, 4, 5, 6`）。
>
> **`atomic_fetch_and_add_int32`**：原子操作——先返回当前值再加1。保证多线程下每个元素在组内获得不同的位置。
>
> **`sort = false`**：`find_points_by_group_index` 传入 `false`，不排序组内结果。因为后面 `grouped_sort` 会重新排序。

## 12. parallel_transform 并行变换

### 12.1 完整实现

```cpp
// source/blender/geometry/intern/reorder.cc:434~441
template<typename T, typename Func>
static void parallel_transform(MutableSpan<T> values, const int64_t grain_size, const Func &func)
{
  threading::parallel_for(values.index_range(), grain_size, [&](const IndexRange range) {
    MutableSpan<T> values_range = values.slice(range);
    std::transform(values_range.begin(), values_range.end(), values_range.begin(), func);
  });
}
```

### 12.2 逐行解析

> **`threading::parallel_for(values.index_range(), grain_size, ...)`**：将 `values` 按 `grain_size` 分块，每块一个线程处理。
>
> **`values.slice(range)`**：切出当前线程负责的子范围。
>
> **`std::transform(begin, end, begin, func)`**：STL 算法，对 `[begin, end)` 中的每个元素调用 `func`，结果写回第三个参数指向的位置。这里输入和输出是同一块内存（原地变换）。
>
> **`grain_size`**：每个线程处理的最小元素数。如果数据量小于 `grain_size`，就不会开新线程。不同调用使用不同的 grain_size：
> - `2048`：用于 `identifiers_to_indices` 的步骤2和步骤5（简单查找，计算快）
> - `4096`：用于 `identifiers_to_indices` 的步骤4（更简单的查找）
> - `2048`：用于路径B的步骤5（`mask[pos]`，简单索引查找）

### 12.3 数值例子

```

func = [&](const int index) { return permutation[index]; }

parallel_transform:
  对每个元素: values[i] = permutation[values[i]]
  values[0] = permutation[0] = 1
  values[1] = permutation[1] = 0
  values[2] = permutation[2] = 2
  values[3] = permutation[1] = 0
  values[4] = permutation[0] = 1

结果: values = [1, 0, 2, 0, 1]
```

### 13.5 indices_are_range — 判断是否连续范围

#### 完整实现

```cpp
// source/blender/blenlib/intern/array_utils.cc:325~342
bool indices_are_range(Span<int> indices, IndexRange range)
{
  if (indices.size() != range.size()) {
    return false;
  }
  return threading::parallel_reduce(
      range.index_range(), 4096, true,
      [&](const IndexRange part, const bool is_range) {
        return is_range &&
               std::equal(indices.slice(part).begin(), indices.slice(part).end(),
                          range.slice(part).begin());
      },
      std::logical_and<>());
}
```

#### 功能

判断 `indices` 是否恰好等于 `[range.start(), range.start()+1, ..., range.start()+size-1]`。

例如 `indices = [3, 4, 5]`, `range = IndexRange(3, 3)` → `true`（恰好是 3,4,5）
`indices = [3, 5, 4]`, `range = IndexRange(3, 3)` → `false`（不是 3,4,5）

#### 逐行解析

```cpp
if (indices.size() != range.size()) {
    return false;
}
```

> **快速失败**：长度不同，内容肯定不同，直接返回。避免启动并行框架的开销。

```cpp
threading::parallel_reduce(
    range.index_range(),   // 要处理的索引范围 [0, 1, 2, ..., size-1]
    4096,                  // grain_size：每块至少 4096 个元素
    true,                  // identity：逻辑与的单位元
    [&](const IndexRange part, const bool is_range) { ... },
    std::logical_and<>()   // reduction：用逻辑与合并分块结果
);
```

> **参数说明**：
> - `range.index_range()` = `[0, size)`——对整个范围分块
> - `4096` = grain_size——数据量 < 4096 时不分块，直接串行
> - `true` = identity——逻辑与的单位元（`true && x = x`）
> - lambda = function——处理每个分块，返回该分块是否匹配
> - `logical_and<>` = reduction——合并分块结果（`a && b`）

```cpp
[&](const IndexRange part, const bool is_range) {
    return is_range &&
           std::equal(indices.slice(part).begin(), indices.slice(part).end(),
                      range.slice(part).begin());
}
```

> **`part`**：当前分块的索引范围，如 `[0, 4096)` 或 `[4096, 8192)`
>
> **`is_range`**：之前分块合并后的累积结果。如果之前已经发现 `false`，这里直接短路返回 `false`，不再调用 `std::equal`——**短路优化**。
>
> **`indices.slice(part)`**：切出当前分块对应的 indices 子数组
>
> **`range.slice(part)`**：切出当前分块对应的 range 子范围
>
> **`std::equal(...)`**：逐个比较两个数组是否完全相同

#### 短路优化详解

`is_range &&` 的短路行为是关键优化：

```cpp
return is_range && std::equal(...);
//     ↑ 如果 is_range=false，std::equal 根本不会执行
```

```
100万元素的数组，第10个元素就不匹配：

不短路：100万个元素全部比较 → 浪费！
短路：  块1前10个就发现 false → 后续所有块直接跳过 → 快100倍
```

> **逻辑与的短路求值**：`false && x` 中，`x` 不会被求值。C++ 语言保证这一点。所以 `is_range && std::equal(...)` 在 `is_range` 为 `false` 时，`std::equal` 不会被调用。

#### 用途

`sort_indices_by_weights` 中两次调用 `indices_are_range`：

```cpp
// 第一次：检查排序后的 gathered_indices 是否与原序相同
if (array_utils::indices_are_range(gathered_indices, IndexRange(domain_size))) {
    return std::nullopt;  // 无需排序
}

// 第二次：检查合并未选中元素后的最终结果是否与原序相同
if (array_utils::indices_are_range(indices, indices.index_range())) {
    return std::nullopt;  // 无需排序
}
```

> 如果排序结果恰好就是 `[0, 1, 2, ...]`（原序），返回 `nullopt` 告诉调用方"不需要重排"——避免不必要的 gather 操作。

### 15.1 代码

```cpp
if (const auto *array_data = std::get_if<GList::ArrayData>(&list_data)) {

  const GSpan src_span(type, array_data->data, list_size);

  // 3. 按排序索引 gather
  type.to_static_type<float, float2, float3, float4, int, int2, bool, int8_t,
```

## 16. to_static_type 类型分发宏

### 16.1 语法

```cpp
type.to_static_type<float, float2, float3, ..., bSound *>([&]<typename T>() {
```

## 18. 关键语法与注释翻译

### 18.1 ResourceScope

```cpp
ResourceScope scope;
```

> **`ResourceScope`**：资源作用域——一个 RAII 容器，存储任意类型的对象。当 `scope` 离开作用域时，所有存储的对象自动销毁。用于延长临时对象（如从列表转换的 `VArray`）的生命周期。

> **RAII**（Resource Acquisition Is Initialization，资源获取即初始化）：C++ 核心资源管理范式——把资源（内存、文件、锁）绑定到对象的生命周期。构造时获取资源，析构时释放资源。离开作用域时编译器**自动**调用析构函数，保证资源不泄漏。
>
> ```cpp
> {
>     ResourceScope scope;        // 构造：空容器
>     scope.add_value(std::move(list));  // 存入对象
>     // ... 使用 list ...
> }  // 离开作用域 → scope 析构 → 自动销毁所有存储的对象
> ```
>
> 对比 Java/Python 的 GC：RAII 是**确定性**的——资源释放时机明确（离开作用域时），不依赖 GC 的不确定时机。

### 18.2 fn:: 命名空间

```cpp
fn::FieldEvaluator field_evaluator(field_context, list_size);
mf::MultiFunction
```

> **`fn::`** = functions 命名空间（`blender::fn`），包含字段系统（Field、FieldEvaluator、FieldOperation、MultiFunction 等）。
>
> **为什么有的节点带 `fn::` 有的不带？**
> - **带 `fn::`**：使用了 `fn` 命名空间中的类型，且当前文件没有 `using namespace blender::fn;`
> - **不带**：文件顶部有 `using namespace blender::fn;` 或在 `namespace blender::fn::...` 内部
>
> ```cpp
> // node_geo_sort_list.cc 顶部
> namespace blender::nodes {
> // 没有 using namespace fn; → 必须写 fn::
> fn::FieldEvaluator field_evaluator(...);
> }
> ```
>
> **`mf::`** = multi function 命名空间（`blender::fn::mf`），是 `fn` 的子命名空间。

### 18.3 MultiFunction 是什么

```cpp
class SampleIndexFunction : public mf::MultiFunction {
```

> **`MultiFunction`**（多函数）：Blender 的"批量计算"抽象——一次对一组数据执行相同操作。
>
> ```cpp
> // MultiFunction 的核心接口
> void call(const IndexMask &mask,    // 对哪些索引执行
>           mf::Params params,         // 输入/输出参数
>           mf::Context context) const; // 上下文
> ```
>
> **为什么叫"多函数"？** 普通函数一次处理一个值：`f(0)`, `f(1)`, `f(2)`...。MultiFunction 一次处理**一批**值：`call([0,1,2,...], inputs, outputs)`——可以批量优化（SIMD、并行）。
>
> **`SampleIndexFunction`**：把列表包装为 MultiFunction——输入索引，输出列表中对应位置的值。
>
> ```mermaid
> flowchart LR
>     subgraph 输入
>         I0["索引 0"]
>         I1["索引 1"]
>         I2["索引 2"]
>     end
>     subgraph "SampleIndexFunction.call"
>         L["GListPtr<br/>[A, B, C, D]"]
>     end
>     subgraph 输出
>         O0["list[0] = A"]
>         O1["list[1] = B"]
>         O2["list[2] = C"]
>     end
>     I0 --> L
>     I1 --> L
>     I2 --> L
>     L --> O0
>     L --> O1
>     L --> O2
> ```

### 18.4 为什么抽象这么复杂

```cpp
auto fn = fn::FieldOperation::from(
    std::make_shared<SampleIndexFunction>(selection_variant.extract<GListPtr>()),
    {fn::IndexFieldInput::get_field()});
field_evaluator.set_selection(fn::Field<bool>(std::move(fn)));
```

> **为什么这么复杂？** 因为要把"列表"塞进"字段系统"——两者接口不兼容。
>
> | 系统 | 接口 | 数据来源 |
> |------|------|----------|
> | 字段系统 | `Field<bool>` | 每个位置计算一个 bool |
> | 列表 | `GListPtr` | 按索引访问元素 |
>
> **转换链**：
>
> ```mermaid
> flowchart TD
>     L["GListPtr<br/>列表数据"] -->|"SampleIndexFunction<br/>包装为 MultiFunction"| MF["MultiFunction<br/>输入索引→输出元素"]
>     IDX["IndexFieldInput<br/>每个位置返回自己的索引"] --> FO
>     MF -->|"FieldOperation::from<br/>包装为 FieldOperation"| FO["FieldOperation<br/>字段操作节点"]
>     FO -->|"Field<bool>(...)<br/>包装为 Field"| F["Field<bool><br/>布尔字段"]
>     F -->|"set_selection<br/>传给 FieldEvaluator"| FE["FieldEvaluator<br/>字段求值器"]
> ```
>
> **类比**：就像把一个数组适配成函数——`f(i) = array[i]`。需要多层包装是因为 Blender 的字段系统设计为**延迟求值**——先构建计算图，最后一次性求值。

### 18.5 为什么用 std::move

```cpp
field_evaluator.set_selection(fn::Field<bool>(std::move(fn)));
```

> **`std::move(fn)`**：`fn` 是 `FieldOperation` 的 `shared_ptr`。`std::move` 把它转为右值，触发**移动构造**而非拷贝构造。
>
> ```cpp
> // 不用 move：拷贝 shared_ptr → 引用计数 +1（原子操作）
> field_evaluator.set_selection(fn::Field<bool>(fn));
>
> // 用 move：移动 shared_ptr → 引用计数不变（零开销）
> field_evaluator.set_selection(fn::Field<bool>(std::move(fn)));
> // fn 之后不再使用，移动是安全的
> ```
>
> `fn` 在这行之后不再使用——移动语义让所有权转移，避免不必要的引用计数操作。

### 18.6 FieldEvaluator 方法详解

```cpp
field_evaluator.add(*group_id_field, &group_id);     // 添加输入字段
field_evaluator.set_selection(selection_field);       // 设置选择
field_evaluator.evaluate();                            // 求值
const IndexMask selection = field_evaluator.get_evaluated_selection_as_mask();
field_evaluator.get_evaluated_as_mask(0);              // 获取第0个输入的mask
```

> **`field_evaluator.add(field, &output)`**：
> - 添加一个输入字段到求值器
> - `field`：要求值的字段（如 Group ID 字段）
> - `&output`：求值结果的输出指针（如 `&group_id`）
> - 返回索引（0, 1, 2...），用于后续 `get_evaluated(index)` 获取结果
>
> **`field_evaluator.set_selection(field)`**：
> - 设置选择字段——只有 `field[i] == true` 的位置才会被求值
> - 类似 SQL 的 `WHERE` 子句
> - 必须在 `evaluate()` 之前调用
>
> **`field_evaluator.evaluate()`**：
> - 执行所有添加的字段的求值
> - 一次性求值所有字段——避免多次遍历
> - 求值后才能获取结果
>
> **`get_evaluated_selection_as_mask()`**：
> - 返回 `set_selection` 设置的**选择字段**的 mask
> - 选择字段控制"哪些位置参与求值"——未选中的位置**被跳过**（性能优化）
> - 求值时已经算好 mask，直接返回 `selection_mask_`
>
> **`get_evaluated_as_mask(index)`**：
> - 返回 `add` 添加的第 `index` 个**数据字段**求值后的 mask
> - **所有位置都参与求值**，事后把 bool 结果转为 mask
> - 代码：`VArray<bool> → index_mask_from_selection()`
>
> **区别**：
>
> | | `add` + `get_evaluated_as_mask` | `set_selection` + `get_evaluated_selection_as_mask` |
> |---|---|---|
> | 字段角色 | 数据字段 | 选择字段 |
> | 求值范围 | 所有位置 | 只对选中位置 |
> | mask 获取 | 事后转换 | 求值时算好 |
>
> **FilterList 用 `add`**：只有一个 filter 字段，直接 add + 转mask 更简单
> **SortList 用 `set_selection`**：有多个字段，set_selection 跳过未选中位置的求值——性能优化

```cpp
ListFieldContext field_context;
fn::FieldEvaluator field_evaluator(field_context, list_size);
```

> **`ListFieldContext`**：列表字段上下文——告诉 `FieldEvaluator` "在列表环境下求值"。与几何体字段上下文不同，列表没有域（domain）的概念，只有大小。

### 18.7 std::optional 和 std::nullopt

```cpp
const std::optional<Array<int>> sorted = geometry::sort_indices_by_weights(...);
if (!sorted) { ... }  // 等价于 sorted == std::nullopt
```

> **`std::optional<T>`**：可能包含值也可能不包含的容器。`std::nullopt` 表示"不包含值"。`sort_indices_by_weights` 返回 `nullopt` 表示"无需排序"——排序结果与原序相同，不需要重排。

### 18.8 std::get_if

```cpp
if (std::get_if<GList::SingleData>(&list_data)) { ... }
if (const auto *array_data = std::get_if<GList::ArrayData>(&list_data)) { ... }
```

> **`std::get_if<T>(&variant)`**：检查 variant 是否持有类型 `T`。如果持有，返回指向数据的指针；否则返回 `nullptr`。与 `std::get<T>` 不同——`std::get` 在类型不匹配时抛出异常，`std::get_if` 返回 `nullptr`。

### 18.9 UNLIKELY 宏

```cpp
if (UNLIKELY(weight_a == weight_b)) {
```

> **`UNLIKELY(condition)`**：编译器提示宏，告诉分支预测器这个条件**很少为真**。CPU 流水线会优化"大概率路径"的执行。等价于 `__builtin_expect(!!(condition), 0)`。

### 18.10 NOD_REGISTER_NODE

```cpp
NOD_REGISTER_NODE(node_register)
```

> **`NOD_REGISTER_NODE`**：Blender 的节点注册宏。在全局初始化阶段调用 `node_register` 函数，将节点类型注册到 Blender 的节点类型系统中。确保节点在 Blender 启动时可用。

## 19. FilterList vs SortList：Selection 处理方式对比

### 19.1 为什么处理方法不同？

FilterList 和 SortList 都接收 `SocketValueVariant("Selection")`，但处理方式完全不同：

|                            | FilterList                                 | SortList                                     |
| -------------------------- | ------------------------------------------ | -------------------------------------------- |
| **Selection 的作用**       | 决定哪些元素**保留/过滤**                  | 决定哪些元素**参与排序**                     |
| **单值模式**               | 直接 `get<bool>()` → 全保留或全过滤        | 包装为 `Field<bool>` 传给 `set_selection`    |
| **字段模式**               | 单独 `FieldEvaluator` 求值 → `IndexMask`   | 和其他输入共用一个 `FieldEvaluator`          |
| **列表模式**               | 直接 `IndexMask::from_bools` → `IndexMask` | 包装为 `SampleIndexFunction` → `Field<bool>` |
| **是否需要 ResourceScope** | ❌ 不需要                                   | ✅ 需要                                       |

### 19.2 FilterList 的处理（直接使用）

```cpp
// node_geo_filter_list.cc:141~167
auto filter_value = params.extract_input<bke::SocketValueVariant>("Selection"_ustr);

if (filter_value.is_single()) {
    // 单值 → 直接判断 true/false
    if (filter_value.get<bool>()) output_lists(params, list, IndexMask(list->size()));
    else                          output_lists(params, list, {});
}
else if (filter_value.is_context_dependent_field()) {
    // 字段 → 单独创建 FieldEvaluator 求值
    fn::FieldEvaluator field_evaluator(field_context, list->size());
    field_evaluator.add(filter_value.extract<Field<bool>>());
    field_evaluator.evaluate();
    output_lists(params, list, field_evaluator.get_evaluated_as_mask(0));
}
else if (filter_value.is_list()) {
    // 列表 → 直接转 IndexMask
    const VArray<bool> values = keep_list->varray().typed<bool>();
    IndexMask::from_bools(IndexRange(list->size()), values, memory);
}
```

**特点**：每种模式独立处理，直接得到 `IndexMask`，不需要 `FieldEvaluator` 统一求值。

### 19.3 SortList 的处理（统一为 Field）

```cpp
// node_geo_sort_list.cc:144~155
if (selection_variant.is_context_dependent_field()) {
    field_evaluator.set_selection(selection_variant.extract<fn::Field<bool>>());
}
else if (selection_variant.is_list()) {
    // 列表 → 包装为 SampleIndexFunction → Field<bool>
    auto fn = fn::FieldOperation::from(
        std::make_shared<SampleIndexFunction>(...),
        {fn::IndexFieldInput::get_field()});
    field_evaluator.set_selection(fn::Field<bool>(std::move(fn)));
}
else {
    // 单值 → 包装为常量 Field<bool>
    field_evaluator.set_selection(fn::Field<bool>(selection_variant.extract<bool>()));
}
```

**特点**：所有模式都转为 `Field<bool>`，统一交给 `FieldEvaluator`。

### 19.4 为什么 SortList 必须统一为 Field？

因为 SortList 有**多个输入**需要同时求值：

```cpp
// SortList 的三个输入都交给同一个 FieldEvaluator
field_evaluator.set_selection(selection_field);  // Selection
get_varray_or_evaluate(list_size, group_id_variant, scope, field_evaluator, 0, group_id);   // Group ID
get_varray_or_evaluate(list_size, weights_variant, scope, field_evaluator, 0.0f, weights); // Sort Weight
field_evaluator.evaluate();  // 一次求值所有输入！
```

如果 Selection 单独处理（像 FilterList 那样），就需要**两次求值**——一次算 Selection，一次算 Group ID 和 Weights。统一为 Field 后只需一次。

```mermaid
flowchart TB
    subgraph "FilterList：独立处理"
        F1["Selection 单值"] --> F1R["直接 IndexMask"]
        F2["Selection 字段"] --> F2R["单独 FieldEvaluator"]
        F3["Selection 列表"] --> F3R["直接 from_bools"]
    end

    subgraph "SortList：统一为 Field"
        S1["Selection 单值"] --> S1F["包装为 Field<bool>"]
        S2["Selection 字段"] --> S2F["直接 Field<bool>"]
        S3["Selection 列表"] --> S3F["SampleIndexFunction → Field<bool>"]
        S1F --> SE["同一个 FieldEvaluator<br/>一次求值"]
        S2F --> SE
        S3F --> SE
        SG["Group ID"] --> SE
        SW["Sort Weight"] --> SE
    end
```

### 19.5 为什么需要 ResourceScope？

```cpp
ResourceScope scope;
```

SortList 需要延长临时对象的生命周期：

```cpp
// get_varray_or_evaluate 中：
if (value.is_list()) {
    auto list = value.extract<GListPtr>();
    if (list && list->size() == list_size) {
        r_varray = scope.add_value(std::move(list))->varray().typed<T>();
        //         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
        //         list 存入 scope，延长生命周期到函数结束
    }
}
```

**为什么 FilterList 不需要？** FilterList 的列表模式直接用 `IndexMask::from_bools` 生成 mask，不保留 `VArray` 引用。SortList 的 `get_varray_or_evaluate` 返回 `VArray<T>`，可能引用 `GList` 内部数据——`GList` 必须存活到 `field_evaluator.evaluate()` 之后。

```mermaid
flowchart LR
    subgraph "SortList 生命周期问题"
        L["GListPtr list<br/>从 SocketValueVariant 提取"] --> |"存入 scope"| S["ResourceScope scope"]
        S --> |"存活到函数结束"| V["VArray 引用 list 数据"]
        V --> |"field_evaluator.evaluate()"| E["求值时 list 仍有效 ✅"]
    end

    subgraph "如果没有 scope"
        L2["GListPtr list<br/>局部变量"] --> |"析构"| D["list 销毁 💀"]
        D --> |"VArray 悬空指针"| U["UB！访问已释放内存 ❌"]
    end
```

> **`ResourceScope`**：RAII 容器，存储任意类型对象。离开作用域时自动销毁所有对象。SortList 用它延长 `GListPtr` 的生命周期，确保 `VArray` 在求值期间有效。FilterList 不需要——它不保留 `VArray` 引用。
